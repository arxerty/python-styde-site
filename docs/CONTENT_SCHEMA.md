# Схема файлов контента

Источник правды — `backend/app/schema.py` (Pydantic). Лишние/опечатанные поля — ошибка.
Проверка: `backend\.venv\Scripts\python tools\verify_content.py part-01/block-01`.

## Структура папок

```
content/
  part-01/
    part.yaml                 # название части
    block-01/
      block.yaml              # название блока и список уроков
      lesson-01.md            # теория урока (Markdown)
      lesson-01.yaml          # вопросы и задачи урока
      ...
      practicum.yaml          # практикум блока
      cheatsheet.md           # шпаргалка блока
      data/                   # (необязательно) датасеты для задач: assets
    project/
      project.yaml            # проект части: ТЗ по этапам
      solution.md             # эталонное решение проекта
```

Имена: `part-NN`, `block-NN`, `lesson-NN` — две цифры. Порядок = сортировка по имени. Новая папка появляется на сайте автоматически.

## lesson-NN.md — теория

Обычный Markdown (GFM: таблицы, списки, цитаты).

- ` ```python ` — пример с кнопкой «Запустить» (в частях `browser`/`mixed`).
- ` ```python norun ` — без кнопки (код для локального запуска, псевдокод).
- ` ```python run ` — с кнопкой даже в `local`-части.
- ` ```text ` / ` ```bash ` — вывод программы, команды терминала.
- Обязательные разделы: `## Частые ошибки`, `## Где это в AI-инженерии`.

## lesson-NN.yaml — вопросы и задачи

```yaml
questions:
  - id: q1                        # уникален в файле
    type: single                  # single | multiple | output | find_bug
    prompt: "Текст вопроса"       # Markdown
    code: |                       # код под вопросом; обязателен для output и find_bug
      print(1 + 1)
    options:                      # варианты (порядок перемешивается на сайте)
      - text: "`2`"               # Markdown
        correct: true             # single/output/find_bug — ровно один true; multiple — один и более
        why: "Почему верно"       # пояснение к варианту — показывается после ответа
      - text: "`11`"
        why: "Почему неверно"
    answer: ""                    # вместо options: ответ вводится текстом (сравнение без регистра и лишних пробелов)
    explanation: "Общий разбор"   # обязательно

tasks:
  - id: t1                        # уникален в файле
    title: "Название"
    mode: browser                 # browser — проверка в браузере; local — pytest у ученика
    difficulty: 1                 # 1 простая, 2 средняя, 3 сложная
    statement: |                  # условие, Markdown
      Напишите функцию `add(a, b)`…
    examples:                     # примеры в условии
      - input: "add(2, 3)"
        output: "5"
        explanation: ""           # необязательно
    starter: |                    # заготовка в редакторе (НЕ должна проходить тесты)
      def add(a, b):
          pass
    hints:                        # подсказки по уровням (2 шт.)
      - "Подсказка 1"
      - "Подсказка 2"
    solution: |                   # эталонное решение (должно проходить все тесты)
      def add(a, b):
          return a + b
    solution_explanation: "Разбор решения"  # Markdown
    setup: ""                     # код, выполняемый перед кодом ученика в каждом тесте (импорты, данные)
    files: {}                     # browser: файлы в виртуальной ФС {имя: содержимое}; local: файлы заготовки
    assets: []                    # пути к файлам папки блока, например data/titanic.csv
    constraints:                  # необязательно: требования к тексту кода (комментарии не учитываются)
      require: ["for "]
      forbid: ["sum("]
      message: "Решите циклом"
    timeout: 10                   # секунд на один тест
    mini_project: false           # true — мини-проект практикума
    tests:                        # скрытые тесты (browser), минимум 5 в уроке
      - name: "Обычный случай"    # видно ученику
        call: "add(2, 3)"         # 1) вызов функции …
        expected: "5"             #    … и ожидаемое значение (Python-выражение)
      - name: "Ввод с клавиатуры"
        stdin: "2\n3\n"           # строки для input()
        stdout: "5"               # 2) точный вывод программы
      - name: "Вывод содержит"
        stdin: "2\n3\n"
        stdout_contains: ["5"]    # 3) подстроки в выводе
      - name: "Произвольная проверка"
        code: |                   # 4) код с assert; сообщение assert показывается ученику
          assert add(-1, 1) == 0, "add(-1, 1) должно быть 0"
      - name: "Свои входные данные"
        setup: "bill = 0"         # код только этого теста — выполняется после setup задачи, до кода ученика
        stdout: "0"
    # --- только для mode: local ---
    run: "pytest -q"              # команда проверки у ученика
    solution_files: {}            # эталонные версии файлов (перекрывают files)
```

### Как работают тесты (browser)

- У каждого теста — ровно один вид проверки: `call`+`expected`, `stdout`, `stdout_contains` или `code`.
- Для каждого теста код ученика выполняется заново в чистом пространстве имён (после `setup` и записи `files`).
- Тесты `call` и `code` выполняют код как модуль (`__name__ == "solution"`): блок `if __name__ == "__main__":` не запускается.
  Тесты `stdout`/`stdout_contains` выполняют код как программу (`__name__ == "__main__"`).
- Приглашения `input("…")` не попадают в проверяемый вывод. В выводе игнорируются пробелы в конце строк и пустые строки по краям.
- Сравнение `expected`: числа — с допуском 1e-6 (`int` и `float` равны при равенстве значений), `bool` строго,
  `list`/`tuple` — с учётом типа, `dict` — по ключам, numpy-массивы — `allclose` + форма, pandas — `assert_frame_equal` без проверки dtype.
- `expected` вычисляется в отдельном пространстве после `setup`, поэтому может использовать импорты из `setup`.
- В тестах `code` доступны `__stdout__` (вывод программы ученика) и `__source__` (текст решения).
- Задачи без функций (первые уроки): входные переменные задаются в `setup` задачи (для «Запустить»)
  и переопределяются в `setup` теста — так каждая проверка получает свои данные.
- Пакеты (numpy, pandas, scikit-learn, matplotlib, sqlite3, pydantic…) подгружаются автоматически по `import`.
- Графики matplotlib в «Запустить» показываются картинками; в тестах проверяйте объекты (`plt.gcf().axes[0]…`).

### Local-задания

`files` — полный набор файлов заготовки (код + `tests/test_*.py`). Ученик скачивает ZIP (файлы + README с условием и командой `run`),
решает у себя, запускает тесты и вставляет вывод pytest на сайт. Засчитывается вывод с «N passed» и без «failed/error».
`solution_files` — эталонные версии изменённых файлов. Внешние API в тестах — только через моки.

## project/project.yaml

```yaml
title: "Менеджер задач в консоли"
mode: browser                     # browser | local — основной режим проекта
description: |                    # полное ТЗ, Markdown
  …
requirements:                     # список требований (Markdown-строки)
  - "Добавление задач"
stages:                           # 6–12 этапов
  - id: stage-01
    title: "Модель данных"
    description: |                # что сделать на этапе
      …
    hints: ["…"]                  # подсказки этапа
    tasks: [ ... ]                # задачи в формате выше — автоматические проверки этапа
    criteria:                     # чек-лист самопроверки (особенно для local)
      - "Код разбит на функции"
```

Этап пройден, когда решены все его задачи и отмечены все пункты `criteria`.
