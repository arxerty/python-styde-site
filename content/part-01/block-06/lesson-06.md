# Рекурсия

## Функция, которая вызывает саму себя

**Рекурсия** — приём, при котором функция вызывает **саму себя**, чтобы решить задачу через решение меньшей версии той же задачи. Звучит как фокус, но это естественный способ мыслить о многих структурах: папка содержит файлы и **другие папки**; JSON-объект содержит значения и **другие JSON-объекты**; дерево решений состоит из узлов, у которых есть **поддеревья**.

Классический пример — факториал: `n! = 1 · 2 · 3 · … · n`. Заметим, что `5! = 5 · 4!`, а `4! = 4 · 3!` — задача сводится к такой же задаче меньшего размера:

```python
def factorial(n):
    if n <= 1:
        return 1
    return n * factorial(n - 1)


print(factorial(5))
print(factorial(1))
```

```text
120
1
```

## Две обязательные части

Любая правильная рекурсивная функция состоит из двух частей:

1. **Базовый случай** — условие, при котором ответ известен **без** рекурсии. Здесь `n <= 1` → ответ 1.
2. **Рекурсивный шаг** — сведение задачи к **меньшей** задаче того же вида: `factorial(n)` → `n * factorial(n - 1)`.

Каждый рекурсивный вызов должен **приближать** к базовому случаю. Если базового случая нет или шаг к нему не ведёт — функция будет вызывать себя бесконечно.

## Как это выполняется

Вспомните **кадры вызова** из первого урока блока: каждый вызов получает собственное пространство для параметров. При рекурсии кадры накапливаются в **стеке вызовов**:

```text
factorial(4)
  → 4 * factorial(3)          ждёт результата
        → 3 * factorial(2)    ждёт результата
              → 2 * factorial(1)
                    → 1       базовый случай
              ← 2 * 1 = 2
        ← 3 * 2 = 6
  ← 4 * 6 = 24
```

Сначала вызовы «спускаются» до базового случая, откладывая умножения. Затем результаты «поднимаются» обратно, и каждый кадр завершает своё вычисление. Каждый вызов имеет **своё** значение `n` — они не мешают друг другу.

Это можно увидеть, добавив отладочный вывод с отступом по глубине:

```python
def factorial(n, depth=0):
    print("  " * depth + f"factorial({n})")
    if n <= 1:
        return 1
    result = n * factorial(n - 1, depth + 1)
    print("  " * depth + f"→ {result}")
    return result


factorial(3)
```

```text
factorial(3)
  factorial(2)
    factorial(1)
  → 2
→ 6
```

## Предел глубины рекурсии

Каждый кадр занимает память, поэтому Python ограничивает глубину рекурсии — по умолчанию около 1000 вызовов:

```python
def countdown(n):
    if n == 0:
        return "старт"
    return countdown(n - 1)


print(countdown(500))
print(countdown(5000))
```

Первый вызов сработает, второй упадёт с `RecursionError: maximum recursion depth exceeded`. Та же ошибка возникает при **забытом базовом случае** — тогда рекурсия «бесконечна», и предел наступает быстро:

```python
def broken(n):
    return broken(n - 1)


broken(10)
```

Результат — `RecursionError`. Предел можно поднять (`sys.setrecursionlimit`), но это почти всегда неверное решение: если задача требует тысяч уровней, лучше переписать её циклом.

## Рекурсия против цикла

Факториал легко посчитать и циклом:

```python
def factorial_loop(n):
    result = 1
    for k in range(2, n + 1):
        result *= k
    return result


print(factorial_loop(5))
```

```text
120
```

В Python цикл здесь лучше: он быстрее (нет накладных расходов на кадры) и не упирается в предел глубины. Любую рекурсию можно переписать циклом (иногда — с явным стеком), и наоборот. Когда же выбирать рекурсию?

- **Данные рекурсивны по природе**: вложенные структуры, деревья, файловые системы, JSON произвольной глубины. Цикл для них неестественен, рекурсия — читается как определение.
- **Задача делится на подзадачи** того же вида: «разделяй и властвуй» (быстрая сортировка, бинарный поиск), перебор вариантов.

Если же рекурсия — просто «другой способ записать цикл» (факториал, сумма списка), в Python выбирайте цикл.

## Где рекурсия незаменима: вложенные структуры

Представим вложенный список произвольной глубины — например, теги, сгруппированные по категориям на разных уровнях. Нужно «сплющить» его в плоский список. Comprehension из урока про коллекции справляется только с одним уровнем вложенности. Рекурсия — с любым:

```python
def flatten(items):
    result = []
    for item in items:
        if isinstance(item, list):
            result.extend(flatten(item))
        else:
            result.append(item)
    return result


print(flatten([1, [2, [3, [4, 5]], 6], [[7]]]))
```

```text
[1, 2, 3, 4, 5, 6, 7]
```

Логика читается как определение: «плоская версия списка — это его элементы, где каждый вложенный список заменён своей плоской версией». `isinstance(item, list)` проверяет, является ли элемент списком. Базовый случай здесь неявный — элемент, который не является списком, или пустой список (цикл просто не выполнится).

### Обход JSON произвольной глубины

То же для словарей: найдём в JSON-ответе все строковые значения поля `"text"` на любой глубине:

```python
def find_texts(data):
    found = []
    if isinstance(data, dict):
        for key, value in data.items():
            if key == "text" and isinstance(value, str):
                found.append(value)
            else:
                found.extend(find_texts(value))
    elif isinstance(data, list):
        for item in data:
            found.extend(find_texts(item))
    return found


response = {
    "content": [
        {"type": "text", "text": "Привет!"},
        {"type": "tool_use", "input": {"query": "погода"}},
        {"type": "text", "text": "Как дела?"},
    ],
    "meta": {"notes": [{"text": "внутренняя заметка"}]},
}
print(find_texts(response))
```

```text
['Привет!', 'Как дела?', 'внутренняя заметка']
```

Функция не знает заранее, какой глубины структура: она разбирает текущий уровень и поручает вложенные уровни **себе же**. Числа и строки — базовый случай: для них просто возвращается пустой список.

## Разделяй и властвуй

Второй класс задач, где рекурсия естественна, — разбиение на подзадачи. Бинарный поиск из блока про циклы рекурсивно:

```python
def binary_search(sorted_items, target, low=0, high=None):
    if high is None:
        high = len(sorted_items) - 1
    if low > high:
        return -1
    middle = (low + high) // 2
    if sorted_items[middle] == target:
        return middle
    if sorted_items[middle] < target:
        return binary_search(sorted_items, target, middle + 1, high)
    return binary_search(sorted_items, target, low, middle - 1)


data = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(binary_search(data, 23), binary_search(data, 7))
```

```text
5 -1
```

Каждый вызов вдвое сужает диапазон, поэтому глубина рекурсии — всего log₂(n): для миллиона элементов около 20. Предел в 1000 уровней здесь не страшен.

## Ловушка: повторные вычисления

Числа Фибоначчи: каждое — сумма двух предыдущих (0, 1, 1, 2, 3, 5, 8, …). Прямолинейная рекурсия красива, но катастрофически медленна:

```python
calls = 0


def fib(n):
    global calls
    calls += 1
    if n < 2:
        return n
    return fib(n - 1) + fib(n - 2)


print(fib(20), "вызовов:", calls)
```

```text
6765 вызовов: 21891
```

21 891 вызов ради `fib(20)`! Причина: `fib(18)` вычисляется дважды, `fib(17)` — трижды и так далее; число вызовов растёт экспоненциально. `fib(40)` займёт минуты.

Решение — **запоминать** уже вычисленные результаты (мемоизация):

```python
def fib_memo(n, cache=None):
    if cache is None:
        cache = {}
    if n < 2:
        return n
    if n not in cache:
        cache[n] = fib_memo(n - 1, cache) + fib_memo(n - 2, cache)
    return cache[n]


print(fib_memo(80))
```

```text
23416728348467685
```

Мгновенно. (Обратите внимание на `cache=None` — защита от ловушки изменяемого значения по умолчанию из урока 2.) В блоке 2.4 вы узнаете декоратор `functools.lru_cache`, который добавляет мемоизацию к любой функции одной строкой. Мемоизация — основа **динамического программирования**, на котором построены многие алгоритмы, включая вычисление расстояния редактирования между строками (сравнение текстов, исправление опечаток).

## Частые ошибки

**1. Нет базового случая** или шаг к нему не ведёт → `RecursionError`.

**2. Базовый случай не покрывает все входы.** `factorial(-1)` с условием `n == 1` уйдёт в бесконечность; используйте `n <= 1`.

**3. Забытый return.** `factorial(n - 1)` без `return` в рекурсивном шаге — функция вернёт `None` и умножение упадёт.

**4. Изменяемое значение по умолчанию для накопителя.** `def collect(data, result=[])` будет копить результаты между внешними вызовами.

**5. Экспоненциальные повторные вычисления.** Наивный Фибоначчи — используйте мемоизацию.

**6. Рекурсия там, где нужен цикл.** Глубокие линейные рекурсии (тысячи уровней) упираются в предел — пишите цикл.

## Где это в AI-инженерии

- **Вложенный JSON.** Ответы API, конфигурации и structured output произвольной глубины обходят рекурсивно: найти все значения поля, заменить секреты на `***` перед логированием, посчитать токены во всех текстовых полях.
- **Деревья решений.** Решающее дерево (блок 5.3) строится рекурсивно: разбить данные по признаку и построить поддеревья для каждой части, пока не выполнено условие остановки — базовый случай.
- **Обход файлов.** Сбор всех документов из папки с подпапками для базы знаний RAG — рекурсивный обход (в `pathlib` есть готовый `rglob`, блок 1.7).
- **Рекурсивный чанкинг.** Популярная стратегия деления документов для RAG: разрезать по абзацам; если кусок всё ещё большой — по предложениям; если всё ещё большой — по словам. Это рекурсия по уровням разделителей (блок 7.5).
- **Автоматическое дифференцирование.** Backpropagation рекурсивно проходит граф вычислений от результата к входам (блок 3.2, где вы напишете мини-autograd).
- **Агенты.** Агент, который разбивает задачу на подзадачи и вызывает для них «под-агентов», — рекурсия на уровне архитектуры; ограничение глубины здесь так же важно, как в Python.

## Итоги урока

- Рекурсия — функция вызывает саму себя для меньшей версии задачи.
- Обязательны базовый случай и шаг, приближающий к нему; иначе `RecursionError`.
- Вызовы накапливаются в стеке; предел глубины в Python — около 1000.
- Рекурсия естественна для вложенных структур (JSON, деревья, папки) и «разделяй и властвуй»; для простых линейных задач лучше цикл.
- Повторные вычисления устраняются мемоизацией (кэшем результатов).
