# def, параметры, return и None

## Зачем писать свои функции

Вы уже пользовались десятками функций: `print`, `len`, `sorted`, `input`, `round`. Каждая из них — именованный кусок кода, который принимает данные, что-то делает и, возможно, возвращает результат. Пора научиться писать **свои**.

Вспомните задачи прошлых блоков. Очистка слова от пунктуации повторялась почти в каждом уроке про строки. Подсчёт среднего — в половине задач. В задаче про сходство Жаккара пришлось крутить цикл на два повтора, лишь бы не копировать код очистки текста. Копирование кода — главный враг программиста:

- ошибку приходится исправлять во всех копиях (и одну обязательно забудете);
- программа растёт и становится нечитаемой;
- непонятно, что делает очередной кусок, пока не прочитаешь его целиком.

**Функция** решает все три проблемы: код пишется **один раз**, получает **имя**, которое объясняет его смысл, и вызывается сколько угодно раз.

## Определение функции

```python
def greet(name):
    print(f"Привет, {name}!")


greet("Ада")
greet("Алан")
```

```text
Привет, Ада!
Привет, Алан!
```

Разберём синтаксис:

```python norun
def имя_функции(параметр1, параметр2):
    тело функции
```

1. **`def`** (от define — определить) начинает определение функции.
2. **Имя** — по тем же правилам, что имена переменных; по PEP 8 — `snake_case` и лучше глагол: `greet`, `calculate_average`, `clean_text`.
3. **Параметры** в скобках — имена для входных данных. Их может не быть совсем: `def show_menu():`.
4. **Двоеточие** и **тело с отступом** — как у `if` и `for`.

PEP 8 рекомендует отделять определения функций от остального кода двумя пустыми строками.

### Определение и вызов — разные вещи

Строки `def ...` **не выполняют** тело функции. Python лишь запоминает: «есть функция с таким именем и таким кодом». Тело выполняется при **вызове** — когда вы пишете имя со скобками и аргументами:

```python
def warn():
    print("Внимание!")


print("До вызова")
warn()
warn()
print("После вызова")
```

```text
До вызова
Внимание!
Внимание!
После вызова
```

Функцию нужно **определить до вызова**: если вызвать её раньше строки `def`, будет `NameError`, как с переменной.

## Параметры и аргументы

Два термина, которые часто путают:

- **параметр** — имя в определении функции: `def greet(name)` — здесь `name` параметр;
- **аргумент** — конкретное значение при вызове: `greet("Ада")` — здесь `"Ада"` аргумент.

При вызове Python привязывает параметры к аргументам **по порядку** и выполняет тело:

```python
def describe(model, params, year):
    print(f"{model}: {params} млрд параметров, {year} год")


describe("GPT-3", 175, 2020)
describe("BERT", 0.34, 2018)
```

```text
GPT-3: 175 млрд параметров, 2020 год
BERT: 0.34 млрд параметров, 2018 год
```

Количество аргументов должно совпадать с количеством параметров (если не заданы значения по умолчанию — следующий урок). Иначе — `TypeError`:

```python
def describe(model, params, year):
    print(model, params, year)


describe("GPT-3", 175)
```

Результат — `TypeError: describe() missing 1 required positional argument: 'year'`.

## return: функция возвращает результат

Функции выше **печатают**. Но гораздо чаще функция должна **вычислить** значение и **вернуть** его вызывающему коду, чтобы тот распорядился результатом сам. Для этого есть `return`:

```python
def average(numbers):
    return sum(numbers) / len(numbers)


scores = [5, 4, 5, 3]
result = average(scores)
print(result)
print(average([10, 20]) * 2)
if average(scores) > 4:
    print("Хорошо")
```

```text
4.25
30.0
Хорошо
```

Вызов функции с `return` — это **выражение**: его можно присвоить, передать в другую функцию, использовать в условии и арифметике. `average(scores)` «превращается» в значение `4.25`.

### return завершает функцию

`return` не только возвращает значение, но и **немедленно завершает** выполнение функции. Код после него не выполняется:

```python
def sign(x):
    if x > 0:
        return "плюс"
    if x < 0:
        return "минус"
    return "ноль"


print(sign(5), sign(-2), sign(0))
```

```text
плюс минус ноль
```

Приём «ранний возврат» избавляет от `elif`/`else`: если первое условие сработало — функция уже вышла. Он же решает задачу из блока про циклы — **выход из вложенных циклов**:

```python
def find_pair(numbers, target):
    for a in numbers:
        for b in numbers:
            if a != b and a + b == target:
                return a, b
    return None


print(find_pair([3, 8, 1, 7], 10))
print(find_pair([1, 2], 100))
```

```text
(3, 7)
None
```

`return` внутри внутреннего цикла сразу выходит из **функции**, а значит, и из обоих циклов. Это самый чистый способ — без флагов и `for…else`.

### Несколько значений

`return a, b` возвращает **кортеж** — а вызывающий код распаковывает его:

```python
def min_max(numbers):
    return min(numbers), max(numbers)


low, high = min_max([7, 2, 9, 4])
print(low, high)
```

```text
2 9
```

## print против return

Самая частая ошибка начинающих — путать **печать** и **возврат**:

```python
def add_print(a, b):
    print(a + b)


def add_return(a, b):
    return a + b


x = add_print(2, 3)
y = add_return(2, 3)
print("x =", x)
print("y =", y)
```

```text
5
x = None
y = 5
```

`add_print` выводит 5 на экран, но **ничего не возвращает** — поэтому `x` равен `None`. С результатом `add_print` ничего нельзя сделать: ни сложить, ни сохранить, ни проверить. Правило:

- функция, которая **вычисляет**, должна **возвращать** результат;
- печатать результат должен **вызывающий** код (или специальная функция «вывода»).

Именно так проверяются задачи в этом блоке: тесты вызывают вашу функцию и сравнивают **возвращённое** значение. Если функция печатает вместо `return`, тест получит `None`.

## None: функция без return

Если функция дошла до конца без `return` (или выполнила `return` без значения), она возвращает **`None`** — специальное значение «ничего». Вы уже видели это у `print()`, `list.append()` и `list.sort()`:

```python
def log(message):
    print("[LOG]", message)


result = log("старт")
print(result is None)
```

```text
[LOG] старт
True
```

Функции, которые что-то делают (печатают, изменяют список, пишут в файл), но ничего не вычисляют, обычно возвращают `None` — и это нормально. Проблема только в том, чтобы не ожидать от них результата.

Коварный случай — `return` есть не во всех ветках:

```python
def grade(score):
    if score >= 90:
        return "отлично"
    elif score >= 60:
        return "зачёт"


print(grade(95), grade(70), grade(30))
```

```text
отлично зачёт None
```

Для `score = 30` ни одна ветка не сработала, функция дошла до конца и вернула `None`. Проверяйте: **каждый путь выполнения функции, возвращающей значение, должен заканчиваться `return`**.

## Как вызов работает внутри

При каждом вызове Python создаёт **кадр вызова** (frame) — отдельное пространство для параметров и переменных этого вызова:

1. Вычисляются аргументы.
2. Создаётся новый кадр; параметры привязываются к аргументам.
3. Выполняется тело функции.
4. На `return` (или в конце тела) кадр уничтожается, значение передаётся туда, откуда был вызов.

Переменные, созданные внутри функции, **локальны**: их не видно снаружи, и они исчезают после завершения вызова:

```python
def compute():
    temp = 42
    return temp * 2


print(compute())
print(temp)
```

Последняя строка упадёт с `NameError: name 'temp' is not defined` — `temp` существовала только внутри вызова. Это не неудобство, а защита: функции не мешают друг другу своими переменными. Подробно об областях видимости — в уроке 4.

Именно стек кадров вы видите в длинных traceback: каждый блок `File ..., line ..., in имя_функции` — это кадр одного вызова, от самого внешнего к тому, где случилась ошибка.

### Аргументы передаются как ссылки

Параметр получает **ссылку на тот же объект**, что и аргумент (вспомните модель «имя — ярлык»). Поэтому функция может **изменить** переданный изменяемый объект:

```python
def add_item(items, item):
    items.append(item)


cart = ["молоко"]
add_item(cart, "хлеб")
print(cart)
```

```text
['молоко', 'хлеб']
```

Список `cart` изменился — функция работала с тем же объектом. Это удобно, но может быть неожиданно. Хорошая практика: функция либо **изменяет** аргумент и возвращает `None` (как `list.sort()`), либо **не изменяет** его и возвращает новый результат (как `sorted()`). Смешивать — путь к ошибкам.

## Разбор задачи: функции для обработки текста

Перепишем код очистки текста из блока 1.4 функциями:

```python
PUNCTUATION = ".,!?;:—-«»\"()"


def clean_word(token):
    return token.lower().strip(PUNCTUATION)


def tokenize(text):
    words = []
    for token in text.split():
        word = clean_word(token)
        if word:
            words.append(word)
    return words


def jaccard(text_a, text_b):
    a = set(tokenize(text_a))
    b = set(tokenize(text_b))
    union = a | b
    return len(a & b) / len(union) if union else 0.0


print(tokenize("Привет, Мир! — Это тест."))
print(round(jaccard("Кот спит.", "кот ест"), 3))
```

```text
['привет', 'мир', 'это', 'тест']
0.333
```

Сравните с решением задачи про Жаккара из блока 1.5, где пришлось крутить цикл на два повтора. Теперь каждая функция делает **одну** понятную вещь, функции **строятся друг на друге** (`jaccard` использует `tokenize`, а та — `clean_word`), и каждую можно проверить отдельно. Константа `PUNCTUATION` в верхнем регистре — по соглашению значение, которое не меняется.

## Частые ошибки

**1. print вместо return.** Функция «работает» (на экране правильное число), но возвращает `None`.

**2. Не все ветки возвращают значение.** Неявный `None` в одной из веток.

**3. Вызов без скобок.** `result = average` — это сама функция, а не результат её вызова.

**4. Код после return.** Он никогда не выполнится; линтеры предупреждают о «недостижимом коде».

**5. Использование локальной переменной снаружи.** `NameError` — значение нужно вернуть через `return`.

**6. Неожиданное изменение аргумента.** Функция меняет переданный список, а вызывающий код этого не ждёт. Если менять не нужно — работайте с копией или создавайте новый список.

## Где это в AI-инженерии

- **Предобработка.** `clean_text`, `tokenize`, `normalize` — функции, которые применяются к каждому примеру датасета.
- **Метрики.** `accuracy(preds, labels)`, `precision_recall(...)` — чистые функции: данные на входе, число на выходе.
- **Инструменты агентов.** Function calling в LLM буквально построен на функциях: вы описываете функцию (имя, параметры, назначение), модель решает её вызвать, ваш код выполняет функцию и возвращает результат модели (блок 7.6).
- **Обёртки над API.** `ask_llm(prompt)` скрывает детали запроса: сборку сообщений, параметры, обработку ошибок. Весь остальной код просто вызывает функцию.
- **Шаг обучения.** `train_step(model, batch)` возвращает loss — стандартная структура цикла обучения.
- **Тестируемость.** Функцию с понятным входом и выходом легко проверить тестами (блок 2.8). Именно так проверяются задачи на этой платформе.

## Итоги урока

- `def имя(параметры):` + тело с отступом; тело выполняется только при вызове `имя(аргументы)`.
- `return значение` возвращает результат и сразу завершает функцию; `return a, b` — кортеж.
- Без `return` функция возвращает `None`; вычисляющая функция должна возвращать, а не печатать.
- Переменные внутри функции локальны; аргументы передаются ссылками — изменяемый объект можно изменить.
- Функция = одна задача + говорящее имя; функции строятся друг на друге.
