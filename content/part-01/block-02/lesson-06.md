# match-case: структурное сопоставление

## Зачем ещё одна конструкция ветвления

Представьте чат-бота, который понимает команды `/help`, `/reset`, `/model` и `/exit`. Через `if/elif` это выглядит так:

```python
command = "/reset"
if command == "/help":
    print("Список команд")
elif command == "/reset":
    print("История очищена")
elif command == "/model":
    print("Текущая модель: mini")
elif command == "/exit":
    print("До свидания")
else:
    print("Неизвестная команда")
```

```text
История очищена
```

Работает, но имя `command ==` повторяется в каждой строке, и суть — «выбрать действие по значению» — теряется в шуме. Начиная с Python 3.10 для этого есть конструкция **`match-case`** (структурное сопоставление с образцом, structural pattern matching):

```python
command = "/reset"
match command:
    case "/help":
        print("Список команд")
    case "/reset":
        print("История очищена")
    case "/model":
        print("Текущая модель: mini")
    case "/exit":
        print("До свидания")
    case _:
        print("Неизвестная команда")
```

```text
История очищена
```

Значение указано один раз, а каждый `case` описывает **образец** (pattern), с которым его сравнивают.

## Синтаксис

```python norun
match выражение:
    case образец_1:
        действия
    case образец_2:
        действия
    case _:
        действия по умолчанию
```

Как это работает:

1. Python вычисляет выражение после `match` (его называют **субъектом**).
2. По очереди сверху вниз проверяет образцы в `case`.
3. Выполняет блок **первого** подошедшего `case`, после чего выходит из `match`.
4. Если ни один образец не подошёл и нет `case _`, ничего не происходит.

Отступы — как везде в Python: `case` сдвинут относительно `match`, тело — относительно `case`.

> **Нет «проваливания».** В языках C, Java, JavaScript есть похожий `switch`, где без `break` выполнение «проваливается» в следующий `case`. В Python такого нет: выполняется ровно один блок. Это убирает целый класс ошибок.

## Виды образцов

### Литералы

Самый простой образец — конкретное значение: строка, число, `True`, `False`, `None`.

```python
status = 404
match status:
    case 200:
        print("OK")
    case 404:
        print("Не найдено")
    case 500:
        print("Ошибка сервера")
```

```text
Не найдено
```

### Подстановочный знак _

`case _:` подходит к **любому** значению — это аналог `else`. Его ставят последним. Символ `_` здесь особенный: он ничего не запоминает, просто означает «что угодно».

### Несколько вариантов через |

Если одно действие подходит для нескольких значений, их перечисляют через `|` («или»):

```python
day = "сб"
match day:
    case "пн" | "вт" | "ср" | "чт" | "пт":
        print("Рабочий день")
    case "сб" | "вс":
        print("Выходной")
    case _:
        print("Нет такого дня")
```

```text
Выходной
```

### Захват значения в переменную

Если в образце стоит **имя** (не `_` и не литерал), оно подходит к любому значению и **запоминает** его:

```python
command = "/weather"
match command:
    case "/help":
        print("Список команд")
    case unknown:
        print("Неизвестная команда:", unknown)
```

```text
Неизвестная команда: /weather
```

Образец `unknown` подошёл к любому значению и связал его с именем `unknown`. Это похоже на `case _`, но значение остаётся доступным в блоке.

### Условия-охранники (guard)

К образцу можно добавить условие через `if`. Образец подходит, только если условие истинно:

```python
temperature = 1.5
match temperature:
    case 0:
        print("Детерминированный режим")
    case t if 0 < t <= 1:
        print("Сбалансированный режим")
    case t if t > 1:
        print("Творческий режим")
    case _:
        print("Некорректная температура")
```

```text
Творческий режим
```

Здесь `t` захватывает значение, а `if` проверяет диапазон. Это позволяет использовать `match` и для числовых интервалов, хотя для простых диапазонов `if/elif` обычно читается проще.

### Последовательности

Самое мощное в `match` — способность разбирать **структуру** данных. Например, пару значений `(x, y)` можно сопоставить с образцами, где часть элементов фиксирована, а часть захватывается:

```python
point = (0, 5)
match point:
    case (0, 0):
        print("Начало координат")
    case (0, y):
        print("На оси Y, y =", y)
    case (x, 0):
        print("На оси X, x =", x)
    case (x, y):
        print("Точка", x, y)
```

```text
На оси Y, y = 5
```

`(0, 5)` — это **кортеж**, неизменяемая пара значений (подробно — в блоке про коллекции). Образец `(0, y)` означает: «пара, где первый элемент равен 0, а второй — любой; второй запомни как `y`». Это и есть **структурное** сопоставление: проверяется не только значение, но и форма данных.

Тот же приём позволяет разбирать команды из нескольких слов. Метод `split()` разбивает строку на слова (подробно — в блоке про строки):

```python
text = "model large"
match text.split():
    case ["help"]:
        print("Справка")
    case ["model", name]:
        print("Переключаемся на модель", name)
    case ["model"]:
        print("Укажите имя модели")
    case _:
        print("Не понимаю")
```

```text
Переключаемся на модель large
```

Образец `["model", name]` подходит к списку ровно из двух слов, первое из которых — `"model"`. Попробуйте поменять `text` на `"model"`, `"help"` и `"model a b"`.

## Ловушка: имя — это захват, а не сравнение

Самая коварная ошибка в `match`. Хочется сравнить субъект со значением из переменной:

```python
correct_answer = "Париж"
answer = "Лондон"
match answer:
    case correct_answer:
        print("Верно!")
```

Вы ожидаете сравнение с `"Париж"`, но голое имя в `case` — это **захват**: оно подходит к любому значению и перезаписывает `correct_answer`. Если после такого `case` есть другие варианты, Python даже откажется запускать код с ошибкой `SyntaxError: name capture 'correct_answer' makes remaining patterns unreachable`.

Для сравнения со значением переменной используйте охранник:

```python
correct_answer = "Париж"
answer = "Лондон"
match answer:
    case a if a == correct_answer:
        print("Верно!")
    case _:
        print("Неверно")
```

```text
Неверно
```

(Ещё один способ — «точечные» имена вроде `Color.RED`, которые `match` воспринимает как константы. Вы встретите их в части 2 вместе с `Enum`.)

## Как Python сопоставляет образец: по шагам

Разберём, что происходит при проверке образца `["model", name]` для субъекта `["model", "large"]`:

1. **Проверка вида.** Образец в квадратных скобках — это образец последовательности. Python проверяет, что субъект — последовательность (список, кортеж), но **не строка**: строки в `match` специально не считаются последовательностями символов, чтобы `case [a, b]:` случайно не «разобрал» слово `"ok"` на буквы.
2. **Проверка длины.** В образце два элемента — субъект тоже должен иметь ровно два. Если бы пользователь ввёл `model a b`, длина 3 не совпала бы, и Python перешёл бы к следующему `case`.
3. **Поэлементная проверка.** Первый элемент образца — литерал `"model"`: сравнивается через `==`. Второй — имя `name`: подходит к любому значению.
4. **Связывание.** Только если все проверки успешны, имя `name` получает значение `"large"`, и выполняется тело `case`.
5. **Охранник.** Если у образца есть `if`, он проверяется последним — уже с привязанными именами.

Если на любом шаге проверка не прошла, Python переходит к следующему `case`. Поэтому порядок образцов так же важен, как порядок условий в `if/elif`: сначала частные, потом общие.

Для сравнения — как пришлось бы писать то же самое без `match`:

```python
words = "model large".split()
if len(words) == 1 and words[0] == "help":
    print("Справка")
elif len(words) == 2 and words[0] == "model":
    name = words[1]
    print("Переключаемся на модель", name)
else:
    print("Не понимаю")
```

```text
Переключаемся на модель large
```

Логика та же, но проверки длины и индексы вручную делают код шумным, а ошибиться в них легко. `match` описывает **форму** данных декларативно: «список из двух слов, первое — model», и Python сам делает все проверки.

## match или if/elif?

| Ситуация | Лучше |
|---|---|
| Выбор действия по одному значению из набора констант | `match` |
| Разбор структуры: пары, списки, команды из нескольких слов | `match` |
| Условия на разные переменные (`a > 0 and b < 5`) | `if/elif` |
| Числовые диапазоны | `if/elif` (или `match` с охранниками) |
| Код должен работать на Python старше 3.10 | `if/elif` |

`match` — не замена `if`, а инструмент для конкретной задачи: **сопоставить данные с образцами**. Он особенно хорош, когда данные имеют разную форму.

## Разбор задачи: маршрутизация инструментов агента

В части 7 вы будете писать AI-агентов: языковая модель решает, какой «инструмент» вызвать, и присылает его имя и аргументы. Код агента должен выполнить нужное действие. Упрощённо:

```python
tool_call = ("calculator", "2 + 2")
match tool_call:
    case ("calculator", expression):
        print("Считаю:", expression)
    case ("search", query):
        print("Ищу в интернете:", query)
    case ("read_file", path):
        print("Читаю файл:", path)
    case (name, _):
        print("Неизвестный инструмент:", name)
```

```text
Считаю: 2 + 2
```

Один `match` и разбирает структуру вызова (имя + аргумент), и выбирает действие. Последний `case (name, _)` ловит любой неизвестный инструмент — модель иногда «придумывает» инструменты, которых нет, и код должен это корректно обработать.

## Частые ошибки

**1. Голое имя как сравнение.** `case expected:` захватывает любое значение. Для сравнения с переменной — охранник `case x if x == expected:`.

**2. `case _` не последний.** Всё, что после него, недостижимо — Python сообщит об ошибке.

**3. Ожидать проваливания.** Выполняется только один `case`; `break` не нужен (и вне циклов недопустим).

**4. `or` вместо `|`.** В образцах альтернативы пишутся через `|`: `case "a" | "b":`. Запись `case "a" or "b":` — синтаксическая ошибка.

**5. Старая версия Python.** `match` появился в 3.10. На старых версиях — `SyntaxError`.

**6. Использовать match для всего.** Для двух вариантов или условий на разные переменные `if/else` проще.

## Где это в AI-инженерии

- **Маршрутизация вызовов инструментов.** Агент получает от модели имя инструмента и аргументы — `match` по имени выбирает функцию.
- **Роли сообщений.** Диалог с LLM состоит из сообщений с ролями `system`, `user`, `assistant`, `tool`. Обработка истории — естественное место для `match message_role:`.
- **Команды чат-бота.** `/reset`, `/model large`, `/temperature 0.2` — разбор через `match text.split():` с образцами-списками.
- **События стриминга.** При потоковой генерации API присылает события разных типов: начало сообщения, кусок текста, вызов инструмента, конец. Их обработка — типичный `match` по типу события.
- **Разбор структурированных ответов.** Когда модель возвращает JSON разной формы (ответ или запрос уточнения), `match` позволяет элегантно разобрать варианты — в части 2 вы увидите образцы для словарей.

## Итоги урока

- `match субъект:` + `case образец:` — выполняется первый подошедший образец, без проваливания.
- Образцы: литералы, `_` (что угодно), `|` (альтернативы), имена (захват), охранники `if`, последовательности `(0, y)` и `["model", name]`.
- Голое имя в `case` — захват, а не сравнение с переменной.
- `match` — для разбора значений и структур; `if/elif` — для условий на разные переменные и диапазоны.
