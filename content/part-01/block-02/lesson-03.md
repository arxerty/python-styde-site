# elif и вложенные условия

## Больше двух вариантов

`if/else` выбирает из двух веток. Но жизнь редко бывает бинарной: оценка бывает «отлично», «хорошо», «удовлетворительно» и «неудовлетворительно»; HTTP-ответ — успешным, ошибкой клиента или ошибкой сервера; тональность отзыва — позитивной, нейтральной или негативной.

Для выбора из нескольких вариантов есть **`elif`** — сокращение от «else if» («иначе если»):

```python
score = 82
if score >= 90:
    print("отлично")
elif score >= 75:
    print("хорошо")
elif score >= 60:
    print("удовлетворительно")
else:
    print("неудовлетворительно")
```

```text
хорошо
```

## Как работает цепочка if / elif / else

Python проверяет условия **сверху вниз** и выполняет **первую** ветку, условие которой истинно. Остальные ветки пропускаются — даже если их условия тоже истинны.

Для `score = 82`:

1. `82 >= 90`? Нет → дальше.
2. `82 >= 75`? Да → печатаем «хорошо» и **выходим** из всей конструкции.
3. `82 >= 60` тоже истинно, но до этой проверки дело не доходит.

Правила цепочки:

- начинается с `if`, затем любое количество `elif`, в конце — необязательный `else`;
- выполняется **не более одной** ветки (ровно одна, если есть `else`);
- у каждого `elif` своё условие и своё двоеточие;
- все части пишутся на одном уровне отступа.

### Порядок условий важен

Поскольку срабатывает первая истинная ветка, условия нужно располагать от более строгих к менее строгим. Посмотрите, что будет, если перепутать порядок:

```python
score = 95
if score >= 60:
    print("удовлетворительно")
elif score >= 75:
    print("хорошо")
elif score >= 90:
    print("отлично")
```

```text
удовлетворительно
```

Отличник получил тройку: условие `95 >= 60` истинно, и до остальных проверок дело не дошло. Это **логическая ошибка** — Python не сообщит о ней. Правило: **в цепочке с `>=` идите от большего порога к меньшему** (или с `<` — от меньшего к большему).

### elif против нескольких if

Сравните цепочку `elif` с независимыми `if`:

```python
temperature = 35
if temperature > 30:
    print("жарко")
if temperature > 20:
    print("тепло")
if temperature > 10:
    print("прохладно")
```

```text
жарко
тепло
прохладно
```

Три независимых `if` проверяются **каждый**, и при 35 градусах печатаются все три сообщения. С `elif` напечаталось бы только «жарко». Выбирайте осознанно:

- **`elif`** — когда варианты **взаимоисключающие** (выбрать одну категорию);
- **несколько `if`** — когда проверки **независимы** (например, несколько предупреждений, каждое из которых может сработать).

## Диапазоны без пробелов и пересечений

Частая задача — разбить числовую ось на интервалы. Благодаря тому, что `elif` проверяется только если предыдущие условия ложны, можно не писать обе границы:

```python
weight = 3.2
if weight <= 1:
    price = 300
elif weight <= 5:
    price = 500
elif weight <= 20:
    price = 900
else:
    price = None
print(price)
```

```text
500
```

Во второй ветке уже известно, что `weight > 1` (иначе сработала бы первая), поэтому писать `1 < weight <= 5` не нужно. Код короче, а интервалы гарантированно не пересекаются и не оставляют «дыр». Сравните с независимыми `if`, где пришлось бы аккуратно прописывать обе границы, и одна опечатка (`<` вместо `<=`) оставила бы значение `5` без цены.

## Вложенные условия

Внутри любой ветки может быть ещё одна конструкция `if` — она получает дополнительный отступ:

```python
is_member = True
total = 3500
if is_member:
    if total >= 3000:
        print("Скидка участника: 15%")
    else:
        print("Скидка участника: 5%")
else:
    print("Скидки нет. Вступите в клуб!")
```

```text
Скидка участника: 15%
```

Читать вложенные условия помогает отступ: внутренний `if/else` относится к ветке `is_member`. Каждый уровень вложенности — плюс 4 пробела.

### Когда вложенность — плохо

Вложенность удобна, когда второе условие имеет смысл только при выполнении первого. Но глубокая вложенность («лесенка» из 4–5 уровней) читается тяжело. Есть два способа её уменьшить:

1. **Логические операторы** `and`/`or` (следующий урок) позволяют объединить условия: `if is_member and total >= 3000:`.
2. **Цепочка `elif`** вместо вложенного `if` в `else`:

```python
code = 404
if code == 200:
    print("OK")
else:
    if code == 404:
        print("Не найдено")
    else:
        print("Другая ошибка")
```

Эквивалентная плоская версия:

```python
code = 404
if code == 200:
    print("OK")
elif code == 404:
    print("Не найдено")
else:
    print("Другая ошибка")
```

```text
Не найдено
```

> «Плоское лучше, чем вложенное» — один из принципов «Дзена Python». Выполните `import this`, чтобы прочитать его целиком.

## Разбор задачи: классификация HTTP-ответа

При работе с API (в том числе с языковыми моделями) важно правильно реагировать на код ответа. Коды делятся на группы: 2xx — успех, 4xx — ошибка запроса, 5xx — ошибка сервера. Особый случай — 429 (превышен лимит запросов): его стоит повторить позже.

```python
status = 429
if 200 <= status < 300:
    action = "обработать ответ"
elif status == 429:
    action = "подождать и повторить"
elif 400 <= status < 500:
    action = "исправить запрос"
elif status >= 500:
    action = "повторить позже"
else:
    action = "неизвестный код"
print(status, "→", action)
```

```text
429 → подождать и повторить
```

Обратите внимание на порядок: проверка `status == 429` стоит **до** общей проверки 4xx. Иначе 429 попал бы в группу «исправить запрос». Частный случай — раньше общего.

## Разбор: тональность по оценке модели

Модели анализа тональности часто выдают число от −1 (резко негативно) до 1 (восторженно). Чтобы показать пользователю понятную метку, число разбивают на интервалы:

```python
sentiment = -0.12
if sentiment <= -0.6:
    label = "очень негативно"
elif sentiment < -0.2:
    label = "негативно"
elif sentiment <= 0.2:
    label = "нейтрально"
elif sentiment < 0.6:
    label = "позитивно"
else:
    label = "очень позитивно"
print(sentiment, "→", label)
```

```text
-0.12 → нейтрально
```

Обратите внимание на смешение `<` и `<=`: решение о том, куда относить сами границы (−0.6, −0.2, 0.2, 0.6), — это продуктовое решение, а не техническое. Главное — чтобы каждая точка оси попала ровно в одну категорию. Цепочка `elif` гарантирует это автоматически, если условия идут по возрастанию верхних границ. Попробуйте подставить значения −1, −0.6, −0.2, 0, 0.2, 0.6 и 1 и проверить метки.

## Тестирование граничных значений

Цепочки условий — главный источник ошибок «на границе». Значение 74 даёт «удовлетворительно», 76 — «хорошо», а что даёт ровно 75? Правильно ли написано `>=` или случайно `>`? Проверка на «удобных» числах из середины диапазона этого не покажет.

Поэтому профессиональные тестировщики используют технику **граничных значений**: для каждой границы проверяют значение **на** границе и **по обе стороны** от неё. Для шкалы оценок это:

| Граница | Проверяем | Ожидаем |
|---|---|---|
| 90 | 89, 90, 91 | хорошо, отлично, отлично |
| 75 | 74, 75, 76 | удовл., хорошо, хорошо |
| 60 | 59, 60, 61 | неуд., удовл., удовл. |
| 0 и 100 | −1, 0, 100, 101 | ошибка, неуд., отлично, ошибка |

Скрытые тесты на этой платформе устроены именно так — поэтому они часто ловят ошибку, которую не видно на примере из условия. Привыкайте сами проверять границы: это сэкономит много времени.

## Таблица решений

Когда вариантов много, полезно сначала нарисовать **таблицу решений**, а уже потом писать код. Пример: тариф такси зависит от времени суток и класса машины.

| Класс \ время | день | ночь |
|---|---|---|
| эконом | 30 руб./км | 45 руб./км |
| комфорт | 50 руб./км | 70 руб./км |

По таблице сразу видно, что условий два и они независимы — удобно вложить одно в другое:

```python
car_class = "комфорт"
is_night = True
if car_class == "эконом":
    if is_night:
        rate = 45
    else:
        rate = 30
else:
    if is_night:
        rate = 70
    else:
        rate = 50
print("Тариф:", rate, "руб./км")
```

```text
Тариф: 70 руб./км
```

Таблица помогает убедиться, что учтены **все** комбинации и ни одна не потеряна. В следующем уроке с логическими операторами эту же логику можно будет записать плоской цепочкой `elif`.

## Пример с вводом: калькулятор ИМТ с категориями

```python
weight = float(input("Вес, кг: "))
height = float(input("Рост, м: "))
bmi = weight / height ** 2

if bmi < 18.5:
    category = "недостаточный вес"
elif bmi < 25:
    category = "норма"
elif bmi < 30:
    category = "избыточный вес"
else:
    category = "ожирение"

print("ИМТ:", round(bmi, 1), "—", category)
```

Здесь каждая ветка только присваивает `category`, а печать вынесена после цепочки. Такой стиль удобен: логика выбора отделена от вывода, и легко добавить новую категорию.

## Частые ошибки

**1. Неправильный порядок условий.** `score >= 60` перед `score >= 90` — отличники получают тройки.

**2. Независимые `if` вместо `elif`.** Срабатывают несколько веток, когда нужна одна.

**3. Дыры и пересечения в диапазонах.** `if x < 5 ... elif x > 5 ...` — значение 5 не попадает никуда. Используйте `<=`/`<` последовательно.

**4. `else` с условием.** `else score < 60:` → `SyntaxError`. Нужно `elif` или просто `else:`.

**5. Глубокая вложенность.** Код из 5 уровней `if` трудно читать и легко сломать. Выравнивайте через `elif` и логические операторы.

**6. `elif` без `if`.** Цепочка обязана начинаться с `if`.

## Где это в AI-инженерии

- **Маршрутизация запросов к моделям.** Короткий простой вопрос — в дешёвую быструю модель, длинный документ — в модель с большим контекстом, код — в специализированную. Это цепочка `if/elif/else` по длине и типу запроса — так экономят деньги в продакшне.
- **Пороговая классификация с несколькими классами.** Оценка тональности от −1 до 1 превращается в метку: `< -0.3` — негатив, `< 0.3` — нейтрально, иначе — позитив.
- **Обработка ошибок API.** Как в разборе выше: разные коды — разные действия. 429 → подождать, 401 → проверить ключ, 5xx → повторить.
- **Планировщики learning rate.** «Если эпоха < 5 — разогрев, если < 50 — основной режим, иначе — затухание» — тоже цепочка условий.
- **Guardrails.** Проверки входа модели: слишком длинный текст, запрещённые темы, подозрение на prompt injection — каждая проверка ведёт к своему действию.

## Итоги урока

- `if / elif / else` выбирает **первую** ветку с истинным условием; остальные пропускаются.
- Порядок условий важен: от строгих к общим, частные случаи — раньше общих.
- `elif` — для взаимоисключающих вариантов, несколько `if` — для независимых проверок.
- В цепочке `elif` можно не повторять уже проверенные границы — интервалы не пересекаются.
- Вложенные условия — дополнительный отступ; избегайте глубокой вложенности.
