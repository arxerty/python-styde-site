# Логические операторы and, or, not

## Когда одного условия мало

Реальные решения редко зависят от одного факта. Чтобы войти в систему, нужен **и** верный логин, **и** верный пароль. Чтобы повторить запрос к API, ошибка должна быть временной **и** попытки ещё не должны закончиться. Скидку дают студентам **или** пенсионерам. Запрос пропускают, если он **не** содержит запрещённых слов.

Слова «и», «или», «не» в Python — это **логические операторы** `and`, `or`, `not`. Они комбинируют логические значения и позволяют записывать сложные условия одной строкой вместо лесенки вложенных `if`.

## Оператор and — «и»

`a and b` истинно, только если **оба** операнда истинны:

| `a` | `b` | `a and b` |
|---|---|---|
| `True` | `True` | `True` |
| `True` | `False` | `False` |
| `False` | `True` | `False` |
| `False` | `False` | `False` |

```python
login_ok = True
password_ok = False
print(login_ok and password_ok)

age = 25
has_ticket = True
print(age >= 18 and has_ticket)
```

```text
False
True
```

`and` — это строгий контролёр: достаточно одного «нет», чтобы весь ответ был «нет».

Вспомните пример со скидкой участника клуба из прошлого урока, где пришлось вкладывать один `if` в другой. С `and` условие становится плоским:

```python
is_member = True
total = 3500
if is_member and total >= 3000:
    print("Скидка 15%")
else:
    print("Без большой скидки")
```

```text
Скидка 15%
```

## Оператор or — «или»

`a or b` истинно, если истинен **хотя бы один** операнд:

| `a` | `b` | `a or b` |
|---|---|---|
| `True` | `True` | `True` |
| `True` | `False` | `True` |
| `False` | `True` | `True` |
| `False` | `False` | `False` |

```python
is_student = False
is_pensioner = True
if is_student or is_pensioner:
    print("Льготный билет")
else:
    print("Полный билет")
```

```text
Льготный билет
```

`or` — снисходительный: достаточно одного «да». Обратите внимание: это **неисключающее** «или» — если истинны оба операнда, результат тоже `True`. Студент-пенсионер тоже получит льготу.

## Оператор not — «не»

`not` переворачивает логическое значение: `not True` — это `False`, и наоборот. У него один операнд:

```python
is_banned = False
print(not is_banned)
if not is_banned:
    print("Пользователь может писать сообщения")
```

```text
True
Пользователь может писать сообщения
```

`not` особенно хорош с хорошо названными переменными: `if not is_valid:` читается как обычная фраза «если не валидно».

## Приоритет операторов

Логические операторы имеют **самый низкий** приоритет — ниже арифметики и сравнений. А между собой: сначала `not`, потом `and`, потом `or`.

Полная иерархия (от высокого к низкому):

1. `**`
2. унарный `-`
3. `* / // %`
4. `+ -`
5. сравнения `== != < > <= >=`
6. `not`
7. `and`
8. `or`

Поэтому выражение `x > 0 and x < 10` работает без скобок: сначала вычисляются оба сравнения, потом `and`.

А вот смешивание `and` и `or` — частый источник ошибок:

```python
is_admin = False
is_owner = True
is_locked = True
print(is_admin or is_owner and not is_locked)
print((is_admin or is_owner) and not is_locked)
```

```text
False
False
```

Здесь оба результата совпали случайно. Поменяем `is_admin` на `True`:

```python
is_admin = True
is_owner = True
is_locked = True
print(is_admin or is_owner and not is_locked)
print((is_admin or is_owner) and not is_locked)
```

```text
True
False
```

Первое выражение читается как `is_admin or (is_owner and not is_locked)` — «админ может всё, а владелец — только если не заблокирован». Второе — «админ или владелец, но только при отсутствии блокировки». Это **разные правила доступа**, и выбор между ними — вопрос логики приложения. Правило инженера: **если в выражении есть и `and`, и `or` — ставьте скобки**, даже если приоритет и так даёт нужный результат.

## Короткое замыкание

Важная особенность `and` и `or`: Python вычисляет операнды **слева направо** и **останавливается**, как только результат известен. Это называется **коротким замыканием** (short-circuit evaluation).

- В `a and b`: если `a` ложно, результат точно `False` — `b` даже не вычисляется.
- В `a or b`: если `a` истинно, результат точно `True` — `b` не вычисляется.

Это не просто оптимизация — на этом построен важный защитный приём:

```python
count = 0
total = 50
if count != 0 and total / count > 10:
    print("Среднее больше 10")
else:
    print("Нет данных или среднее мало")
```

```text
Нет данных или среднее мало
```

Если бы Python вычислял оба операнда, `total / count` упал бы с `ZeroDivisionError`. Но `count != 0` ложно, поэтому деление не выполняется. **Порядок операндов важен**: сначала безопасная проверка, потом рискованная операция. Если поменять их местами — `total / count > 10 and count != 0` — программа упадёт.

Короткое замыкание можно увидеть наглядно, если во втором операнде стоит что-то с побочным эффектом:

```python
print(False and print("этого не будет"))
print(True or print("и этого не будет"))
```

```text
False
True
```

Внутренние `print()` не выполнились — Python не дошёл до них.

## and и or возвращают операнд, а не обязательно bool

Тонкость, которая пригодится в следующем уроке: `and` и `or` возвращают не `True`/`False`, а **один из операндов** — тот, на котором закончилось вычисление.

```python
print(0 or 42)
print("" or "значение по умолчанию")
print(5 and 10)
print(0 and 10)
```

```text
42
значение по умолчанию
10
0
```

С логическими значениями это незаметно: вы получаете `True` или `False`. Но с другими типами `or` превращается в удобный способ подставить значение по умолчанию. Подробно — в уроке про truthy/falsy.

## Законы де Моргана

Иногда условие проще записать «от противного». Две формулы помогают правильно вносить `not` внутрь скобок:

- `not (a and b)` равно `(not a) or (not b)`;
- `not (a or b)` равно `(not a) and (not b)`.

Словами: «неверно, что оба» = «хотя бы один нет»; «неверно, что хотя бы один» = «оба нет».

```python
temp = 45
is_ok = 0 <= temp <= 40
print(not (temp >= 0 and temp <= 40))
print(temp < 0 or temp > 40)
print(not is_ok)
```

```text
True
True
True
```

Все три строки проверяют одно — «температура вне допустимого диапазона». Обычно самая читаемая — вторая: без отрицаний. **Чем меньше `not` в условии, тем легче его понять.**

## Разбор задачи: стоит ли повторять запрос

Вернёмся к API языковой модели. Повторять запрос имеет смысл, если ошибка временная (код 429 — превышен лимит, или 5xx — ошибка сервера) **и** ещё остались попытки:

```python
status = 503
attempt = 2
max_attempts = 3

is_temporary = status == 429 or status >= 500
can_retry = attempt < max_attempts

if 200 <= status < 300:
    print("Успех")
elif is_temporary and can_retry:
    print("Повторяем запрос, попытка", attempt + 1)
else:
    print("Сдаёмся, код", status)
```

```text
Повторяем запрос, попытка 3
```

Обратите внимание на два приёма: сложные условия вынесены в переменные с говорящими именами (`is_temporary`, `can_retry`), а скобки вокруг `or` не нужны, потому что результат сохранён в отдельную переменную. Итоговое условие `is_temporary and can_retry` читается как обычное предложение.

## Частые ошибки

**1. `x == 1 or 2`.** Хотели «x равно 1 или 2», а Python читает это как `(x == 1) or 2`. Число `2` — «истинное» значение, поэтому условие **всегда** истинно. Правильно: `x == 1 or x == 2`.

```python
color = "зелёный"
if color == "красный" or "синий":
    print("Тёплый или холодный цвет")
```

```text
Тёплый или холодный цвет
```

Зелёный цвет прошёл проверку — это баг.

**2. Неполное сравнение.** `if x > 0 and < 10:` — `SyntaxError`. У каждого сравнения два операнда: `x > 0 and x < 10` или `0 < x < 10`.

**3. Смешение `and`/`or` без скобок.** Приоритет `and` выше, результат может не совпасть с замыслом. Ставьте скобки.

**4. Неправильный порядок при коротком замыкании.** Рискованная операция до защитной проверки: `total / count > 10 and count != 0` упадёт при `count = 0`.

**5. Двойные отрицания.** `if not not_found:` — читается с трудом. Переименуйте переменную в `found`.

**6. `&` и `|` вместо `and` и `or`.** В обычных условиях Python это побитовые операции, у них другой приоритет. Исключение — pandas и NumPy, где для массивов используют именно `&` и `|` (с обязательными скобками). Вы встретите это в части 4.

## Где это в AI-инженерии

- **Фильтрация данных.** Оставить для обучения только отзывы на русском длиной от 20 символов с проставленной меткой: `lang == "ru" and len(text) >= 20 and label is not None`. В pandas то же самое пишется как `(df.lang == "ru") & (df.length >= 20)`.
- **Логика повторов.** Как в разборе выше: временная ошибка **и** есть попытки.
- **Guardrails.** Отклонить запрос, если он слишком длинный **или** содержит запрещённые темы **или** похож на prompt injection.
- **Ранняя остановка.** Остановить обучение, если loss не улучшался 5 эпох **или** достигнут лимит времени.
- **Безопасное обращение к данным.** Короткое замыкание защищает от ошибок: `response is not None and response.status == 200` — второе условие проверяется, только если ответ вообще пришёл.
- **Права агентов.** В части 7 вы будете решать, может ли AI-агент выполнить действие: `is_safe_tool or (user_confirmed and not is_destructive)`. Ошибка в скобках здесь — уже вопрос безопасности.

## Итоги урока

- `and` — истинно, только если истинны оба; `or` — если истинен хотя бы один; `not` — переворачивает значение.
- Приоритет: сравнения → `not` → `and` → `or`. Смешиваете `and` и `or` — ставьте скобки.
- Короткое замыкание: вычисление останавливается, когда результат известен; сначала безопасная проверка, потом рискованная.
- `and`/`or` возвращают один из операндов, а не обязательно `bool`.
- `x == 1 or 2` — классическая ошибка; пишите `x == 1 or x == 2`.
