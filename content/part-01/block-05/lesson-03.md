# Кортежи и распаковка

## Неизменяемый список?

**Кортеж** (`tuple`) — упорядоченная коллекция, как список, но **неизменяемая**. Записывается в круглых скобках:

```python
point = (3, 4)
rgb = (255, 128, 0)
record = ("Ада", 36, "Лондон")
print(point[0], rgb[-1], record[1:])
print(len(record), type(record))
```

```text
3 0 (36, 'Лондон')
3 <class 'tuple'>
```

Индексы, срезы, `len`, `in`, перебор в `for`, `count` и `index` — всё как у списка. Но изменить кортеж нельзя:

```python
point = (3, 4)
point[0] = 10
```

Результат — `TypeError: 'tuple' object does not support item assignment`. Нет и методов `append`, `remove`, `sort`.

Зачем нужна «урезанная» версия списка? Именно затем, что она урезанная.

## Зачем кортежи

**1. Записи с фиксированной структурой.** Точка `(x, y)`, цвет `(r, g, b)`, дата `(год, месяц, день)`, запись `("Ада", 36, "Лондон")`. У такой записи фиксированное число полей, и каждое поле имеет свой смысл. Добавить к точке третью координату «случайно» — ошибка, и кортеж её не допустит.

Отсюда негласное правило:

- **список** — однородная коллекция переменной длины: «оценки всех студентов», «сообщения диалога»;
- **кортеж** — запись фиксированной длины, поля которой могут быть разных типов: «имя, возраст, город».

**2. Безопасность.** Кортеж можно передать куда угодно и быть уверенным, что его не изменят. Это защищает от целого класса ошибок «кто-то поменял мои данные».

**3. Ключи словарей и элементы множеств.** Словари и множества (уроки 4–5) требуют неизменяемых ключей. Кортеж `(55.75, 37.62)` может быть ключом словаря, а список `[55.75, 37.62]` — нет.

**4. Возврат нескольких значений из функции.** Функция возвращает один объект, и если нужно вернуть два значения, возвращают кортеж. Вы уже встречали это: `divmod(17, 5)` возвращает `(3, 2)`.

**5. Скорость и память.** Кортежи чуть компактнее и быстрее создаются — мелочь, но приятная.

## Создание кортежей

На самом деле кортеж создают **запятые**, а не скобки. Скобки лишь группируют:

```python
a = 1, 2, 3
b = (1, 2, 3)
print(a == b, type(a))
```

```text
True <class 'tuple'>
```

Отсюда главная ловушка — кортеж из одного элемента:

```python
not_tuple = (42)
one = (42,)
also_one = 42,
print(type(not_tuple), type(one), type(also_one))
print(len(one))
```

```text
<class 'int'> <class 'tuple'> <class 'tuple'>
1
```

`(42)` — просто число в скобках (как `(2 + 3)`). Кортеж из одного элемента требует **запятой**: `(42,)`. Пустой кортеж — `()`. Кортеж из любой последовательности — `tuple(...)`:

```python
print(tuple("abc"), tuple([1, 2]), tuple(range(3)))
```

```text
('a', 'b', 'c') (1, 2) (0, 1, 2)
```

## Распаковка

**Распаковка** — присваивание элементов последовательности сразу нескольким переменным. Вы уже пользовались ею: `a, b = 1, 2` и обмен `a, b = b, a`. Теперь понятно, что происходит: справа создаётся кортеж, слева он раскладывается по именам.

```python
record = ("Ада", 36, "Лондон")
name, age, city = record
print(f"{name}, {age} лет, {city}")
```

```text
Ада, 36 лет, Лондон
```

Распаковывать можно любую последовательность: список, строку, результат `split()`:

```python
year, month, day = "2026-10-17".split("-")
print(day, month, year)
first, second = "ок"
print(first, second)
```

```text
17 10 2026
о к
```

Количество переменных должно **совпадать** с количеством элементов:

```python
a, b = (1, 2, 3)
```

Результат — `ValueError: too many values to unpack (expected 2)`. А при нехватке — `not enough values to unpack`. Эта ошибка часто появляется при разборе строк неожиданного формата: например, `key, value = line.split("=")` упадёт на строке без `=` или с двумя `=`.

### Звёздочка: собрать остаток

Если элементов больше, чем переменных, лишние можно собрать в список с помощью `*`:

```python
first, *rest = [10, 20, 30, 40]
print(first, rest)
*init, last = [10, 20, 30, 40]
print(init, last)
head, *middle, tail = "abcde"
print(head, middle, tail)
a, *empty, b = (1, 2)
print(empty)
```

```text
10 [20, 30, 40]
[10, 20, 30] 40
a ['b', 'c', 'd'] e
[]
```

Переменная со звёздочкой всегда становится **списком** (возможно, пустым). Звёздочка может быть только одна.

### Подчёркивание: значение не нужно

По соглашению ненужные значения распаковывают в `_`:

```python
name, _, city = ("Ада", 36, "Лондон")
print(name, city)
_, *scores = "Ада 5 4 5".split()
print(scores)
```

```text
Ада Лондон
['5', '4', '5']
```

### Вложенная распаковка

Структура слева может повторять вложенность справа:

```python
person = ("Ада", (1815, 12, 10))
name, (year, month, day) = person
print(name, year)
```

```text
Ада 1815
```

## Распаковка в циклах

Самое частое применение — перебор списка пар или записей:

```python
students = [("Ада", 95), ("Алан", 88), ("Грейс", 91)]
for name, score in students:
    print(f"{name:<6} {score}")
```

```text
Ада    95
Алан   88
Грейс  91
```

`for name, score in students` распаковывает каждый кортеж на две переменные. Сравните с `for item in students: print(item[0], item[1])` — индексы `[0]` и `[1]` ничего не говорят читателю, а имена `name` и `score` говорят всё.

Именно это происходит в `for i, x in enumerate(...)` и `for a, b in zip(...)` из прошлого урока: `enumerate` и `zip` выдают кортежи, а цикл их распаковывает.

## Сравнение кортежей

Кортежи сравниваются **лексикографически**, как строки: сначала первые элементы, при равенстве — вторые, и так далее:

```python
print((1, 2) < (1, 3))
print((2, 0) > (1, 99))
print(("Москва", 25) < ("Москва", 30))
```

```text
True
True
True
```

Это делает кортежи удобным ключом сортировки по нескольким признакам: отсортировать записи по городу, а внутри города — по возрасту, можно, просто составив кортежи в нужном порядке полей:

```python
people = [("Ада", 36, "Лондон"), ("Алан", 41, "Лондон"), ("Грейс", 85, "Нью-Йорк"), ("Билл", 30, "Лондон")]
rows = []
for name, age, city in people:
    rows.append((city, age, name))
for city, age, name in sorted(rows):
    print(city, age, name)
```

```text
Лондон 30 Билл
Лондон 36 Ада
Лондон 41 Алан
Нью-Йорк 85 Грейс
```

## Изменяемое внутри неизменяемого

Неизменяемость кортежа «поверхностная»: кортеж нельзя изменить — заменить или удалить его элементы. Но если элемент сам изменяем (например, список), то менять **его содержимое** можно:

```python
team = ("Команда A", ["Ада", "Алан"])
team[1].append("Грейс")
print(team)
```

```text
('Команда A', ['Ада', 'Алан', 'Грейс'])
```

Кортеж по-прежнему хранит ссылку на тот же список — ссылка не поменялась, поменялся список. Такой кортеж, кстати, нельзя использовать как ключ словаря: Python потребует, чтобы все элементы были неизменяемы.

## Разбор задачи: формы тензоров

В PyTorch и NumPy размерность массива данных — **форма** (shape) — это кортеж. Например, батч из 32 цветных картинок 224×224 имеет форму `(32, 3, 224, 224)`: батч, каналы, высота, ширина. С формами постоянно работают через распаковку:

```python
shape = (32, 3, 224, 224)
batch_size, channels, height, width = shape
print(f"Батч: {batch_size}, каналов: {channels}, размер: {height}×{width}")
total = 1
for dim in shape:
    total *= dim
print("Чисел в тензоре:", f"{total:,}")
print("Размерностей:", len(shape))
batch, *rest = shape
print("Форма одного примера:", tuple(rest))
```

```text
Батч: 32, каналов: 3, размер: 224×224
Чисел в тензоре: 4,816,896
Размерностей: 4
Форма одного примера: (3, 224, 224)
```

Почти 5 миллионов чисел в одном батче — отсюда требования к видеопамяти. Ошибка «shapes cannot be multiplied» в нейросетях — это несовпадение именно таких кортежей.

## Попробуйте сами

- Создайте кортеж из одного элемента тремя способами и проверьте `type()` каждого.
- Распакуйте строку `"Иванов Иван Иванович"` в три переменные, а затем — в фамилию и список остальных частей.
- Отсортируйте список кортежей `(оценка, имя)` по убыванию оценки, а при равенстве — по имени.

## Частые ошибки

**1. `(42)` вместо `(42,)`.** Без запятой это не кортеж, а число.

**2. Изменение кортежа.** `t[0] = 1` → `TypeError`. Нужна изменяемая версия — превратите в список: `list(t)`.

**3. Несовпадение числа переменных при распаковке.** `ValueError: too many values to unpack`. Проверяйте формат данных или используйте `*rest`.

**4. Две звёздочки в распаковке.** `*a, *b = ...` — `SyntaxError`: Python не может решить, как разделить элементы.

**5. Индексы вместо распаковки.** `item[0]`, `item[1]` в цикле — нечитаемо. Распаковывайте в говорящие имена.

**6. Считать кортеж со списком внутри полностью неизменяемым.** Вложенный список можно изменить.

## Где это в AI-инженерии

- **Формы тензоров.** `x.shape` в NumPy и PyTorch — кортеж. `batch_size, seq_len, hidden = x.shape` — строка, которую вы будете писать постоянно.
- **Пары (признаки, метка).** Датасет PyTorch возвращает пример как кортеж `(input, target)`, а цикл обучения распаковывает батч: `for inputs, targets in dataloader:`.
- **Несколько результатов функции.** `loss, accuracy = evaluate(model, data)`; `X_train, X_test, y_train, y_test = train_test_split(X, y)` в scikit-learn — распаковка кортежа из четырёх элементов.
- **Ключи кэша.** Ответы LLM кэшируют по ключу-кортежу `(model, prompt, temperature)` — список ключом быть не может.
- **Сортировка по нескольким признакам.** Ранжирование результатов поиска по `(релевантность, свежесть)` — сравнение кортежей.
- **Неизменяемые конфигурации.** Гиперпараметры, которые не должны меняться во время эксперимента, удобно хранить в кортежах и неизменяемых структурах (`NamedTuple`, `frozen dataclass` в части 2).

## Итоги урока

- Кортеж — упорядоченная неизменяемая коллекция; создаётся запятыми, `(x,)` — кортеж из одного элемента.
- Список — для однородных наборов переменной длины, кортеж — для записей фиксированной структуры.
- Распаковка: `a, b, c = seq`; `first, *rest = seq`; `_` — для ненужных значений; работает в циклах.
- Кортежи сравниваются поэлементно — удобный ключ сортировки по нескольким признакам.
- Кортежи могут быть ключами словарей, если все их элементы неизменяемы.
