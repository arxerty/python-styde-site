# Обработка текста — основа NLP

## Что такое NLP и зачем чистить текст

**NLP** (Natural Language Processing, обработка естественного языка) — область, которая учит компьютеры работать с человеческим текстом: классифицировать отзывы, переводить, отвечать на вопросы, извлекать факты. Языковые модели вроде GPT — вершина NLP, но фундамент у всех методов общий: текст нужно **разобрать на части** и **привести к единому виду**.

Почему это важно? Для компьютера `"Модель"`, `"модель"`, `"модель,"` и `"модель!"` — четыре разные строки. Если считать частоту слов без подготовки, одно и то же слово разобьётся на четыре счётчика, а статистика окажется мусорной. Классическое правило данных: **мусор на входе — мусор на выходе** (garbage in, garbage out).

В этом уроке вы соберёте из инструментов прошлых уроков простой **конвейер обработки текста** (pipeline):

1. нормализация — регистр, пробелы, невидимые символы;
2. токенизация — разбиение на слова;
3. очистка токенов — удаление знаков препинания;
4. фильтрация — удаление стоп-слов;
5. анализ — подсчёты и статистика.

## Шаг 1. Нормализация

Приводим текст к нижнему регистру и схлопываем пробелы:

```python
raw = "  Машинное   обучение — это ОБУЧЕНИЕ на данных!  "
text = " ".join(raw.lower().split())
print(f"[{text}]")
```

```text
[машинное обучение — это обучение на данных!]
```

Приведение к нижнему регистру — компромисс. Мы теряем информацию («Apple» компания и «apple» фрукт сольются), зато считаем «Обучение» и «обучение» одним словом. Для подсчёта статистик это почти всегда правильный выбор. А вот современные языковые модели получают текст **без** такой нормализации: регистр несёт смысл, и модель сама с ним разбирается.

## Шаг 2. Токенизация

**Токен** — минимальная единица текста, с которой работает алгоритм. Самый простой токенизатор — разбиение по пробелам:

```python
text = "машинное обучение — это обучение на данных!"
tokens = text.split()
print(tokens)
print(len(tokens))
```

```text
['машинное', 'обучение', '—', 'это', 'обучение', 'на', 'данных!']
7
```

Видны проблемы: тире стало отдельным «словом», а восклицательный знак прилип к слову `данных!`. Их решает следующий шаг.

> Токенизаторы настоящих языковых моделей устроены иначе: они режут текст не на слова, а на **подслова** (subword) — частые куски слов. «обучение» может стать токенами `об`, `уч`, `ение`. Это позволяет модели работать с любыми, даже невиданными словами. Подробно об алгоритме BPE — в блоке 6.5.

## Шаг 3. Очистка токенов от пунктуации

Знаки препинания чаще всего прилипают к краям слов. `strip()` с набором символов снимает их с обоих концов, не трогая середину (дефис в «из-за» сохранится):

```python
punctuation = ".,!?;:—–-«»\"'()…"
tokens = ["машинное", "обучение", "—", "это", "«обучение»,", "на", "данных!", "из-за"]
clean = []
for token in tokens:
    word = token.strip(punctuation)
    if word:
        clean.append(word)
print(clean)
```

```text
['машинное', 'обучение', 'это', 'обучение', 'на', 'данных', 'из-за']
```

Тире превратилось в пустую строку и было отброшено проверкой `if word:`. Метод `append()` добавляет элемент в конец списка — подробно о списках в следующем блоке; пока достаточно знать, что `clean = []` создаёт пустой список, а `clean.append(x)` дописывает в него `x`.

## Шаг 4. Стоп-слова

**Стоп-слова** — частые служебные слова, которые почти не несут смысла для анализа темы: предлоги, союзы, частицы, местоимения («и», «в», «на», «это», «что»). При подсчёте «о чём текст» их отбрасывают — иначе в топе частых слов всегда будут «и» и «в».

```python
stop_words = " и в во на с со по к о об от до за из что это как а но не "
words = ["машинное", "обучение", "это", "обучение", "на", "данных"]
meaningful = []
for word in words:
    if f" {word} " not in stop_words:
        meaningful.append(word)
print(meaningful)
```

```text
['машинное', 'обучение', 'обучение', 'данных']
```

Обратите внимание на приём: стоп-слова хранятся в одной строке через пробелы, а проверяем мы `" слово "` **с пробелами по краям**. Без них проверка `"на" in stop_words` нашла бы «на» внутри других слов. В следующем блоке вы узнаете **множества** (`set`) — правильную структуру для таких проверок, которая работает мгновенно для тысяч стоп-слов.

## Шаг 5. Анализ: подсчёты

### Сколько раз встречается слово

```python
words = ["машинное", "обучение", "обучение", "данных", "обучение"]
target = "обучение"
count = 0
for word in words:
    if word == target:
        count += 1
print(f"«{target}»: {count}")
```

```text
«обучение»: 3
```

### Уникальные слова

Чтобы найти все различные слова, накапливаем их, пропуская уже встреченные:

```python
words = ["кот", "и", "пёс", "и", "кот"]
unique = []
for word in words:
    if word not in unique:
        unique.append(word)
print(unique, len(unique))
```

```text
['кот', 'и', 'пёс'] 3
```

Отношение числа уникальных слов к общему числу слов — **лексическое разнообразие** (type-token ratio). У детской книжки оно низкое, у научной статьи — высокое.

### Частота каждого слова

Комбинируем: для каждого уникального слова считаем вхождения — вложенные циклы:

```python
words = "кот видит кота кот спит кот".split()
unique = []
for word in words:
    if word not in unique:
        unique.append(word)
best_word = ""
best_count = 0
for candidate in unique:
    count = 0
    for word in words:
        if word == candidate:
            count += 1
    print(candidate, count)
    if count > best_count:
        best_word = candidate
        best_count = count
print("Самое частое:", best_word, best_count)
```

```text
кот 3
видит 1
кота 1
спит 1
Самое частое: кот 3
```

Это работает, но медленно: для текста из n слов с m уникальными — n × m сравнений. Для книги в 100 000 слов это сотни миллионов операций. В следующем блоке **словарь** (`dict`) решит задачу за один проход, а в части 2 — `collections.Counter` одной строкой. Но понимать, что делается «внутри», важно уже сейчас.

Заметьте ещё одну проблему: «кот» и «кота» посчитаны как разные слова. Приведение слов к начальной форме называется **лемматизацией** (кота → кот, обучения → обучение). Для русского языка с его богатой морфологией это особенно важно; для этого есть библиотеки вроде pymorphy3.

## Предложения

Разбить текст на предложения можно, заменив `!` и `?` на точку и разрезав по точке:

```python
text = "Модели учатся на данных. Данные бывают грязными! Что делать? Чистить."
unified = text.replace("!", ".").replace("?", ".")
sentences = []
for part in unified.split("."):
    sentence = part.strip()
    if sentence:
        sentences.append(sentence)
for sentence in sentences:
    print(len(sentence.split()), "|", sentence)
print("Предложений:", len(sentences))
```

```text
4 | Модели учатся на данных
3 | Данные бывают грязными
2 | Что делать
1 | Чистить
Предложений: 4
```

Наивный подход ломается на сокращениях («т.е.», «г. Москва», «3.14») — настоящие сегментаторы предложений учитывают такие случаи. Но для анализа «средней длины предложения» простого способа часто достаточно.

## N-граммы

**N-грамма** — последовательность из n подряд идущих слов. Биграммы (пары) и триграммы показывают устойчивые сочетания: «машинное обучение», «нейронная сеть». На n-граммах были построены первые статистические языковые модели: вероятность следующего слова оценивалась по частоте n-грамм в корпусе.

```python
words = "я люблю машинное обучение".split()
for i in range(len(words) - 1):
    print(words[i], words[i + 1])
```

```text
я люблю
люблю машинное
машинное обучение
```

`range(len(words) - 1)` — чтобы `words[i + 1]` не вышел за границу (тот же приём, что для соседних символов в уроке 4).

## Собираем конвейер

```python
raw = "Нейросети учатся на ДАННЫХ. Данные — это всё! Без данных нет нейросетей."
punctuation = ".,!?;:—–-«»\"'()…"
stop_words = " и в на с по к о от до за из что это как а но не нет без всё "

text = " ".join(raw.lower().split())
words = []
for token in text.split():
    word = token.strip(punctuation)
    if word and f" {word} " not in stop_words:
        words.append(word)
print("Слова:", words)
print(f"Всего значимых слов: {len(words)}")
```

```text
Слова: ['нейросети', 'учатся', 'данных', 'данные', 'данных', 'нейросетей']
Всего значимых слов: 6
```

Конвейер из пяти строк превратил шумный текст в аккуратный список значимых слов. Именно с таких конвейеров начинается классическое NLP: следующими шагами были бы лемматизация, подсчёт частот и превращение текста в вектор чисел для модели (bag-of-words, TF-IDF — часть 5).

## Частые ошибки

**1. Подсчёт без нормализации.** «Данные», «данные» и «данные,» окажутся разными словами.

**2. Проверка стоп-слов подстрокой без границ.** `"на" in "она пошла"` — `True`. Нужны пробелы-границы или множество.

**3. Удаление пунктуации `replace` внутри слов.** `"из-за".replace("-", "")` даст «изза». Снимайте пунктуацию с краёв через `strip`.

**4. Пустые токены.** После очистки тире или многоточие превращаются в `""` — их надо отбрасывать.

**5. Наивное деление на предложения.** «Т.е.» и «3.14» разрежутся неправильно — учитывайте это при интерпретации.

**6. Квадратичный подсчёт частот на больших текстах.** Для реальных данных используйте словари и `Counter`.

## Где это в AI-инженерии

- **Классическое NLP.** Классификаторы спама и тональности на основе bag-of-words и TF-IDF (часть 5) требуют ровно такой предобработки: нормализация, токенизация, стоп-слова, частоты.
- **Подготовка данных для LLM.** Языковым моделям не нужна лемматизация, но нужна очистка: удаление дубликатов, мусорных символов, HTML-разметки, слишком коротких текстов.
- **RAG и поиск.** Ключевой (лексический) поиск BM25 (блок 7.4) работает именно со словами после нормализации, а гибридный поиск сочетает его с векторным.
- **Эвалы.** Метрики сравнения ответа модели с эталоном нормализуют оба текста: регистр, пунктуация, лишние пробелы — иначе правильный ответ «Париж.» не совпадёт с «париж».
- **Анализ данных.** Перед обучением модели изучают корпус: длины текстов, частые слова, дубликаты. Это первый шаг EDA для текстовых данных.
- **Понимание токенизации.** Разница между «словами» и «токенами» объясняет стоимость и ограничения LLM: лимиты контекста считаются в токенах, а не в словах.

## Итоги урока

- Конвейер обработки текста: нормализация → токенизация → очистка → фильтрация → анализ.
- `lower()` + `" ".join(text.split())` — нормализация; `token.strip(punctuation)` — очистка краёв слова.
- Стоп-слова отбрасывают служебные слова; проверяйте вхождение с границами.
- Частоты, уникальные слова, предложения и n-граммы строятся из циклов и накопителей.
- Наивные методы медленные и ломаются на сложных случаях — словари, множества и специализированные библиотеки решают это в следующих блоках.
