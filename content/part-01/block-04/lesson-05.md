# Unicode, кодировки, ord и chr

## Компьютер не знает букв

Внутри компьютера нет букв — только числа. Чтобы хранить текст, каждому символу ставят в соответствие **число** (код). Слово «Да» для компьютера — последовательность двух чисел. Договорённость о том, какое число означает какой символ, называется **набором символов**, а способ записать эти числа в байты — **кодировкой**.

Понимание этой кухни избавит вас от целого класса загадочных ошибок: «кракозябр» вместо русского текста, `UnicodeDecodeError` при чтении файла, странной длины строк с эмодзи. А для AI-инженера это ещё и ключ к пониманию токенизаторов языковых моделей.

## ord и chr

Функция `ord()` возвращает код символа, `chr()` — символ по коду:

```python
print(ord("A"), ord("a"), ord("0"), ord(" "))
print(ord("Я"), ord("я"), ord("ё"))
print(chr(65), chr(1071), chr(128013))
```

```text
65 97 48 32
1071 1103 1105
A Я 🐍
```

Коды букв одного алфавита идут подряд, поэтому с ними можно делать арифметику:

```python
print(chr(ord("a") + 1))
print(ord("z") - ord("a") + 1)
print(ord("я") - ord("а") + 1)
```

```text
b
26
32
```

Последняя строка — ловушка: в русском алфавите 33 буквы, а получилось 32. Буква `ё` (1105) стоит **отдельно**, после `я` (1103). Это наследие истории кодировок, и оно ломает «наивную» сортировку русских слов и алгоритмы, полагающиеся на непрерывность алфавита.

### Пример: шифр Цезаря

Классический шифр: каждая буква сдвигается на фиксированное число позиций по алфавиту, с «заворачиванием» в начало.

```python
text = "hello, world"
shift = 3
result = ""
for char in text:
    if "a" <= char <= "z":
        offset = (ord(char) - ord("a") + shift) % 26
        result += chr(ord("a") + offset)
    else:
        result += char
print(result)
```

```text
khoor, zruog
```

Разберём формулу для `z` со сдвигом 3: `ord("z") - ord("a")` = 25 (номер буквы в алфавите с нуля), `+ 3` = 28, `% 26` = 2 (заворачиваем), `chr(ord("a") + 2)` = `c`. Остаток от деления делает алфавит «кольцом». Знаки препинания и пробелы не трогаем.

## Как мы к этому пришли: от ASCII к Unicode

**ASCII** (1963) — первая массовая таблица: 128 символов (коды 0–127), латиница, цифры, знаки препинания, управляющие символы вроде перевода строки. Каждый символ — один байт. Кириллице места не нашлось.

Затем появились **национальные кодировки**: для русского — KOI8-R, CP866 (DOS), **CP1251** (Windows). Они использовали коды 128–255 для своих букв. Проблема: один и тот же байт означал разные символы в разных кодировках. Открыли файл не в той кодировке — получили «кракозябры».

**Unicode** (1991) решил проблему радикально: **одна таблица для всех символов всех письменностей**. Сегодня в ней около 150 тысяч символов: все алфавиты, иероглифы, математические знаки, эмодзи. Номер символа в Unicode называется **кодовой точкой** (code point) и записывается как `U+0041` (это `A`). Функция `ord()` возвращает именно кодовую точку.

В Python 3 строки (`str`) — это последовательности кодовых точек Unicode. Поэтому `len("Привет")` = 6, а `"東京"[0]` = `東`: Python работает с символами, а не с байтами.

```python
print("AБ中")
print(len("東京"), "東京"[1])
```

```text
AБ中
2 京
```

Запись `\uXXXX` — способ вставить символ по шестнадцатеричному коду.

## Кодировки: как символы становятся байтами

Unicode говорит, **какой номер** у символа. Но в файл и в сеть пишутся **байты** (числа 0–255). Правило превращения кодовых точек в байты — это **кодировка**. Самая важная — **UTF-8**:

| Символы | Байт на символ в UTF-8 |
|---|---|
| ASCII: латиница, цифры | 1 |
| кириллица, греческий, арабский | 2 |
| иероглифы, большинство других | 3 |
| эмодзи и редкие символы | 4 |

UTF-8 совместима с ASCII (английский текст в ASCII и UTF-8 — одни и те же байты), экономна для латиницы и умеет кодировать любой символ. Сегодня это стандарт де-факто: веб, Linux, JSON, Python-исходники, API языковых моделей.

### str и bytes

В Python есть отдельный тип для байтов — `bytes`. Превращение строки в байты — `encode()`, обратно — `decode()`:

```python
text = "Привет, AI"
data = text.encode("utf-8")
print(data)
print(type(data))
print(len(text), len(data))
print(data.decode("utf-8"))
```

```text
b'\xd0\x9f\xd1\x80\xd0\xb8\xd0\xb2\xd0\xb5\xd1\x82, AI'
<class 'bytes'>
10 16
Привет, AI
```

Литерал байтов начинается с `b`. Шесть кириллических букв заняли по 2 байта (12), запятая, пробел и `AI` — по одному (4): итого 16 байт при 10 символах. Отсюда важный практический вывод: **длина строки в символах и размер в байтах — разные вещи**. Лимиты API, размеры полей в базах данных и сетевых пакетов часто считаются в байтах.

```python
for s in ["AI", "ИИ", "人工", "🤖"]:
    print(s, len(s), len(s.encode("utf-8")))
```

```text
AI 2 2
ИИ 2 4
人工 2 6
🤖 1 4
```

### Ошибки кодировок

Если декодировать байты не той кодировкой, получится мусор или ошибка:

```python
data = "Привет".encode("utf-8")
print(data.decode("cp1251"))
```

```text
РџСЂРёРІРµС‚
```

Это и есть «кракозябры» (по-английски — mojibake): байты UTF-8 прочитаны как CP1251. Если вы видите в тексте `Р` и `С` через букву — почти наверняка проблема именно такая.

Бывает и наоборот — байты не являются корректным UTF-8, и Python не может их прочитать:

```python
data = "Привет".encode("cp1251")
print(data.decode("utf-8"))
```

Результат — `UnicodeDecodeError: 'utf-8' codec can't decode byte 0xcf...`. Это значит: файл был сохранён в другой кодировке (часто в старой Windows-кодировке CP1251). Решение — указать правильную кодировку: `data.decode("cp1251")`.

Чтобы не падать на повреждённых данных, у `decode` есть параметр `errors`:

```python
data = b"OK \xff\xfe end"
print(data.decode("utf-8", errors="replace"))
print(data.decode("utf-8", errors="ignore"))
```

```text
OK �� end
OK  end
```

`replace` заменяет плохие байты символом `�`, `ignore` — выбрасывает. Это компромисс: данные частично теряются, зато обработка не останавливается.

> **Правило:** при работе с файлами всегда указывайте кодировку явно: `open(path, encoding="utf-8")` (блок 1.7). На Windows кодировка по умолчанию может оказаться CP1251, и один и тот же код будет вести себя по-разному на разных компьютерах.

## Коварные символы

### Невидимые символы

В тексте из интернета, PDF и Word встречаются символы, которые не видны, но мешают обработке:

- ` ` — неразрывный пробел (выглядит как пробел, но `" " == " "` — `False`);
- `​` — пробел нулевой ширины (совсем невидим);
- `﻿` — BOM, служебная метка в начале некоторых файлов.

```python
word = "Hello​World"
print(word)
print(len(word))
print(word == "HelloWorld")
print(word.replace("​", "") == "HelloWorld")
```

```text
Hello​World
11
False
True
```

Слово выглядит как `HelloWorld`, но длина 11 и сравнение не проходит. Такие символы ломают поиск, подсчёт слов и даже работу токенизаторов — поэтому при очистке текста их удаляют.

### Эмодзи из нескольких кодовых точек

Некоторые эмодзи состоят из нескольких кодовых точек, склеенных специальным символом:

```python
family = "👨‍👩‍👧"
print(len(family))
flag = "🇷🇺"
print(len(flag))
```

```text
5
2
```

Пользователь видит один символ, а Python считает 5 и 2. Срез посередине такого эмодзи «сломает» его. Для большинства задач это неважно, но при обрезке текста под лимит длины стоит помнить.

## Разбор задачи: насколько «дорог» текст на разных языках

Посчитаем, сколько байт в UTF-8 занимает в среднем один символ текста на разных языках:

```python
texts = ["Machine learning", "Машинное обучение", "機械学習"]
for text in texts:
    size = len(text.encode("utf-8"))
    print(f"{text:<20} символов: {len(text):>2}  байт: {size:>2}  байт/символ: {size / len(text):.2f}")
```

```text
Machine learning     символов: 16  байт: 16  байт/символ: 1.00
Машинное обучение    символов: 17  байт: 33  байт/символ: 1.94
機械学習                 символов:  4  байт: 12  байт/символ: 3.00
```

(Иероглифы в моноширинном шрифте занимают по две позиции, поэтому столбцы «съезжают» — ещё одна особенность Unicode.)

Это напрямую связано с ценой работы с LLM. Современные токенизаторы работают на уровне **байтов** UTF-8 (byte-level BPE): частые последовательности байтов объединяются в токены. Английский текст в обучающих данных встречался чаще всего, поэтому английские слова обычно становятся одним-двумя токенами. Русский текст требует больше байтов и реже встречался — в итоге тот же смысл на русском часто стоит в 1,5–3 раза больше токенов. Подробно — в блоке 7.1.

## Частые ошибки

**1. Путать символы и байты.** `len(text)` — символы, `len(text.encode("utf-8"))` — байты. Лимиты в байтах при кириллице заканчиваются вдвое быстрее.

**2. Не указывать кодировку.** `open(path)` и `.decode()` без кодировки зависят от системы. Пишите `encoding="utf-8"` явно.

**3. Декодировать не той кодировкой.** Кракозябры `РџСЂРёРІРµС‚` — признак UTF-8, прочитанного как CP1251.

**4. Забывать про `ё`.** Она стоит вне диапазона `а`–`я`: проверка `"а" <= c <= "я"` её не пропустит.

**5. Невидимые символы.** Строки «одинаковые на вид» не равны — ищите ` `, `​`, `﻿`.

**6. Резать эмодзи и составные символы срезом.** Срез по индексу может разрезать символ, состоящий из нескольких кодовых точек.

## Где это в AI-инженерии

- **Токенизация.** Токенизаторы GPT-подобных моделей работают с байтами UTF-8. Это объясняет, почему эмодзи и редкие символы «съедают» много токенов, а русский текст дороже английского.
- **Очистка датасетов.** Невидимые символы, BOM, разные виды пробелов и кавычек нормализуют перед обучением — иначе одинаковые тексты выглядят для модели по-разному.
- **Нормализация Unicode.** Одна и та же буква может быть записана разными кодовыми точками (например, `é` как один символ или как `e` + знак ударения). Модуль `unicodedata` и форма нормализации NFKC приводят их к единому виду — так делают многие токенизаторы.
- **Чтение данных.** `UnicodeDecodeError` при загрузке CSV — ежедневная проблема при работе с данными из разных источников. Знание кодировок превращает её из загадки в двухминутную починку.
- **Лимиты API.** Размер запроса, длина полей и метаданных в векторных базах иногда ограничены в байтах — кириллица занимает вдвое больше.

## Итоги урока

- Символы — это числа: `ord(символ)` → код, `chr(код)` → символ; Unicode — единая таблица для всех письменностей.
- `str` — последовательность символов Unicode, `bytes` — последовательность байтов; `encode`/`decode` переводят между ними.
- UTF-8: латиница — 1 байт, кириллица — 2, иероглифы — 3, эмодзи — 4.
- Неверная кодировка даёт кракозябры или `UnicodeDecodeError`; указывайте кодировку явно.
- Невидимые символы и составные эмодзи — частые источники странных ошибок.
