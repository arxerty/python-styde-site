# break, continue и else у цикла

## Управление ходом цикла

Обычный цикл работает «от начала до конца»: `for` перебирает все элементы, `while` крутится, пока условие истинно. Но часто нужно вмешаться в этот ход:

- **досрочно выйти**, когда цель достигнута: нашли нужный элемент, запрос к API наконец прошёл успешно, модель перестала улучшаться;
- **пропустить** текущую итерацию: строка данных повреждена, отзыв слишком короткий, число отрицательное.

Для этого есть две инструкции: **`break`** и **`continue`**. А ещё у циклов в Python есть редкая для других языков возможность — ветка **`else`**.

## break — досрочный выход

`break` немедленно **прекращает весь цикл**. Оставшиеся итерации не выполняются, управление переходит к первой инструкции после цикла.

```python
for number in range(1, 100):
    if number * number > 50:
        print("Первое число, квадрат которого больше 50:", number)
        break
print("Цикл окончен")
```

```text
Первое число, квадрат которого больше 50: 8
Цикл окончен
```

Цикл мог бы перебрать 99 чисел, но остановился на восьмом: дальше искать незачем.

### while True + break

Самое частое применение `break` — выход из намеренно бесконечного цикла. Это удобно, когда условие выхода естественно проверять **в середине** тела, а не в заголовке:

```python
total = 0
while True:
    text = input("Число или «стоп»: ")
    if text == "стоп":
        break
    total += int(text)
print("Сумма:", total)
```

Сравните с шаблоном «чтение с опережением» из первого урока: здесь `input()` написан один раз, а не дважды. Многие считают такой вариант более читаемым. Главное правило для `while True`: **внутри обязательно должен быть достижимый `break`**, иначе цикл действительно никогда не закончится.

## continue — переход к следующей итерации

`continue` прерывает **только текущую итерацию**: остаток тела пропускается, и цикл сразу переходит к следующему элементу (в `while` — к проверке условия).

```python
for number in range(1, 11):
    if number % 3 == 0:
        continue
    print(number, end=" ")
print()
```

```text
1 2 4 5 7 8 10 
```

Числа, кратные трём, пропущены: для них `print` не выполнился.

`continue` полезен как **фильтр в начале тела**: сначала отсеиваем неподходящие данные, а основной код пишем без лишней вложенности.

```python
readings = "12 -5 30 abc 7"
total = 0
for item in readings.split():
    if not item.lstrip("-").isdigit():
        print("Пропускаю мусор:", item)
        continue
    value = int(item)
    if value < 0:
        print("Пропускаю отрицательное:", value)
        continue
    total += value
print("Сумма корректных:", total)
```

```text
Пропускаю отрицательное: -5
Пропускаю мусор: abc
Сумма корректных: 49
```

(Методы `split()`, `lstrip()` и `isdigit()` вы подробно изучите в блоке про строки. Здесь важна структура: проверки с `continue` — в начале, полезная работа — в конце, без вложенных `if`.)

Сравните с вариантом без `continue`:

```python
values = "12 -5 30 7"
total = 0
for item in values.split():
    value = int(item)
    if value >= 0:
        total += value
print(total)
```

```text
49
```

Для одной проверки оба варианта хороши. Но когда проверок три-четыре, `continue` спасает от «лесенки» из вложенных условий.

### Ловушка: continue в while

В `while` `continue` перепрыгивает **всё**, что ниже, — включая изменение счётчика:

```python norun
i = 0
while i < 10:
    if i == 5:
        continue      # i больше никогда не изменится — бесконечный цикл!
    print(i)
    i += 1
```

Когда `i` станет 5, `continue` будет пропускать `i += 1` снова и снова. Решение — менять счётчик **до** `continue` или использовать `for`, где переход к следующему элементу происходит автоматически.

## else у цикла

У `for` и `while` в Python может быть ветка `else`. Она выполняется, если цикл завершился **естественно** — то есть **не через `break`**.

```python
target = 7
for number in [3, 9, 4]:
    if number == target:
        print("Нашли", target)
        break
else:
    print(target, "не найдено")
```

```text
7 не найдено
```

(Квадратные скобки `[3, 9, 4]` — это список, о них подробно в блоке 1.5. Здесь важно, что `for` перебирает его элементы.)

Как читать конструкцию `for … else`: «перебери элементы; если ни разу не сработал `break` — выполни `else`». Многие предлагают мысленно называть эту ветку `nobreak`.

Это идеальный инструмент для **поиска**: `break` — «нашли», `else` — «перебрали всё и не нашли». Без `else` пришлось бы заводить флаг:

```python
target = 9
found = False
for number in [3, 9, 4]:
    if number == target:
        found = True
        break
if found:
    print("Нашли", target)
else:
    print(target, "не найдено")
```

```text
Нашли 9
```

Флаг тоже рабочий вариант, и многие команды предпочитают его, потому что `for … else` малоизвестен. Выбирайте то, что понятнее вашей команде, но уметь читать `for … else` нужно обязательно — он встречается в чужом коде.

### else у while

С `while` логика та же: `else` выполняется, когда условие стало ложным, но не после `break`.

```python
attempt = 1
max_attempts = 3
while attempt <= max_attempts:
    print("Попытка", attempt, "— ошибка 503")
    attempt += 1
else:
    print("Все попытки исчерпаны")
```

```text
Попытка 1 — ошибка 503
Попытка 2 — ошибка 503
Попытка 3 — ошибка 503
Все попытки исчерпаны
```

Если бы на одной из попыток запрос прошёл и сработал `break`, сообщение об исчерпании не появилось бы.

## Разбор задачи: проверка числа на простоту

Число простое, если оно больше 1 и делится только на 1 и на себя. Алгоритм: перебираем возможные делители; если нашли хоть один — число составное, дальше искать незачем (`break`); если перебрали все — простое (`else`).

```python
n = 97
for divisor in range(2, int(n ** 0.5) + 1):
    if n % divisor == 0:
        print(n, "— составное, делится на", divisor)
        break
else:
    print(n, "— простое")
```

```text
97 — простое
```

Почему перебираем только до квадратного корня? Если у `n` есть делитель больше корня, то парный к нему делитель (`n / divisor`) обязательно меньше корня — и мы его уже встретили бы. Для `n = 97` это 9 проверок вместо 95. Такие оптимизации — часть **алгоритмического мышления**, которому посвящён урок 6.

## Разбор задачи: ранняя остановка обучения

Во время обучения модель после каждой эпохи проверяют на валидационных данных и смотрят на ошибку (validation loss). Пока loss падает — модель учится. Если loss несколько эпох подряд не улучшается — дальнейшее обучение бесполезно или даже вредно (модель начинает переобучаться). Механизм **early stopping** останавливает обучение после `patience` эпох без улучшения.

Смоделируем его на заранее известных значениях loss (метод `split()` разбивает строку на части по пробелам):

```python
losses = "0.90 0.71 0.62 0.60 0.61 0.63 0.59 0.64"
patience = 2
best_loss = 999.0
bad_epochs = 0
epoch = 0
for text in losses.split():
    epoch += 1
    loss = float(text)
    if loss < best_loss:
        best_loss = loss
        bad_epochs = 0
        print("Эпоха", epoch, "| loss", loss, "| новый рекорд, сохраняем модель")
        continue
    bad_epochs += 1
    print("Эпоха", epoch, "| loss", loss, "| без улучшения:", bad_epochs)
    if bad_epochs >= patience:
        print("Ранняя остановка на эпохе", epoch)
        break
else:
    print("Обучение завершено по плану")
print("Лучший loss:", best_loss)
```

```text
Эпоха 1 | loss 0.9 | новый рекорд, сохраняем модель
Эпоха 2 | loss 0.71 | новый рекорд, сохраняем модель
Эпоха 3 | loss 0.62 | новый рекорд, сохраняем модель
Эпоха 4 | loss 0.6 | новый рекорд, сохраняем модель
Эпоха 5 | loss 0.61 | без улучшения: 1
Эпоха 6 | loss 0.63 | без улучшения: 2
Ранняя остановка на эпохе 6
Лучший loss: 0.6
```

Здесь работают все три инструмента урока:

- `continue` — при новом рекорде остаток тела (подсчёт «плохих» эпох) не нужен;
- `break` — терпение исчерпано, обучение прекращаем;
- `else` — выполнился бы, если бы обучение дошло до конца без остановки.

Обратите внимание: на 7-й эпохе loss был бы 0.59 — лучше рекорда. Ранняя остановка иногда «не дожидается» позднего улучшения, поэтому `patience` подбирают с запасом. Это реальный компромисс, который вы будете решать при обучении моделей в части 6.

## break и continue во вложенных циклах

`break` и `continue` действуют только на **ближайший** охватывающий цикл. Подробно — в следующем уроке про вложенные циклы, а пока запомните: `break` во внутреннем цикле не прерывает внешний.

## Как это работает внутри

На уровне байт-кода `break` — это переход сразу за конец цикла (минуя блок `else`), а `continue` — переход к началу следующей итерации: в `for` — к получению следующего элемента у итератора, в `while` — к проверке условия. Ветка `else` просто стоит после цикла и выполняется при «нормальном» выходе, а `break` перепрыгивает через неё. Никакой дополнительной стоимости эти инструкции не несут, так что используйте их, когда это делает код понятнее.

## Частые ошибки

**1. `while True` без достижимого `break`** — вечный цикл.

**2. `continue` в `while` до изменения счётчика** — вечный цикл.

**3. Путаница `break` и `continue`.** `break` — выйти из цикла совсем, `continue` — только из текущей итерации.

**4. Неверный отступ `else`.** `else` цикла пишется на уровне `for`/`while`. Если поставить его на уровень вложенного `if`, он станет `else` условия — и логика изменится.

**5. Ожидать, что `else` выполнится после `break`.** Наоборот: `else` выполняется только **без** `break`.

**6. Слишком много `break` и `continue`.** Если их в цикле пять, код трудно читать. Подумайте о разбиении на функции (блок 1.6).

## Где это в AI-инженерии

- **Ранняя остановка обучения.** `if epochs_without_improvement >= patience: break` — прекратить обучение, когда модель перестала улучшаться.
- **Повторы запросов.** `for attempt in range(max_attempts):` — при успехе `break`, а `else` сообщает, что все попытки исчерпаны. Именно так устроен декоратор `@retry`, который вы напишете в части 2.
- **Очистка данных.** `continue` пропускает пустые, слишком короткие или повреждённые записи датасета, не останавливая обработку.
- **Поиск в результатах.** Найти первый документ с релевантностью выше порога — `break` на находке, `else` — «ничего не найдено».
- **Агентный цикл.** Агент работает в `while True` или `for step in range(max_steps)`: `break`, когда модель дала финальный ответ, `else` — «превышен лимит шагов».
- **Стриминг.** Чтение потока ответа можно прервать `break`, если пользователь нажал «Стоп» или ответ превысил лимит длины.

## Итоги урока

- `break` — немедленно выйти из цикла; `continue` — перейти к следующей итерации.
- `while True:` + `break` — цикл с условием выхода в середине тела.
- В `while` меняйте счётчик до `continue`.
- `else` у цикла выполняется, если цикл закончился без `break` — удобно для поиска.
- `break`/`continue` действуют только на ближайший цикл.
