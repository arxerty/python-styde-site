# Накопители: сумма, счётчик, максимум, поиск

## Шаблон, на котором держится половина программ

Циклы редко нужны сами по себе. Обычно цикл проходит по данным, чтобы **получить итог**: сумму продаж, количество ошибок, самую высокую оценку, первый подходящий документ. Для этого используется **накопитель** (аккумулятор) — переменная, которая обновляется на каждой итерации и в конце содержит результат.

Шаблон накопителя всегда состоит из трёх шагов:

1. **Инициализация до цикла** — начальное значение, которое соответствует «пустым данным».
2. **Обновление в теле цикла** — учёт очередного элемента.
3. **Использование после цикла** — итоговое значение готово.

```python
total = 0                      # 1. инициализация
for price in [120, 45, 300]:
    total += price             # 2. обновление
print("Итого:", total)         # 3. использование
```

```text
Итого: 465
```

Этот урок — каталог самых важных накопителей. Каждый из них вы будете писать сотни раз: сначала вручную, а потом узнавать их внутри функций `sum()`, `max()`, `any()` и методов pandas.

## Сумма и произведение

Сумма начинается с **нуля** — нейтрального элемента сложения (прибавление нуля ничего не меняет). Произведение — с **единицы** (умножение на единицу ничего не меняет).

```python
product = 1
for k in range(1, 6):
    product *= k
print("5! =", product)
```

```text
5! = 120
```

Если по ошибке начать произведение с нуля, результат всегда будет нулём. А если начать сумму с единицы — она окажется на единицу больше. Начальное значение — это ответ на вопрос: «Каким должен быть результат, если данных нет совсем?»

## Счётчик

Счётчик — частный случай суммы: прибавляем единицу, когда элемент подходит под условие.

```python
text = "Машинное обучение — это обучение на данных"
count = 0
for char in text:
    if char == "о":
        count += 1
print("Букв «о»:", count)
```

```text
Букв «о»: 4
```

Напомним трюк из урока про `bool`: `True` — это 1. Поэтому счётчик можно записать и как `count += (char == "о")`, но обычный `if` читается понятнее.

## Среднее значение

Среднее = сумма / количество. Значит, нужны **два** накопителя одновременно:

```python
scores = [4, 5, 3, 5, 4]
total = 0
count = 0
for score in scores:
    total += score
    count += 1
if count > 0:
    print("Среднее:", total / count)
else:
    print("Нет данных")
```

```text
Среднее: 4.2
```

Обязательная проверка `count > 0` защищает от деления на ноль, если данных нет. Это не перестраховка: пустые выборки в реальных данных встречаются постоянно (никто не оставил отзывов, фильтр отсеял все строки).

## Максимум и минимум

Максимум ищут приёмом «текущий рекорд»: храним лучшее значение среди уже просмотренных и обновляем его, когда встречаем большее.

Главный вопрос — **с чего начать**. Начинать с нуля **нельзя**: если все числа отрицательные, ноль «победит», хотя его в данных нет.

```python
temperatures = [-12, -5, -20, -8]
warmest = 0
for t in temperatures:
    if t > warmest:
        warmest = t
print("Неверно:", warmest)
```

```text
Неверно: 0
```

Два правильных способа:

**1. Начать с первого элемента.**

```python
temperatures = [-12, -5, -20, -8]
warmest = temperatures[0]
for t in temperatures:
    if t > warmest:
        warmest = t
print("Самая тёплая:", warmest)
```

```text
Самая тёплая: -5
```

**2. Начать с `None`** — «рекорда ещё нет». Удобно, когда данные приходят потоком (например, с `input()`) и первого элемента заранее нет:

```python
coldest = None
for t in [-12, -5, -20, -8]:
    if coldest is None or t < coldest:
        coldest = t
print("Самая холодная:", coldest)
```

```text
Самая холодная: -20
```

Короткое замыкание `or` здесь важно: при `coldest is None` сравнение `t < coldest` не вычисляется — иначе было бы `TypeError` (число нельзя сравнить с `None`).

### Позиция максимума (argmax)

Часто важно не само значение, а **где** оно: какой день был самым жарким, какой класс модель считает самым вероятным. Для этого вместе с рекордом храним его позицию:

```python
probabilities = [0.1, 0.65, 0.2, 0.05]
best_index = 0
for i in range(len(probabilities)):
    if probabilities[i] > probabilities[best_index]:
        best_index = i
print("Самый вероятный класс:", best_index)
```

```text
Самый вероятный класс: 1
```

Эта операция называется **argmax** — «аргумент максимума». Ровно так классификатор выбирает ответ: модель выдаёт вероятности классов, а итоговый класс — argmax. В NumPy и PyTorch это функция `argmax()`.

Обратите внимание на строгое `>`: при равных значениях остаётся **первое**. С `>=` оставалось бы последнее. Такие детали стоит проговаривать в условии задачи.

## Поиск: первый подходящий, есть ли хоть один, все ли

### Первый подходящий элемент

Из прошлого урока: `break` при находке + `else` или флаг.

```python
words = ["кот", "собака", "попугай", "хомяк"]
for word in words:
    if len(word) > 5:
        print("Первое длинное слово:", word)
        break
else:
    print("Длинных слов нет")
```

```text
Первое длинное слово: собака
```

### «Есть ли хотя бы один» (any)

Флаг начинается с `False` и становится `True`, как только найден подходящий элемент. Дальше можно не искать:

```python
numbers = [3, 8, -1, 4]
has_negative = False
for n in numbers:
    if n < 0:
        has_negative = True
        break
print("Есть отрицательные:", has_negative)
```

```text
Есть отрицательные: True
```

### «Все ли» (all)

Наоборот: флаг начинается с `True` и сбрасывается при первом **неподходящем** элементе:

```python
numbers = [3, 8, -1, 4]
all_positive = True
for n in numbers:
    if n <= 0:
        all_positive = False
        break
print("Все положительные:", all_positive)
```

```text
Все положительные: False
```

Интересный граничный случай: для **пустых** данных «все ли» даёт `True`, а «есть ли» — `False`. Это не ошибка, а логика: в пустом наборе нет ни одного контрпримера. В математике это называется «бессодержательной истиной». Встроенные функции `any()` и `all()` ведут себя так же.

## Накопление строки

Накопитель может быть строкой: начинаем с пустой и добавляем куски.

```python
word = "нейросеть"
reversed_word = ""
for char in word:
    reversed_word = char + reversed_word
print(reversed_word)
```

```text
ьтесорйен
```

Каждый новый символ ставится **перед** уже накопленными — так строка переворачивается.

## Несколько накопителей за один проход

Хорошая практика — собирать всю нужную статистику за **один** проход по данным. Для огромных датасетов второй проход может стоить минут или часов.

```python
values = [12, 7, 19, 3, 25, 8]
total = 0
count = 0
smallest = None
largest = None
for v in values:
    total += v
    count += 1
    if smallest is None or v < smallest:
        smallest = v
    if largest is None or v > largest:
        largest = v
print("n =", count, "| сумма =", total, "| среднее =", round(total / count, 2))
print("min =", smallest, "| max =", largest, "| размах =", largest - smallest)
```

```text
n = 6 | сумма = 74 | среднее = 12.33
min = 3 | max = 25 | размах = 22
```

Такие алгоритмы, которые обрабатывают данные «на лету», не храня их целиком, называют **потоковыми** (streaming, online). Они работают, даже если данные не помещаются в память: строки читаются из файла или приходят по сети одна за другой.

## Встроенные функции: когда можно не писать цикл

Для самых частых накопителей в Python есть готовые функции:

```python
data = [4, 9, 1, 7]
print(sum(data), max(data), min(data), len(data))
print(any(x > 8 for x in data), all(x > 0 for x in data))
```

```text
21 9 1 4
True True
```

(Запись `x > 8 for x in data` — генераторное выражение, о нём в блоке 1.5 и части 2.) В реальном коде используйте встроенные функции — они короче и быстрее. Но в задачах этого урока они часто запрещены: важно понимать, **что происходит внутри**. Когда вы будете писать собственные метрики для моделей, готовой функции может не оказаться.

## Частые ошибки

**1. Инициализация внутри цикла.** `total = 0` в теле обнуляет накопитель на каждой итерации — в итоге остаётся только последний элемент.

**2. Неверное начальное значение.** Произведение с 0, максимум с 0 при отрицательных данных, минимум с 0 при положительных.

**3. Деление на ноль при среднем.** Всегда проверяйте, что количество больше нуля.

**4. `>=` вместо `>` при поиске позиции.** Меняется, какой из равных элементов будет выбран.

**5. Сравнение с `None` без проверки.** `t < None` → `TypeError`. Сначала `is None`, потом сравнение — через `or`.

**6. Лишние проходы.** Сначала цикл для суммы, потом для минимума, потом для максимума — работает, но в три раза медленнее, чем один проход.

## Где это в AI-инженерии

- **Средний loss за эпоху.** `running_loss += loss` на каждом батче, в конце `running_loss / num_batches` — первая строка любого лога обучения.
- **Accuracy.** Счётчик правильных предсказаний `correct += (pred == label)` и общий счётчик `total += 1`.
- **Лучшая модель.** Накопитель «текущий рекорд»: `if val_loss < best_loss: best_loss = val_loss; сохранить модель`.
- **argmax.** Выбор класса классификатором и выбор следующего токена при «жадной» генерации текста в LLM.
- **Потоковые метрики.** При обработке миллионов документов метрики считают за один проход — в памяти хранится лишь несколько накопителей.
- **Подсчёт стоимости.** `total_tokens += usage.total_tokens` для каждого запроса к API — так считают расходы AI-сервиса.
- **Нормализация.** Среднее и стандартное отклонение признаков — два накопителя, по которым потом нормализуют данные.

## Итоги урока

- Накопитель: инициализация до цикла → обновление в теле → результат после цикла.
- Начальное значение = результат для пустых данных: сумма 0, произведение 1, «есть ли» False, «все ли» True.
- Максимум/минимум начинайте с первого элемента или с `None`, но не с нуля.
- argmax — храните позицию рекорда; строгое `>` оставляет первый из равных.
- Собирайте всю статистику за один проход; готовые `sum`, `max`, `min`, `any`, `all` — в реальном коде.
