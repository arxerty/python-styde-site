# Вложенные циклы

## Цикл внутри цикла

Тело цикла — обычный код, а значит, в нём может быть ещё один цикл. Такую конструкцию называют **вложенными циклами**. Они нужны, когда данные двумерны или когда нужно перебрать **все комбинации** чего-то с чем-то: строки и столбцы таблицы, пары товаров, сочетания гиперпараметров, пиксели изображения.

```python
for row in range(1, 4):
    for col in range(1, 4):
        print(row * col, end="\t")
    print()
```

```text
1	2	3	
2	4	6	
3	6	9	
```

Это таблица умножения 3×3. Внешний цикл перебирает строки, внутренний — столбцы в каждой строке.

## Как выполняются вложенные циклы

Ключевое правило: **на каждую итерацию внешнего цикла внутренний выполняется полностью**, от начала до конца.

Трассировка таблицы выше:

| Внешний `row` | Внутренний `col` | Действие |
|---|---|---|
| 1 | 1, 2, 3 | печать 1, 2, 3, затем перевод строки |
| 2 | 1, 2, 3 | печать 2, 4, 6, затем перевод строки |
| 3 | 1, 2, 3 | печать 3, 6, 9, затем перевод строки |

Важно, где стоит пустой `print()`: он внутри внешнего цикла, но **вне** внутреннего. Поэтому перевод строки происходит один раз после каждой строки таблицы. Сдвиньте его на один отступ вправо — и он окажется во внутреннем цикле, каждое число будет на своей строке. Сдвиньте влево — и он выполнится один раз после всей таблицы. Отступы снова определяют логику программы.

Аналогия — часы: внешний цикл — часовая стрелка, внутренний — минутная. Пока часовая сдвигается на одно деление, минутная проходит полный круг.

## Сколько всего итераций

Если внешний цикл делает `n` итераций, а внутренний — `m`, тело внутреннего цикла выполнится **n × m** раз:

```python
count = 0
for i in range(10):
    for j in range(20):
        count += 1
print(count)
```

```text
200
```

Это важно для оценки скорости. Два вложенных цикла по 1000 итераций — это миллион выполнений тела. Три вложенных цикла по 1000 — миллиард, и на Python это займёт минуты. Вложенность **умножает** работу. Такие алгоритмы называют квадратичными (O(n²)) или кубическими (O(n³)) — подробно о сложности алгоритмов в части 2.

## Зависимый внутренний цикл

Границы внутреннего цикла могут зависеть от переменной внешнего. Классический пример — треугольник:

```python
for row in range(1, 6):
    for _ in range(row):
        print("*", end="")
    print()
```

```text
*
**
***
****
*****
```

В первой строке внутренний цикл выполняется 1 раз, во второй — 2, и так далее. Всего итераций: 1 + 2 + 3 + 4 + 5 = 15 — почти вдвое меньше, чем 5 × 5.

(Конечно, ту же строку можно получить через повторение `"*" * row`. Но вложенные циклы нужны, когда в каждой «клетке» происходит что-то сложнее, чем печать одного символа.)

## Перебор пар

Частая задача — перебрать **все пары** элементов. Чтобы не рассматривать пару дважды (`(1, 2)` и `(2, 1)`) и не сравнивать элемент сам с собой, внутренний цикл начинают со следующего элемента:

```python
n = 4
for a in range(1, n + 1):
    for b in range(a + 1, n + 1):
        print(a, b)
```

```text
1 2
1 3
1 4
2 3
2 4
3 4
```

Шесть пар из четырёх элементов. В общем случае пар `n × (n − 1) / 2` — тоже квадратичный рост. Для 10 000 документов это около 50 миллионов сравнений.

### Пример: общие буквы двух слов

```python
word1 = "питон"
word2 = "кино"
common = ""
for letter1 in word1:
    for letter2 in word2:
        if letter1 == letter2 and letter1 not in common:
            common += letter1
print("Общие буквы:", common)
```

```text
Общие буквы: ион
```

Каждая буква первого слова сравнивается с каждой буквой второго — 5 × 4 = 20 сравнений. Строка `common` накапливает найденные буквы, а проверка `not in common` не даёт добавить букву дважды. Позже вы узнаете о множествах (блок 1.5), которые решают эту задачу одной строкой и намного быстрее.

## break и continue во вложенных циклах

`break` и `continue` действуют только на **ближайший** цикл — тот, в теле которого стоят:

```python
for i in range(1, 4):
    for j in range(1, 4):
        if j == 2:
            break
        print(i, j)
```

```text
1 1
2 1
3 1
```

`break` прервал внутренний цикл, но внешний продолжил работу со следующего `i`. Это частый источник ошибок, когда нужно **полностью** остановить поиск при первой находке.

### Как выйти из обоих циклов

**Способ 1: флаг.**

```python
target = 12
found = False
for a in range(1, 10):
    for b in range(1, 10):
        if a * b == target:
            print("Нашли:", a, "*", b)
            found = True
            break
    if found:
        break
```

```text
Нашли: 2 * 6
```

Внутренний `break` выходит из внутреннего цикла, флаг сообщает внешнему, что тоже пора выходить.

**Способ 2: `for … else`.** Хитрый, но идиоматичный приём:

```python
target = 12
for a in range(1, 10):
    for b in range(1, 10):
        if a * b == target:
            print("Нашли:", a, "*", b)
            break
    else:
        continue
    break
```

```text
Нашли: 2 * 6
```

Если внутренний цикл закончился **без** `break`, срабатывает его `else` → `continue` внешнего (идём к следующему `a`). Если внутренний прерван `break`, `else` пропускается и выполняется внешний `break`. Работает, но читается тяжело — многие предпочитают флаг.

**Способ 3: функция с `return`** — самый чистый. Вы освоите его в блоке 1.6: `return` выходит из функции сразу, сколько бы циклов ни было вложено.

## Разбор задачи: поиск по сетке гиперпараметров

У модели два гиперпараметра: скорость обучения и размер батча. Хотим попробовать все комбинации и выбрать лучшую. Представим, что «качество» комбинации считает некоторая формула (в реальности — обучение модели):

```python
best_score = -1.0
best_lr = 0.0
best_batch = 0
for lr in [0.1, 0.01, 0.001]:
    for batch in [16, 32, 64]:
        score = round(1 - abs(lr - 0.01) * 3 - abs(batch - 32) / 200, 3)
        print("lr =", lr, "batch =", batch, "score =", score)
        if score > best_score:
            best_score = score
            best_lr = lr
            best_batch = batch
print("Лучшее:", best_lr, best_batch, best_score)
```

```text
lr = 0.1 batch = 16 score = 0.65
lr = 0.1 batch = 32 score = 0.73
lr = 0.1 batch = 64 score = 0.57
lr = 0.01 batch = 16 score = 0.92
lr = 0.01 batch = 32 score = 1.0
lr = 0.01 batch = 64 score = 0.84
lr = 0.001 batch = 16 score = 0.893
lr = 0.001 batch = 32 score = 0.973
lr = 0.001 batch = 64 score = 0.813
Лучшее: 0.01 32 1.0
```

Это **grid search** — перебор по сетке. 3 × 3 = 9 комбинаций. С пятью параметрами по 5 значений — уже 3125 обучений модели, поэтому на практике используют умнее устроенный случайный поиск или байесовскую оптимизацию (блок 5.4). Но идея всегда начинается со вложенных циклов.

## Частые ошибки

**1. Неверный отступ «перевода строки».** `print()` во внутреннем цикле вместо внешнего — и таблица превращается в столбец.

**2. Одинаковые имена переменных.** `for i in …: for i in …:` — внутренний цикл затирает переменную внешнего. Давайте разные и говорящие имена: `row`/`col`, `lr`/`batch`.

**3. Ожидать, что `break` выйдет из обоих циклов.** Только из ближайшего.

**4. Недооценивать количество итераций.** 10 000 × 10 000 — сто миллионов итераций. Прежде чем вкладывать циклы, прикиньте n × m.

**5. Пары с повторами.** `for b in range(1, n + 1)` вместо `range(a + 1, n + 1)` даёт и `(1, 2)`, и `(2, 1)`, и `(1, 1)`.

**6. Инициализация накопителя не там.** Сумму по строке нужно обнулять внутри внешнего цикла (перед внутренним), а общую сумму — до обоих циклов.

## Где это в AI-инженерии

- **Эпохи × батчи.** Классический цикл обучения — два вложенных цикла: `for epoch in range(num_epochs): for batch in dataloader: …`.
- **Grid search.** Перебор комбинаций гиперпараметров — вложенные циклы или их аналоги (`itertools.product`, `GridSearchCV`).
- **Попарное сходство.** Поиск дубликатов среди документов требует сравнить все пары — n² операций. Поэтому для миллионов эмбеддингов используют векторные индексы (часть 7), которые избегают полного перебора.
- **Матрицы и изображения.** Умножение матриц и свёртка изображения на «наивном» Python — это вложенные циклы. Библиотеки делают то же самое на C и GPU в тысячи раз быстрее, но понимание вложенных циклов помогает понять, что они вычисляют.
- **Механизм внимания в трансформерах.** Каждый токен сравнивается с каждым — те же n² пар. Именно поэтому длинный контекст LLM так дорог: удвоение длины текста учетверяет работу attention.

## Итоги урока

- Внутренний цикл выполняется полностью на каждой итерации внешнего; всего n × m итераций.
- Отступы определяют, что выполняется в каждой «клетке», а что — после строки.
- Границы внутреннего цикла могут зависеть от внешнего: треугольники, пары `range(a + 1, n + 1)`.
- `break`/`continue` влияют только на ближайший цикл; для выхода из обоих — флаг, `for…else` или функция с `return`.
- Вложенность умножает работу — оценивайте количество итераций заранее.
