# Цикл while и условие выхода

## Зачем нужны циклы

Компьютеры особенно хороши в одном: делать одно и то же **много раз** — быстро и без ошибок. Обучение нейросети — это тысячи повторений одного шага: взять порцию данных, посчитать ошибку, подправить веса. Чат-бот — бесконечное повторение «прочитать сообщение, ответить». Обработка датасета — одно действие для каждой из миллиона строк.

Без циклов, чтобы вывести числа от 1 до 5, пришлось бы писать пять `print()`. А до миллиона? Циклы позволяют описать действие **один раз** и указать, сколько раз или до какого момента его повторять.

В Python два вида циклов:

- **`while`** — «пока условие истинно, повторяй». Используется, когда заранее неизвестно, сколько будет повторений.
- **`for`** — «для каждого элемента последовательности сделай». Используется для перебора известного набора (следующий урок).

## Синтаксис while

```python norun
while условие:
    тело цикла
следующая инструкция
```

Устроено как `if`, только тело выполняется **многократно**:

1. Python проверяет условие.
2. Если оно истинно — выполняет тело целиком.
3. Возвращается к шагу 1 и снова проверяет условие.
4. Как только условие ложно — выходит из цикла и выполняет следующую после него инструкцию.

Одно выполнение тела называется **итерацией**.

```python
count = 1
while count <= 5:
    print("Итерация", count)
    count += 1
print("Готово")
```

```text
Итерация 1
Итерация 2
Итерация 3
Итерация 4
Итерация 5
Готово
```

## Трассировка цикла

Разберём, что происходит, шаг за шагом:

| Проверка | `count` | `count <= 5` | Действие |
|---|---|---|---|
| 1 | 1 | True | печать «Итерация 1», count → 2 |
| 2 | 2 | True | печать «Итерация 2», count → 3 |
| 3 | 3 | True | печать «Итерация 3», count → 4 |
| 4 | 4 | True | печать «Итерация 4», count → 5 |
| 5 | 5 | True | печать «Итерация 5», count → 6 |
| 6 | 6 | False | выход из цикла |

Обратите внимание: условие проверено **6 раз**, а тело выполнено **5 раз**. Последняя проверка «проваливается» — это и есть момент выхода. После цикла `count` равен 6, а не 5 — эту деталь часто забывают.

## Три части правильного цикла

Почти любой цикл `while` с счётчиком состоит из трёх частей:

1. **Инициализация** — начальное значение переменной до цикла: `count = 1`.
2. **Условие** — проверка в заголовке: `count <= 5`.
3. **Изменение** — шаг внутри тела, который приближает условие к ложному: `count += 1`.

Если забыть любую часть, цикл сломается:

- без инициализации — `NameError` при первой проверке;
- с неверным условием — цикл не выполнится ни разу или выполнится лишний раз;
- без изменения — условие никогда не станет ложным, и цикл будет вечным.

## Бесконечные циклы

Если условие всегда истинно, цикл никогда не закончится:

```python norun
count = 1
while count <= 5:
    print(count)
    # забыли count += 1 — программа будет печатать 1 вечно
```

Программа «зависает» и съедает процессор. В терминале её прерывают сочетанием `Ctrl + C`. На этой платформе запуск автоматически останавливается по таймауту с сообщением о возможном бесконечном цикле.

Типичные причины бесконечных циклов:

- забыли изменить переменную условия;
- изменяют не ту переменную (опечатка: `cuont += 1`);
- изменение идёт «не в ту сторону»: `count -= 1` при условии `count <= 5`;
- изменение стоит вне тела цикла из-за неверного отступа.

```python norun
count = 1
while count <= 5:
    print(count)
count += 1      # без отступа — это уже после цикла, до него дело не дойдёт
```

### Намеренно бесконечный цикл

Иногда бесконечный цикл — это **то, что нужно**: сервер ждёт запросы, чат-бот ждёт сообщения, игра обрабатывает кадры. Тогда пишут `while True:`, а выход делают изнутри с помощью `break` (подробно — в уроке 3):

```python
messages = 0
while True:
    messages += 1
    if messages == 3:
        break
print("Обработано сообщений:", messages)
```

```text
Обработано сообщений: 3
```

## Цикл, который может не выполниться ни разу

Условие проверяется **до** первой итерации. Если оно сразу ложно, тело не выполнится ни разу:

```python
balance = 0
while balance > 0:
    print("Тратим деньги")
    balance -= 100
print("Баланс:", balance)
```

```text
Баланс: 0
```

Это не ошибка, а полезное свойство: цикл корректно обрабатывает «пустой» случай.

## while для неизвестного числа повторений

Главная сила `while` — когда количество повторений определяется **данными**, а не известно заранее.

### Пример: сколько лет до удвоения вклада

```python
amount = 100_000
rate = 12
target = amount * 2
years = 0
while amount < target:
    amount *= 1 + rate / 100
    years += 1
print("Вклад удвоится через", years, "лет")
print("Сумма:", round(amount, 2))
```

```text
Вклад удвоится через 7 лет
Сумма: 221068.14
```

Мы не знаем заранее, сколько будет лет — цикл просто повторяет «прожить ещё год», пока сумма не дорастёт до цели.

### Пример: разбор числа на цифры

Классический алгоритм: пока число не стало нулём, отщепляем последнюю цифру через `% 10` и убираем её через `// 10`:

```python
number = 4721
digit_sum = 0
digits = 0
while number > 0:
    digit_sum += number % 10
    number //= 10
    digits += 1
print("Цифр:", digits, "Сумма цифр:", digit_sum)
```

```text
Цифр: 4 Сумма цифр: 14
```

Трассировка: `4721 → 472 → 47 → 4 → 0`. На каждом шаге к сумме прибавляется последняя цифра: 1, 2, 7, 4.

### Пример: чтение данных до стоп-слова

`while` естественно сочетается с вводом: читаем, пока пользователь не введёт специальное значение-**сигнал остановки** (sentinel):

```python
total = 0
number = int(input("Число (0 — конец): "))
while number != 0:
    total += number
    number = int(input("Число (0 — конец): "))
print("Сумма:", total)
```

Обратите внимание на структуру: первое чтение — **до** цикла, следующее — **в конце** тела. Так условие всегда проверяет только что прочитанное значение, а сигнал остановки `0` не попадает в сумму. Этот шаблон называют «чтение с опережением».

## Разбор задачи: угадываем число делением пополам

Компьютер загадал число от 1 до 100. Мы можем спрашивать «твоё число больше X?» Как угадать за минимальное число вопросов? Перебирать 1, 2, 3… — до 100 вопросов. Гораздо лучше каждый раз спрашивать про **середину** оставшегося диапазона: так он сокращается вдвое.

```python
secret = 73
low = 1
high = 100
steps = 0
while low < high:
    middle = (low + high) // 2
    steps += 1
    if secret > middle:
        low = middle + 1
    else:
        high = middle
print("Число:", low, "| вопросов:", steps)
```

```text
Число: 73 | вопросов: 7
```

Трассировка первых шагов:

| Шаг | `low` | `high` | `middle` | `secret > middle`? |
|---|---|---|---|---|
| 1 | 1 | 100 | 50 | да → `low = 51` |
| 2 | 51 | 100 | 75 | нет → `high = 75` |
| 3 | 51 | 75 | 63 | да → `low = 64` |
| 4 | 64 | 75 | 69 | да → `low = 70` |

Диапазон каждый раз сужается вдвое, и через 7 шагов в нём остаётся одно число. Для диапазона в миллион чисел понадобится всего 20 вопросов, для миллиарда — 30. Этот алгоритм называется **бинарным поиском**, и он — первый пример того, как правильная идея важнее скорости компьютера. В блоке про алгоритмы (часть 2) вы разберёте его подробно.

Обратите внимание, почему здесь именно `while`: количество шагов зависит от загаданного числа и заранее неизвестно. Условие `low < high` гарантирует завершение — на каждой итерации расстояние между границами строго уменьшается. Это стоит проверять для любого `while`: **что именно приближает цикл к выходу?**

## Как работает цикл внутри

На уровне байт-кода цикл `while` — это всего лишь условный переход: «если условие ложно — перейди за конец цикла, иначе выполни тело и перейди обратно к проверке». Никакой магии: компьютер просто возвращается к уже выполненным инструкциям. Поэтому каждая итерация стоит времени, и в Python — относительно много: простой цикл выполняет порядка десятков миллионов итераций в секунду. Это быстро для обычных программ, но мало для обработки больших массивов чисел — именно поэтому в ML используют NumPy и PyTorch, которые выполняют циклы на C и GPU. В части 4 вы увидите, как одна векторизованная операция NumPy заменяет цикл и работает в сотни раз быстрее.

## Частые ошибки

**1. Забыть изменить переменную условия** — бесконечный цикл.

**2. Неверный отступ** — изменение оказывается вне тела цикла.

**3. Ошибка на единицу** (off-by-one). `while count < 5` против `while count <= 5` — разница в одну итерацию. Проверяйте первую и последнюю итерацию трассировкой.

**4. Забыть, что после цикла переменная «перешагнула» границу.** После `while count <= 5` значение `count` равно 6.

**5. Перезаписывать накопитель внутри цикла.** `total = number` вместо `total += number` — в конце останется только последнее значение.

**6. Неверная инициализация.** Если начать `count = 0` вместо `count = 1`, цикл сделает лишний шаг или напечатает 0.

## Где это в AI-инженерии

- **Цикл обучения.** Обучение модели — это цикл «пока не достигнуто нужное число шагов или loss не перестал падать». Часто его пишут именно через `while step < max_steps:`.
- **Ранняя остановка.** `while epochs_without_improvement < patience:` — продолжать, пока модель улучшается.
- **Повторы запросов к API.** `while attempt < max_attempts:` с паузой между попытками — стандартный способ пережить временные сбои сервиса LLM.
- **Агентный цикл.** AI-агент работает по схеме «подумать → выполнить действие → посмотреть результат» в цикле `while not done:`, пока не получит ответ или не исчерпает лимит шагов. Лимит обязателен — иначе агент может «зациклиться» и потратить весь бюджет на API.
- **Чат-бот в консоли.** `while True:` — читать сообщение, отправлять модели, печатать ответ, выходить по команде `/exit`.
- **Стриминг.** При потоковой генерации ответ приходит кусками, и код читает их в цикле, пока поток не закончится.

## Итоги урока

- `while условие:` повторяет тело, пока условие истинно; условие проверяется перед каждой итерацией.
- Три части цикла: инициализация, условие, изменение. Нет изменения — вечный цикл.
- Тело может не выполниться ни разу, если условие сразу ложно.
- `while` — для неизвестного заранее числа повторений: до достижения цели, до сигнала остановки.
- Шаблон чтения до стоп-значения: первое чтение до цикла, следующее — в конце тела.
