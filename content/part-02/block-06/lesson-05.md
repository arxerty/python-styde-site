# Поиск и сортировка: бинарный поиск, принципы сортировок

## Линейный поиск

Самый простой способ найти элемент — проверять всё подряд. Это **линейный поиск**, сложность O(n): в худшем случае нужно просмотреть все элементы.

```python
def linear_search(items, target):
    for index, item in enumerate(items):
        if item == target:
            return index
    return -1


print(linear_search([7, 3, 9, 1], 9), linear_search([7, 3, 9, 1], 5))
```

```text
2 -1
```

Именно так работают `list.index`, `in` для списка и `str.find`. Линейный поиск универсален — ему не важен порядок данных. Но если данные **отсортированы**, можно искать несравнимо быстрее.

## Бинарный поиск

Вспомните, как вы ищете слово в бумажном словаре: открываете на середине, смотрите, левее или правее нужное слово, и отбрасываете ненужную половину. Каждый шаг уменьшает область поиска вдвое. Это **бинарный поиск**:

```python
def binary_search(items, target):
    low, high = 0, len(items) - 1
    while low <= high:
        middle = (low + high) // 2
        if items[middle] == target:
            return middle
        if items[middle] < target:
            low = middle + 1
        else:
            high = middle - 1
    return -1


numbers = [2, 5, 8, 12, 16, 23, 38, 56, 72, 91]
print(binary_search(numbers, 23), binary_search(numbers, 7))
```

```text
5 -1
```

Алгоритм поддерживает **инвариант**: если искомый элемент есть, он лежит в диапазоне `[low, high]`. На каждом шаге диапазон сокращается вдвое, а когда `low > high`, диапазон пуст — элемента нет.

Сколько шагов нужно? Для миллиона элементов — около 20 (2²⁰ ≈ 10⁶), для миллиарда — около 30. Это сложность **O(log n)**: удвоение данных добавляет всего один шаг.

```python
import math

for n in (1_000, 1_000_000, 1_000_000_000):
    print(n, math.ceil(math.log2(n + 1)))
```

```text
1000 10
1000000 20
1000000000 30
```

Главное условие — данные **отсортированы**. Бинарный поиск по неотсортированному списку даёт бессмысленный результат без всякой ошибки. Если поиск нужен один раз, сортировать ради него невыгодно (сортировка — O(n log n), дороже линейного поиска); выгода появляется, когда поисков много.

## Модуль bisect

Писать бинарный поиск вручную легко с ошибкой «на единицу» (`<` вместо `<=`, `middle` вместо `middle + 1`) — классика собеседований. В стандартной библиотеке есть готовый модуль `bisect`:

```python
import bisect

scores = [10, 20, 20, 20, 30, 40]
print(bisect.bisect_left(scores, 20))
print(bisect.bisect_right(scores, 20))
print(bisect.bisect_left(scores, 25))
bisect.insort(scores, 25)
print(scores)
```

```text
1
4
4
[10, 20, 20, 20, 25, 30, 40]
```

- `bisect_left(a, x)` — первая позиция, куда можно вставить `x`, сохранив порядок (индекс первого элемента ≥ x);
- `bisect_right(a, x)` — последняя такая позиция (индекс первого элемента > x);
- разница `bisect_right − bisect_left` — сколько раз `x` встречается в списке;
- `insort(a, x)` — вставить с сохранением сортировки (поиск O(log n), но вставка в список — O(n)).

Проверка наличия элемента через `bisect`:

```python
import bisect


def contains(sorted_items, x):
    i = bisect.bisect_left(sorted_items, x)
    return i < len(sorted_items) and sorted_items[i] == x


words = sorted(["модель", "токен", "эмбеддинг", "агент", "промпт"])
print(words)
print(contains(words, "токен"), contains(words, "вектор"))
```

```text
['агент', 'модель', 'промпт', 'токен', 'эмбеддинг']
True False
```

## Бинарный поиск по ответу

Идея бинарного поиска шире, чем «найти элемент в списке». Его можно применять к любой **монотонной** проверке: если условие ложно до некоторой точки и истинно после неё, границу можно найти делением пополам.

Пример: определить минимальный размер батча, при котором обработка уложится в лимит времени, или порог уверенности модели, при котором точность не ниже 95%. Покажем на задаче: какой минимальный бюджет токенов на документ нужен, чтобы все документы поместились в контекст из 10 000 токенов?

```python
def fits(budget, docs, limit):
    return sum(min(length, budget) for length in docs) <= limit


def max_budget(docs, limit):
    low, high = 0, max(docs)
    while low < high:
        middle = (low + high + 1) // 2
        if fits(middle, docs, limit):
            low = middle
        else:
            high = middle - 1
    return low


docs = [5200, 1800, 900, 4300, 2600]
budget = max_budget(docs, 10_000)
print(budget, sum(min(d, budget) for d in docs))
```

```text
2433 9999
```

Если каждому документу разрешить не больше 2433 токенов (длинные обрезаются), все вместе занимают 9999 токенов и помещаются в лимит; при 2434 — уже нет. Функция `fits` монотонна: чем больше бюджет, тем больше суммарный объём. Вместо перебора всех значений от 0 до 5200 понадобилось около 13 проверок.

## Сортировка: зачем знать алгоритмы

В Python есть `sorted()` и `list.sort()`, и писать сортировки вручную на практике почти никогда не нужно. Но понимать их принципы важно: это классические примеры сложности O(n²) и O(n log n), стратегии «разделяй и властвуй» и вопросов стабильности.

### Сортировка вставками — O(n²)

Идея: берём элементы по одному и вставляем каждый на своё место в уже отсортированную левую часть — как раскладывают карты в руке.

```python
def insertion_sort(items):
    result = list(items)
    for i in range(1, len(result)):
        current = result[i]
        j = i - 1
        while j >= 0 and result[j] > current:
            result[j + 1] = result[j]
            j -= 1
        result[j + 1] = current
    return result


print(insertion_sort([5, 2, 9, 1, 5, 6]))
```

```text
[1, 2, 5, 5, 6, 9]
```

В худшем случае (данные в обратном порядке) каждый элемент сдвигается через всю левую часть — O(n²). Зато на **почти отсортированных** данных сортировка вставками почти линейна, и для маленьких массивов она очень быстрая.

### Сортировка слиянием — O(n log n)

Стратегия **«разделяй и властвуй»**: разбить список пополам, рекурсивно отсортировать половины и **слить** два отсортированных списка в один (как в задаче про слияние потоков из блока 2.3):

```python
def merge(left, right):
    result = []
    i = j = 0
    while i < len(left) and j < len(right):
        if left[i] <= right[j]:
            result.append(left[i])
            i += 1
        else:
            result.append(right[j])
            j += 1
    result.extend(left[i:])
    result.extend(right[j:])
    return result


def merge_sort(items):
    if len(items) <= 1:
        return list(items)
    middle = len(items) // 2
    return merge(merge_sort(items[:middle]), merge_sort(items[middle:]))


print(merge_sort([38, 27, 43, 3, 9, 82, 10]))
```

```text
[3, 9, 10, 27, 38, 43, 82]
```

Почему O(n log n)? Список делится пополам log₂ n раз (уровни рекурсии), и на каждом уровне слияние всех частей суммарно обрабатывает n элементов. Это лучшее возможное время для сортировки, основанной на сравнениях.

Ещё один известный алгоритм — **быстрая сортировка** (quicksort): выбрать опорный элемент, разделить список на «меньше» и «больше» опорного и рекурсивно отсортировать части. В среднем O(n log n), в худшем — O(n²).

### Что использует Python

`sorted` и `list.sort` используют **Timsort** — гибрид сортировки слиянием и вставками, придуманный Тимом Петерсом для Python. Он находит в данных уже упорядоченные участки («серии») и сливает их, поэтому на реальных частично упорядоченных данных работает очень быстро, а в худшем случае — O(n log n).

## Стабильность и сортировка по нескольким ключам

Сортировка **стабильна**, если элементы с равными ключами сохраняют исходный порядок. Timsort стабилен — и это позволяет сортировать по нескольким критериям:

```python
results = [
    ("bert", 0.91, 120),
    ("gpt", 0.95, 900),
    ("tfidf", 0.91, 3),
    ("cnn", 0.88, 45),
]
by_score_then_speed = sorted(results, key=lambda r: (-r[1], r[2]))
print([name for name, _, _ in by_score_then_speed])

stable = sorted(results, key=lambda r: r[2])
stable = sorted(stable, key=lambda r: r[1], reverse=True)
print([name for name, _, _ in stable])
```

```text
['gpt', 'tfidf', 'bert', 'cnn']
['gpt', 'tfidf', 'bert', 'cnn']
```

Два способа дают одно и то же: «по точности по убыванию, при равенстве — по задержке по возрастанию».

- **Ключ-кортеж**: `key=lambda r: (-r[1], r[2])` — кортежи сравниваются поэлементно; минус разворачивает порядок для чисел;
- **Несколько стабильных сортировок**: сначала по второстепенному ключу, затем по главному. Этот приём нужен, когда минус неприменим (например, строки по убыванию и числа по возрастанию).

## Разбор задачи: поиск по отсортированному индексу

Нужно быстро отвечать на запросы «сколько документов с оценкой релевантности в диапазоне [a, b]» и «какой порог отсекает лучшие 10% документов». Отсортируем оценки один раз и будем отвечать на каждый запрос за O(log n):

```python
import bisect
import random

rng = random.Random(7)
scores = sorted(round(rng.random(), 3) for _ in range(10_000))


def count_in_range(sorted_scores, low, high):
    return bisect.bisect_right(sorted_scores, high) - bisect.bisect_left(sorted_scores, low)


def top_threshold(sorted_scores, fraction):
    index = int(len(sorted_scores) * (1 - fraction))
    return sorted_scores[index]


print(count_in_range(scores, 0.0, 1.0))
print(count_in_range(scores, 0.5, 0.5999) > 0)
threshold = top_threshold(scores, 0.1)
print(sum(1 for s in scores if s >= threshold) >= 1000)
```

```text
10000
True
True
```

Сортировка стоит O(n log n), но выполняется один раз; дальше каждый запрос диапазона — два бинарных поиска. Для тысяч запросов это в тысячи раз быстрее, чем считать подходящие оценки перебором каждый раз. Порог «лучших 10%» — просто элемент на нужной позиции отсортированного списка (это и есть квантиль, о котором пойдёт речь в части 3).

## Частые ошибки

**1. Бинарный поиск по неотсортированным данным.** Результат будет неверным без всякой ошибки. Сортируйте или проверяйте порядок.

**2. Ошибки «на единицу».** `while low < high` вместо `<=`, `high = middle` вместо `middle - 1` — бесконечный цикл или пропуск элемента. Используйте `bisect`.

**3. Сортировка ради одного поиска.** Сортировка O(n log n) дороже одного линейного поиска O(n). Бинарный поиск выгоден при многих запросах.

**4. `insort` в цикле для больших данных.** Каждая вставка в список — O(n), итого O(n²). Если нужно добавить много элементов — добавьте всё и отсортируйте один раз.

**5. Неверный порядок многоступенчатой сортировки.** При сортировке в несколько проходов первым идёт **второстепенный** ключ, последним — главный.

**6. Сортировка, когда нужен только максимум или top-k.** `sorted(items)[-1]` — O(n log n), а `max(items)` — O(n); для top-k есть `heapq.nlargest` (урок 6).

## Где это в AI-инженерии

- **Ранжирование результатов поиска**: документы сортируются по релевантности, при равенстве — по свежести (многоключевая стабильная сортировка).
- **Пороги и квантили**: выбор порога уверенности классификатора, отсечение аномалий по перцентилю — поиск в отсортированных оценках.
- **Бинарный поиск по ответу** в инженерии: подбор максимального размера батча, который помещается в память GPU; поиск learning rate; выбор длины контекста под бюджет токенов.
- **Токенизаторы**: сопоставление позиций символов с токенами (offset mapping) — бинарный поиск по отсортированным границам.
- **Слияние отсортированных шардов** при обработке больших данных — тот же `merge`, что в сортировке слиянием.

## Итоги урока

- Линейный поиск — O(n), работает с любыми данными; бинарный — O(log n), только по отсортированным.
- Бинарный поиск сужает диапазон вдвое и держит инвариант «ответ внутри [low, high]».
- `bisect_left`, `bisect_right`, `insort` — готовый бинарный поиск без ошибок «на единицу».
- Бинарный поиск по ответу работает для любой монотонной проверки.
- Вставками — O(n²) (хороша на почти отсортированных данных), слиянием — O(n log n); Python использует стабильный Timsort.
- Сортировка по нескольким ключам: ключ-кортеж или несколько стабильных проходов (от второстепенного к главному).
