# Объекты, ссылки, id, is и ==

## Переменная — это не коробка

В начале курса удобно было представлять переменную как «коробку», в которую кладут значение. Для понимания того, как Python работает на самом деле, эта картинка не годится. Точнее другая модель: **переменная — это имя, ярлык, привязанный к объекту**. Сам объект живёт отдельно, в памяти, а имя лишь указывает на него.

Присваивание `x = [1, 2, 3]` делает две вещи: создаёт объект-список и **привязывает** к нему имя `x`. А присваивание `y = x` не копирует список — оно привязывает второе имя к **тому же самому** объекту:

```python
x = [1, 2, 3]
y = x
y.append(4)
print(x)
print(y)
print(x is y)
```

```text
[1, 2, 3, 4]
[1, 2, 3, 4]
True
```

Мы изменили список через имя `y`, а изменение видно и через `x` — потому что это один и тот же список с двумя ярлыками. Два имени для одного объекта называют **псевдонимами** (aliasing). Это одна из главных причин неожиданных багов в Python — и одна из главных идей, которые нужно понять, чтобы их избегать.

## id: адрес объекта

У каждого объекта есть уникальный идентификатор, который не меняется всё время жизни объекта. Его возвращает функция `id()` (в CPython это адрес объекта в памяти):

```python
a = [1, 2]
b = a
c = [1, 2]
print(id(a) == id(b))
print(id(a) == id(c))
```

```text
True
False
```

`a` и `b` указывают на один объект — идентификаторы равны. `c` — другой список с тем же содержимым — идентификатор другой. Конкретные значения `id` печатать нет смысла: они разные при каждом запуске.

## is и ==: тождество и равенство

В Python два разных вопроса о двух объектах:

- `a == b` — **равны ли** они по значению? Вызывает метод `__eq__` (блок 2.2);
- `a is b` — **один ли это объект**? Сравнивает идентичность, то есть `id(a) == id(b)`.

```python
first = {"model": "bert", "layers": 12}
second = {"model": "bert", "layers": 12}
alias = first
print(first == second, first is second)
print(first == alias, first is alias)
```

```text
True False
True True
```

Два словаря с одинаковым содержимым **равны**, но это **разные** объекты. Изменение `second` не затронет `first`, а изменение `alias` — затронет.

Когда что использовать:

- `==` — почти всегда, когда сравниваете значения: числа, строки, списки, свои объекты;
- `is` — для сравнения с **синглтонами** — объектами, которые существуют в единственном экземпляре: `None`, `True`, `False`, а также члены `Enum` (блок 2.2) и маркеры вроде `sentinel = object()` (блок 2.3).

```python
def find(items, target):
    for index, item in enumerate(items):
        if item == target:
            return index
    return None


result = find(["a", "b"], "c")
print(result is None)
print(find(["a", "b"], "a") is None)
```

```text
True
False
```

`x is None` — стандарт PEP 8. Почему не `x == None`? Класс может переопределить `__eq__` так, что сравнение с `None` даст неожиданный результат, а `is` нельзя переопределить — он всегда честно проверяет тождество. Кроме того, `is` чуть быстрее.

## Ловушка: is для чисел и строк

Новички иногда сравнивают числа и строки через `is`, и это **иногда** работает — что делает ошибку особенно коварной:

```python
a = 256
b = 256
print(a is b)
x = int("1000")
y = int("1000")
print(x == y, x is y)
```

```text
True
True False
```

Небольшие целые числа (от −5 до 256) CPython создаёт заранее и переиспользует — поэтому `256 is 256` истинно. Числа побольше, созданные в разных местах, — разные объекты: `x is y` ложно, хотя числа равны. С короткими строками похожая история: часть из них Python **интернирует** (хранит в одном экземпляре), часть — нет.

Это детали реализации, которые могут меняться между версиями Python. Правило простое: **значения сравнивайте только через `==`**. Начиная с Python 3.8 интерпретатор даже предупреждает об `is` с литералом: `SyntaxWarning: "is" with a literal`.

## Передача аргументов в функции

Как Python передаёт аргументы в функцию — «по значению» или «по ссылке»? Ни то, ни другое в классическом смысле. Параметр функции — это новое **имя**, привязанное к **тому же объекту**, что передали. Это называют передачей по ссылке на объект (call by sharing).

Из этого следуют два случая:

```python
def add_item(items, item):
    items.append(item)


def replace_items(items):
    items = ["новый", "список"]


data = ["a"]
add_item(data, "b")
print(data)
replace_items(data)
print(data)
```

```text
['a', 'b']
['a', 'b']
```

- `add_item` **изменяет** объект (`append`) — изменение видно снаружи, потому что `items` и `data` указывают на один список;
- `replace_items` **переназначает имя** `items` на новый список — это меняет только локальное имя внутри функции, объект `data` снаружи не затронут.

Различайте **изменение объекта** (методы `append`, `update`, `sort`, присваивание элемента `items[0] = ...`) и **переназначение имени** (`items = ...`). Первое видно всем, у кого есть ссылка на объект; второе касается только одного имени.

Отсюда практическое правило: функция, которая **меняет** переданный изменяемый объект, должна делать это явно и ожидаемо (как `list.sort`), а обычно лучше возвращать новый объект и не трогать аргументы.

## Неизменяемые объекты и «изменение»

С неизменяемыми объектами — числами, строками, кортежами — изменить объект нельзя в принципе. Операции, которые выглядят как изменение, создают **новый** объект и переназначают имя:

```python
name = "ада"
original = name
name = name.upper()
print(name, original)

counter = 10
alias = counter
counter += 1
print(counter, alias)

point = (1, 2)
same = point
point += (3,)
print(point, same)
```

```text
АДА ада
11 10
(1, 2, 3) (1, 2)
```

Во всех трёх случаях исходный объект не изменился — у `original`, `alias`, `same` старые значения, а основное имя теперь указывает на новый объект. С неизменяемыми объектами псевдонимы безопасны: никто не может изменить объект «у вас под носом».

А вот `+=` для **списка** работает иначе — изменяет список на месте (через `__iadd__`, блок 2.2), и это видно через все псевдонимы:

```python
items = [1, 2]
alias = items
items += [3]
print(alias, items is alias)
```

```text
[1, 2, 3] True
```

## Жизнь объекта: подсчёт ссылок

Когда объект перестаёт быть нужным? CPython ведёт для каждого объекта **счётчик ссылок** — сколько имён, элементов коллекций и атрибутов на него указывают. Когда счётчик падает до нуля, объект немедленно удаляется и память освобождается. Для циклических ссылок (объект ссылается сам на себя через другие) есть дополнительный сборщик мусора (`gc`).

Инструкция `del name` удаляет **имя**, а не объект: объект исчезнет, только если на него больше никто не ссылается.

```python
model_weights = [0.1] * 1000
backup = model_weights
del model_weights
print(len(backup))
```

```text
1000
```

Список жив, потому что на него ещё ссылается `backup`. Это важно в ML: если «удалить» большую модель или датасет через `del`, но где-то осталась ссылка (в списке, словаре, атрибуте объекта), память не освободится. Типичная причина «утечек» памяти в ноутбуках Jupyter — забытые ссылки на большие объекты.

## Разбор задачи: история диалога и общий список

Классический баг в LLM-приложениях — история сообщений, которая неожиданно оказывается общей. Вот упрощённый пример: шаблон диалога с системным промптом используется для создания историй разных пользователей.

```python
TEMPLATE = [{"role": "system", "content": "Ты вежливый помощник."}]


def start_chat_buggy():
    return TEMPLATE


def start_chat():
    return [dict(message) for message in TEMPLATE]


ada = start_chat_buggy()
alan = start_chat_buggy()
ada.append({"role": "user", "content": "Мой пароль — 1234"})
print(len(alan), alan is ada, alan is TEMPLATE)

TEMPLATE[1:] = []
grace = start_chat()
linus = start_chat()
grace.append({"role": "user", "content": "Привет"})
grace[0]["content"] = "Отвечай кратко."
print(len(linus), linus[0]["content"], TEMPLATE[0]["content"])
```

```text
2 True True
1 Ты вежливый помощник. Ты вежливый помощник.
```

В первой версии все пользователи получили **один и тот же** список — тот самый `TEMPLATE`. Сообщение Ады (с паролем!) оказалось в истории Алана и даже в шаблоне. Вторая версия создаёт для каждого пользователя новый список с **копиями** словарей-сообщений — изменения истории Грейс не затрагивают ни Линуса, ни шаблон. (Строка `TEMPLATE[1:] = []` удаляет из шаблона «просочившееся» сообщение — изменение на месте.)

Почему копировать нужно ещё и словари внутри, а не только список, — тема следующего урока о поверхностном и глубоком копировании.

## Частые ошибки

**1. Ожидание копии при присваивании.** `b = a` для списка или словаря не копирует данные — изменения через `b` видны через `a`.

**2. `is` для сравнения значений.** `x is 1000`, `name is "admin"` — работает «иногда», зависит от реализации. Значения сравнивайте через `==`.

**3. `== None` вместо `is None`.** Работает, но не идиоматично и может обмануть классы с переопределённым `__eq__`. Пишите `is None` / `is not None`.

**4. Неожиданное изменение аргумента.** Функция, которая делает `items.append(...)` или `config["lr"] = ...` с переданным объектом, меняет данные вызывающего кода. Если это не цель функции — работайте с копией.

**5. Ожидание, что переназначение параметра изменит аргумент.** `items = []` внутри функции не очищает список снаружи. Для очистки на месте — `items.clear()`.

**6. «Удаление» объекта через `del`, когда есть другие ссылки.** Память не освободится, пока жива хоть одна ссылка.

## Где это в AI-инженерии

- **Тензоры и массивы**: в NumPy и PyTorch срезы и `view` часто разделяют память с исходным массивом — изменение «копии» меняет оригинал (блок 4.1). Понимание ссылок — основа работы с ними.
- **Истории диалогов и конфигурации**: общий список сообщений или словарь настроек между пользователями — частый источник утечки данных в LLM-сервисах.
- **Память в ноутбуках**: большие модели и датасеты не освобождаются, пока на них есть ссылки (в том числе в истории вывода Jupyter `Out[...]`).
- **Кэширование**: кэш, возвращающий ссылку на хранящийся изменяемый объект, позволяет вызывающему коду испортить кэш (блок 2.4).
- **Предобученные веса**: несколько моделей могут разделять один объект слоя эмбеддингов (weight tying) — изменение весов одной меняет другую.

## Итоги урока

- Переменная — имя, привязанное к объекту; присваивание не копирует, а создаёт ещё одну ссылку.
- `id(obj)` — идентификатор объекта; `is` сравнивает тождество, `==` — равенство значений.
- `is` — только для синглтонов: `None`, `True`, `False`, члены Enum, маркеры; значения — через `==`.
- Аргументы передаются как ссылки на объекты: изменение объекта видно снаружи, переназначение параметра — нет.
- Операции над неизменяемыми объектами создают новые объекты; `+=` для списка меняет его на месте.
- Объект живёт, пока на него есть ссылки; `del` удаляет имя, а не объект.
