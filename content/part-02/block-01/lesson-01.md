# Зачем ООП: класс, объект, __init__ и self

## Данные и действия вместе

В части 1 вы описывали данные словарями, а действия — функциями. Задача в менеджере задач была словарём `{"id": 1, "title": ..., "done": False}`, а `complete_task(tasks, task_id)` и `format_task(task)` — отдельными функциями, которые знают устройство этого словаря. Это работает, но у подхода есть слабые места:

- **Ничто не гарантирует структуру.** Любой код может создать словарь без поля `done` или с опечаткой `"titel"` — ошибка проявится далеко от места, где её допустили.
- **Данные и действия разбросаны.** Функции для задач нужно искать по всему проекту; новый разработчик не знает, какие операции вообще доступны.
- **Имена конфликтуют.** `format` для задачи, `format` для отчёта, `format` для пользователя — приходится придумывать `format_task`, `format_report`...

**Объектно-ориентированное программирование (ООП)** решает это, объединяя **данные** и **поведение** в одну сущность — **объект**. Задача «знает» свои поля и «умеет» себя выполнять и форматировать: `task.complete()`, `task.format()`.

Вы пользуетесь объектами с первого урока: строка `"текст"` — объект с данными (символы) и методами (`.upper()`, `.split()`); список — объект с данными (элементы) и методами (`.append()`, `.sort()`). Сегодня вы научитесь создавать **собственные** типы объектов.

## Класс и объект

**Класс** — это шаблон, «чертёж», описывающий, какие данные будут у объектов и что они умеют. **Объект** (экземпляр класса) — конкретная вещь, созданная по этому чертежу.

Аналогия: класс — это форма для печенья, объекты — само печенье. Форма одна, печений много, и у каждого может быть своя глазурь.

```python
class Dog:
    pass


rex = Dog()
bobik = Dog()
print(type(rex))
print(rex is bobik)
```

```text
<class '__main__.Dog'>
False
```

- `class Dog:` объявляет класс. Имена классов по PEP 8 пишутся в стиле **CapWords**: `Dog`, `BankAccount`, `HttpClient`.
- `Dog()` — **вызов класса** создаёт новый объект. Каждый вызов — новый, независимый объект.
- `type(rex)` показывает, что `rex` — экземпляр класса `Dog`.

Класс `Dog` пока пустой (`pass`). Наполним его.

## Атрибуты объекта

Объект может хранить данные — **атрибуты**. Обращение к ним — через точку:

```python
class Dog:
    pass


rex = Dog()
rex.name = "Рекс"
rex.age = 3
print(rex.name, rex.age)
```

```text
Рекс 3
```

Так можно, но это плохая практика: атрибуты появляются у объекта «где попало», и у двух собак может оказаться разный набор полей. Атрибуты должны создаваться в одном месте — при создании объекта.

## __init__: инициализация объекта

Специальный метод `__init__` вызывается **автоматически** при создании объекта. В нём задают начальное состояние:

```python
class Dog:
    def __init__(self, name, age):
        self.name = name
        self.age = age


rex = Dog("Рекс", 3)
bobik = Dog("Бобик", 5)
print(rex.name, rex.age)
print(bobik.name, bobik.age)
```

```text
Рекс 3
Бобик 5
```

Что происходит при `Dog("Рекс", 3)`:

1. Python создаёт новый пустой объект класса `Dog`.
2. Вызывает `__init__`, передавая **этот объект первым аргументом** (`self`), а затем ваши аргументы: `name="Рекс"`, `age=3`.
3. Внутри `__init__` строки `self.name = name` создают атрибуты **у этого объекта**.
4. Готовый объект возвращается и присваивается переменной `rex`.

Двойные подчёркивания с обеих сторон (`__init__`) — признак **специального** («магического», dunder — double underscore) метода, который Python вызывает сам в определённых ситуациях. Вы встретите их десятки: `__str__`, `__len__`, `__eq__` (блок 2.2).

Обратите внимание: `__init__` ничего не возвращает (`return` в нём не пишут). Его задача — настроить уже созданный объект.

## self: «этот объект»

`self` — первый параметр каждого метода; через него метод получает доступ к **конкретному объекту**, для которого вызван. Внутри класса `self.name` значит «атрибут `name` этого объекта».

Имя `self` — соглашение, а не ключевое слово: технически можно назвать параметр иначе, но так не делает никто. Всегда пишите `self`.

Новичков смущает, что `self` есть в определении, но не передаётся при вызове. Дело в том, что вызов `rex.bark()` Python превращает в `Dog.bark(rex)` — объект перед точкой автоматически становится первым аргументом:

```python
class Dog:
    def __init__(self, name):
        self.name = name

    def bark(self):
        return f"{self.name}: Гав!"


rex = Dog("Рекс")
print(rex.bark())
print(Dog.bark(rex))
```

```text
Рекс: Гав!
Рекс: Гав!
```

Обе записи делают одно и то же; первая — привычная и правильная.

## Методы

**Метод** — функция, определённая внутри класса. Она описывает, что умеет объект, и работает с его данными через `self`:

```python
class BankAccount:
    def __init__(self, owner, balance=0):
        self.owner = owner
        self.balance = balance

    def deposit(self, amount):
        if amount <= 0:
            raise ValueError("сумма должна быть положительной")
        self.balance += amount
        return self.balance

    def withdraw(self, amount):
        if amount > self.balance:
            raise ValueError("недостаточно средств")
        self.balance -= amount
        return self.balance

    def describe(self):
        return f"Счёт {self.owner}: {self.balance} руб."


account = BankAccount("Ада", 1000)
account.deposit(500)
account.withdraw(300)
print(account.describe())
other = BankAccount("Алан")
print(other.describe())
```

```text
Счёт Ада: 1200 руб.
Счёт Алан: 0 руб.
```

Методы — обычные функции со всеми возможностями из блока 1.6: параметры по умолчанию, `return`, исключения, docstring. Отличие одно: первый параметр — `self`, через который метод читает и меняет состояние объекта.

Сравните с версией на функциях и словарях:

```python norun
account = {"owner": "Ада", "balance": 1000}
deposit(account, 500)
withdraw(account, 300)
print(describe(account))
```

Разница не в количестве кода, а в организации: в классе всё, что касается счёта, собрано в одном месте; невозможно создать счёт без владельца или забыть поле `balance`; а `account.` в редакторе показывает список всех доступных операций.

## Состояние у каждого объекта своё

Каждый объект хранит **свои** атрибуты. Изменение одного объекта не влияет на другие:

```python
class Counter:
    def __init__(self):
        self.value = 0

    def increment(self):
        self.value += 1


clicks = Counter()
views = Counter()
clicks.increment()
clicks.increment()
views.increment()
print(clicks.value, views.value)
```

```text
2 1
```

Вспомните счётчики-замыкания из блока 1.6 (`make_counter`): там «независимое состояние» требовало вложенных функций и `nonlocal`. С классом это выглядит естественнее — и именно классы стандартный способ хранить состояние в Python.

## Строковое представление: __str__ и __repr__

По умолчанию `print(account)` выводит что-то вроде `<__main__.BankAccount object at 0x7f...>` — бесполезно. Метод `__str__` задаёт, как объект выглядит при печати и в `str()`:

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def __str__(self):
        return f"({self.x}, {self.y})"

    def __repr__(self):
        return f"Point({self.x}, {self.y})"


p = Point(3, 4)
print(p)
print([p, Point(0, 0)])
```

```text
(3, 4)
[Point(3, 4), Point(0, 0)]
```

- `__str__` — «для пользователя»: красивый вывод в `print`;
- `__repr__` — «для разработчика»: однозначное представление, используется в списках, отладчике и консоли. Хороший `__repr__` выглядит как код, создающий такой объект.

## Разбор задачи: история диалога как класс

В блоке 1.5 история диалога с LLM была списком словарей, а операции над ней — разрозненным кодом. Оформим её классом:

```python
class Conversation:
    def __init__(self, system_prompt=None, max_messages=20):
        self.messages = []
        self.max_messages = max_messages
        if system_prompt:
            self.messages.append({"role": "system", "content": system_prompt})

    def add(self, role, content):
        if role not in ("user", "assistant"):
            raise ValueError(f"неизвестная роль: {role}")
        self.messages.append({"role": role, "content": content})
        self._trim()

    def _trim(self):
        has_system = self.messages and self.messages[0]["role"] == "system"
        start = 1 if has_system else 0
        while len(self.messages) > self.max_messages:
            self.messages.pop(start)

    def last_user_message(self):
        for message in reversed(self.messages):
            if message["role"] == "user":
                return message["content"]
        return None


chat = Conversation("Ты — вежливый помощник.", max_messages=3)
chat.add("user", "Привет!")
chat.add("assistant", "Здравствуйте!")
chat.add("user", "Что такое класс?")
print(len(chat.messages), chat.messages[0]["role"])
print(chat.last_user_message())
```

```text
3 system
Что такое класс?
```

Класс прячет детали: обрезку истории с сохранением системного сообщения, проверку ролей, поиск последнего вопроса. Метод `_trim` с подчёркиванием в начале — «внутренний», его не предполагается вызывать снаружи (об этом — в уроке 3). Остальной код программы пользуется простым интерфейсом: `chat.add(...)`, `chat.messages`. Именно так устроены классы истории в LangChain и других библиотеках для LLM.

## Когда нужен класс, а когда — функция

ООП — инструмент, а не религия. Признаки, что пора создать класс:

- есть **данные и операции над ними**, которые всегда используются вместе;
- нужно **состояние**, которое живёт между вызовами (счётчик, история, соединение);
- нужно **много однотипных сущностей** (счета, задачи, документы);
- нужна **иерархия** похожих сущностей (урок 4).

А если есть просто вычисление «данные на входе — результат на выходе» — достаточно функции. Класс с одним методом и без состояния — признак того, что класс не нужен.

## Частые ошибки

**1. Забыть `self` в определении метода.** `def bark():` → при вызове `TypeError: bark() takes 0 positional arguments but 1 was given` — Python передал объект, а принять его некуда.

**2. Забыть `self.` при обращении к атрибуту.** `return name` внутри метода ищет локальную переменную `name`, а не атрибут → `NameError`. Нужно `self.name`.

**3. Создать атрибут без `self`.** `name = name` в `__init__` создаёт локальную переменную, которая исчезнет; атрибута у объекта не будет.

**4. Возвращать значение из `__init__`.** `__init__` должен возвращать `None`; `return что-то` вызовет `TypeError`.

**5. Путать класс и объект.** `BankAccount.deposit(100)` — вызов у класса без объекта. Создайте объект: `account = BankAccount(...)`, затем `account.deposit(100)`.

**6. Опечатка в `__init__`.** `__int__` или `_init_` — Python не вызовет такой метод автоматически, атрибуты не создадутся.

## Где это в AI-инженерии

- **Модели в PyTorch** — классы: `class Classifier(nn.Module)` с `__init__` (создание слоёв) и `forward` (вычисление). Это первое, что вы напишете в блоке 6.2.
- **Клиенты API.** `client = Anthropic(api_key=...)`, затем `client.messages.create(...)` — объект хранит ключ, настройки и соединение, методы выполняют запросы.
- **scikit-learn.** `model = LogisticRegression()`, `model.fit(X, y)`, `model.predict(X)` — объект модели хранит обученные параметры как состояние.
- **Датасеты.** `class ReviewsDataset(Dataset)` с методами `__len__` и `__getitem__` — стандарт загрузки данных в PyTorch.
- **Агенты и инструменты.** Агент — объект с историей, набором инструментов и методом `run(task)`; инструмент — объект с именем, описанием и методом вызова.
- **Pydantic-модели** (блок 2.5) — классы, описывающие структуру данных: запросов, ответов, конфигураций.

## Итоги урока

- Класс — шаблон, объект — экземпляр; `obj = ClassName(аргументы)`.
- `__init__(self, ...)` вызывается при создании и задаёт атрибуты через `self.атрибут = значение`.
- `self` — ссылка на текущий объект; `obj.method()` превращается в `Class.method(obj)`.
- Методы — функции внутри класса, работающие с состоянием через `self`; у каждого объекта своё состояние.
- `__str__` — вывод для пользователя, `__repr__` — для разработчика.
- Класс нужен, когда данные и поведение идут вместе или нужно состояние; иначе — функция.
