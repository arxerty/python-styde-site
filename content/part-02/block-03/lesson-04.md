# yield from и конвейеры генераторов

## yield from: отдать всё из другого источника

Часто генератору нужно выдать все элементы другого итерируемого объекта. Можно написать цикл:

```python
def numbers_and_letters():
    for n in [1, 2, 3]:
        yield n
    for ch in "ab":
        yield ch


print(list(numbers_and_letters()))
```

```text
[1, 2, 3, 'a', 'b']
```

Конструкция `yield from` делает то же короче — она **делегирует** перебор другому итерируемому объекту и выдаёт все его элементы по одному:

```python
def numbers_and_letters():
    yield from [1, 2, 3]
    yield from "ab"
    yield "конец"


print(list(numbers_and_letters()))
```

```text
[1, 2, 3, 'a', 'b', 'конец']
```

`yield from` принимает что угодно итерируемое: список, строку, `range`, другой генератор. Ленивость сохраняется: элементы выдаются по одному, по мере запроса.

## Склеивание и разворачивание

Типичное применение — объединить несколько источников или «развернуть» вложенную структуру на один уровень:

```python
def chain_all(*sources):
    for source in sources:
        yield from source


def flatten(nested):
    for inner in nested:
        yield from inner


print(list(chain_all([1, 2], (3,), range(4, 6))))
print(list(flatten([["a", "b"], [], ["c"]])))
```

```text
[1, 2, 3, 4, 5]
['a', 'b', 'c']
```

В следующем уроке вы увидите, что для этих задач в стандартной библиотеке есть готовые `itertools.chain` и `chain.from_iterable`. Но понимать, как они устроены, полезно.

## Рекурсивные генераторы

`yield from` особенно хорош для **рекурсивных** структур — деревьев любой глубины. Генератор вызывает сам себя для вложенных частей и пробрасывает их элементы наверх:

```python
def deep_flatten(items):
    for item in items:
        if isinstance(item, list):
            yield from deep_flatten(item)
        else:
            yield item


data = [1, [2, [3, [4, 5]], 6], [[7]], 8]
print(list(deep_flatten(data)))
```

```text
[1, 2, 3, 4, 5, 6, 7, 8]
```

Каждый уровень вложенности — отдельный генератор, а `yield from` передаёт элементы с самых глубоких уровней наверх по цепочке. Тот же приём работает для обхода файловой системы, JSON-документов и деревьев решений:

```python
config = {
    "model": {"name": "bert", "layers": 12},
    "train": {"lr": 0.001, "schedule": {"warmup": 100}},
    "seed": 42,
}


def walk(tree, prefix=""):
    for key, value in tree.items():
        path = f"{prefix}.{key}" if prefix else key
        if isinstance(value, dict):
            yield from walk(value, path)
        else:
            yield path, value


for path, value in walk(config):
    print(f"{path} = {value}")
```

```text
model.name = bert
model.layers = 12
train.lr = 0.001
train.schedule.warmup = 100
seed = 42
```

Функция `walk` превращает вложенную конфигурацию в плоский поток пар «путь — значение» — так конфиги экспериментов логируют в системы отслеживания вроде MLflow.

## Конвейеры генераторов

Главная сила генераторов раскрывается, когда их соединяют в **конвейер** (pipeline): каждый генератор принимает поток от предыдущего, что-то с ним делает и передаёт дальше. Это похоже на конвейер на заводе или на `|` в командной строке Unix.

Типичные звенья:

- **источник** — производит поток (чтение файла, запросы к API, список);
- **фильтр** — пропускает часть элементов;
- **преобразователь** — меняет каждый элемент;
- **потребитель** — собирает результат (`list`, `sum`, запись в файл).

```python
def read(lines):
    for line in lines:
        yield line


def strip_empty(lines):
    for line in lines:
        line = line.strip()
        if line:
            yield line


def lowercase(lines):
    for line in lines:
        yield line.lower()


def unique(lines):
    seen = set()
    for line in lines:
        if line not in seen:
            seen.add(line)
            yield line


raw = ["  Привет ", "", "МИР", "привет", "  ", "Python"]
pipeline = unique(lowercase(strip_empty(read(raw))))
print(list(pipeline))
```

```text
['привет', 'мир', 'python']
```

Каждое звено — маленькая функция с одной обязанностью, которую легко понять и протестировать отдельно. Звенья переставляются и комбинируются как кубики: чтобы убрать приведение к нижнему регистру, достаточно убрать одно звено.

## Конвейер ленив от начала до конца

Важнейшее свойство: элементы проходят конвейер **по одному**. Первый элемент проходит все стадии прежде, чем источник прочитает второй. Добавим отладочные сообщения:

```python
def source():
    for n in [1, 2, 3]:
        print(f"источник: {n}")
        yield n


def double(numbers):
    for n in numbers:
        print(f"  удвоение: {n}")
        yield n * 2


def only_big(numbers):
    for n in numbers:
        if n > 2:
            print(f"    прошло: {n}")
            yield n


for result in only_big(double(source())):
    print(f"      результат: {result}")
```

```text
источник: 1
  удвоение: 1
источник: 2
  удвоение: 2
    прошло: 4
      результат: 4
источник: 3
  удвоение: 3
    прошло: 6
      результат: 6
```

Никакая стадия не хранит весь поток. В памяти одновременно находится по одному элементу на каждом звене (плюс состояние вроде множества `seen` в `unique`). Поэтому конвейер одинаково работает со списком из шести строк и с файлом на сто гигабайт.

Сравните с подходом «списками»: каждая стадия создавала бы полный промежуточный список, и для большого файла понадобилось бы в несколько раз больше памяти, чем занимает сам файл.

## Конвейер из генераторных выражений

Простые звенья можно записывать генераторными выражениями — конвейер становится совсем компактным:

```python
lines = ["ERROR db timeout", "INFO ok", "ERROR api 500", "WARN slow", "ERROR db lost"]

errors = (line for line in lines if line.startswith("ERROR"))
components = (line.split()[1] for line in errors)
counts = {}
for component in components:
    counts[component] = counts.get(component, 0) + 1
print(counts)
```

```text
{'db': 2, 'api': 1}
```

`errors` и `components` ничего не вычисляют, пока цикл `for` не начнёт забирать элементы. Для сложных звеньев (с состоянием, несколькими условиями, обработкой ошибок) лучше генераторные функции — они читаются легче и тестируются по отдельности.

## Как проектировать звенья

Несколько правил, которые делают конвейеры удобными в работе.

**Одно звено — одна обязанность.** Звено «очистить, отфильтровать и посчитать» трудно переиспользовать и тестировать. Три маленьких звена комбинируются как угодно.

**Звено принимает итерируемый объект и возвращает итератор.** Тогда любое звено можно подключить к любому источнику: списку в тесте, файлу в продакшене, другому звену. Не делайте звенья, которые принимают путь к файлу, — пусть файл открывает источник.

**Параметры — после потока.** `min_words(lines, n)` читается естественно и позволяет добавить параметры по умолчанию.

**Состояние — только необходимое.** Фильтр и преобразователь не хранят ничего, кроме текущего элемента. Если звену нужна память (дедупликация, скользящее среднее), подумайте, может ли она расти бесконечно.

**Ошибки — осознанно.** Решите заранее, что звено делает с некорректным элементом: пропускает, исправляет или бросает исключение. Для больших датасетов обычно пропускают и считают пропущенное, чтобы одна битая строка не останавливала обработку миллиона хороших.

## Значение, которое возвращает yield from

Тонкость для любознательных: если подгенератор завершился через `return значение`, то выражение `yield from` **возвращает** это значение. Так генератор может одновременно выдавать поток и сообщать итог:

```python
def count_valid(items):
    valid = 0
    for item in items:
        if item.isdigit():
            valid += 1
            yield int(item)
    return valid


def process(items):
    total = yield from count_valid(items)
    print(f"корректных значений: {total}")


print(list(process(["1", "x", "22", "3"])))
```

```text
корректных значений: 3
[1, 22, 3]
```

В повседневном коде это встречается редко, но объясняет, зачем `return` с значением вообще разрешён в генераторах.

## Разбор задачи: подготовка корпуса для обучения

Перед обучением языковой модели или классификатора тексты проходят предобработку: чтение из нескольких файлов, очистку, фильтрацию по длине, дедупликацию и токенизацию. Соберём такой конвейер:

```python
import re

files = {
    "part1.txt": "Генераторы экономят память.\n\nГенераторы экономят память.\nОк\n",
    "part2.txt": "Конвейеры   легко   расширять!\nhttp://spam.example — купите\n",
}
for name, text in files.items():
    with open(name, "w", encoding="utf-8") as f:
        f.write(text)


def read_files(paths):
    for path in paths:
        with open(path, encoding="utf-8") as file:
            yield from file


def clean(lines):
    for line in lines:
        line = re.sub(r"\s+", " ", line).strip()
        if line and "http" not in line:
            yield line


def min_words(lines, n):
    return (line for line in lines if len(line.split()) >= n)


def deduplicate(lines):
    seen = set()
    for line in lines:
        key = line.lower()
        if key not in seen:
            seen.add(key)
            yield line


def tokenize(lines):
    for line in lines:
        yield re.findall(r"\w+", line.lower())


corpus = tokenize(deduplicate(min_words(clean(read_files(files)), 2)))
for tokens in corpus:
    print(tokens)
```

```text
['генераторы', 'экономят', 'память']
['конвейеры', 'легко', 'расширять']
```

Разберём, что произошло со строками:

- `read_files` с `yield from file` склеил строки двух файлов в один поток;
- `clean` сжал повторяющиеся пробелы регулярным выражением (блок 1.4) и отбросил пустые строки и строки со ссылками;
- `min_words` (генераторное выражение) отсеял «Ок» — слишком короткую строку;
- `deduplicate` убрал повтор; ключ в нижнем регистре делает сравнение нечувствительным к регистру;
- `tokenize` разбил строки на слова.

Каждое звено можно протестировать на маленьком списке строк, а весь конвейер работает с корпусом любого размера: в памяти — одна строка и множество уже встреченных строк. Для очень больших корпусов вместо множества строк хранят их хеши, чтобы сэкономить память.

## Частые ошибки

**1. `yield` вместо `yield from`.** `yield inner_list` выдаст список целиком одним элементом, а не его элементы по одному.

**2. Рекурсия без `yield from`.** Вызов `deep_flatten(item)` без `yield from` создаёт генератор и выбрасывает его — вложенные элементы потеряются.

**3. Стадия, превращающая поток в список.** Одно звено с `list(lines)` или `sorted(lines)` внутри ломает ленивость всего конвейера: весь поток окажется в памяти.

**4. Повторное использование конвейера.** Конвейер — цепочка генераторов, он одноразовый. Для второго прохода соберите его заново.

**5. Исчерпание общего источника.** Если два конвейера построены на одном генераторе-источнике, первый «съест» элементы второго.

**6. Бесконечный рост состояния.** Звено `unique` с множеством растёт с каждым уникальным элементом. Для бесконечных потоков ограничивайте состояние (например, хранят только последние N ключей).

## Где это в AI-инженерии

- **Предобработка корпусов** для обучения моделей — классический конвейер: чтение шардов, очистка, фильтрация качества, дедупликация, токенизация.
- **Загрузка документов в RAG**: обход папок рекурсивным генератором, чтение, разбиение на чанки, вычисление эмбеддингов батчами — всё лениво, чтобы не держать базу знаний в памяти.
- **Hugging Face `datasets`** со `streaming=True` и цепочками `.filter().map()` — те же ленивые конвейеры.
- **torch.utils.data** в режиме `IterableDataset` строит поток примеров генераторами: чтение, аугментация, перемешивание в буфере.
- **Логирование конфигураций**: «расплющивание» вложенных конфигов в пары путь–значение для систем отслеживания экспериментов.

## Итоги урока

- `yield from iterable` выдаёт все элементы другого итерируемого объекта, сохраняя ленивость.
- Рекурсивные генераторы с `yield from` обходят деревья любой глубины.
- Конвейер генераторов: источник → фильтры и преобразователи → потребитель; каждое звено — маленькая функция.
- Элементы проходят конвейер по одному: память не зависит от размера потока.
- Звено, превращающее поток в список, разрушает ленивость всего конвейера.
- `result = yield from gen` получает значение из `return` подгенератора.
