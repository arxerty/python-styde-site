# Функции как объекты, функции высшего порядка

## Функция — такой же объект, как число

В Python всё является объектом — и функции тоже. С функцией можно делать то же, что с числом или строкой: присвоить переменной, положить в список или словарь, передать в другую функцию и вернуть из функции. Говорят, что функции в Python — **объекты первого класса** (first-class objects).

```python
def greet(name):
    """Поприветствовать по имени."""
    return f"Привет, {name}!"


say_hello = greet
print(say_hello("Ада"))
print(say_hello is greet)
print(type(greet).__name__)
print(greet.__name__, "|", greet.__doc__)
```

```text
Привет, Ада!
True
function
greet | Поприветствовать по имени.
```

- `say_hello = greet` — **без скобок**: функция не вызывается, появляется ещё одно имя для того же объекта. Поэтому `say_hello is greet` — `True`.
- `greet("Ада")` — **со скобками**: вызов функции, результат — строка.
- У функции есть атрибуты: `__name__` (имя, под которым её объявили), `__doc__` (docstring) и другие.

Различие между `greet` (объект функции) и `greet()` (результат вызова) — ключ ко всему этому блоку. Почти все ошибки с декораторами и колбэками сводятся к лишним или забытым скобкам.

## Функции в коллекциях

Раз функция — объект, её можно хранить в списке или словаре. Список функций — это готовый конвейер обработки:

```python
def strip_spaces(text):
    return text.strip()


def lowercase(text):
    return text.lower()


def remove_exclamations(text):
    return text.replace("!", "")


steps = [strip_spaces, lowercase, remove_exclamations]
text = "  Отличный Продукт!!! "
for step in steps:
    text = step(text)
    print(f"{step.__name__:20} → {text!r}")
```

```text
strip_spaces         → 'Отличный Продукт!!!'
lowercase            → 'отличный продукт!!!'
remove_exclamations  → 'отличный продукт'
```

Порядок шагов задаётся данными (списком), а не кодом: шаг можно добавить, убрать или переставить, не трогая цикл.

## Таблица диспетчеризации вместо if/elif

Словарь «имя → функция» заменяет длинные цепочки `if/elif`. Такой словарь называют **таблицей диспетчеризации** (dispatch table):

```python
def mean(values):
    return sum(values) / len(values)


def spread(values):
    return max(values) - min(values)


METRICS = {
    "mean": mean,
    "max": max,
    "min": min,
    "spread": spread,
}


def compute(name, values):
    if name not in METRICS:
        raise ValueError(f"неизвестная метрика {name!r}, доступны: {sorted(METRICS)}")
    return METRICS[name](values)


scores = [0.82, 0.91, 0.77]
for name in ("mean", "spread", "max"):
    print(name, round(compute(name, scores), 3))
```

```text
mean 0.833
spread 0.14
max 0.91
```

Обратите внимание: в словарь попали и свои функции (`mean`), и встроенные (`max`, `min`) — для Python они одинаково «функции». Новая метрика — одна строка в словаре. Так устроены реестры метрик, функций потерь и инструментов агентов: имя приходит из конфигурации, а код находит по нему функцию.

## Функции высшего порядка

**Функция высшего порядка** (higher-order function) — функция, которая принимает другую функцию как аргумент или возвращает функцию. Вы ими уже пользовались:

```python
words = ["Python", "ai", "Нейросеть", "ML", "данные"]
print(sorted(words, key=len))
print(sorted(words, key=str.lower))
print(list(map(str.upper, words[:2])))
print(list(filter(str.isascii, words)))
print(max(words, key=len))
```

```text
['ai', 'ML', 'Python', 'данные', 'Нейросеть']
['ai', 'ML', 'Python', 'данные', 'Нейросеть']
['PYTHON', 'AI']
['Python', 'ai', 'ML']
Нейросеть
```

`sorted`, `max`, `min` с параметром `key`, а также `map` и `filter` — функции высшего порядка. Аргумент `key=len` передаёт функцию `len` (без скобок!), и `sorted` вызывает её для каждого элемента. Метод тоже можно передать: `str.lower` — это функция, которая принимает строку.

## Свои функции высшего порядка

Написать функцию, принимающую функцию, просто — внутри её вызывают как обычно:

```python
def apply_n_times(func, value, n):
    for _ in range(n):
        value = func(value)
    return value


def retry_until(func, condition, attempts):
    for attempt in range(1, attempts + 1):
        result = func(attempt)
        if condition(result):
            return attempt, result
    return None


print(apply_n_times(lambda x: x * 2, 1, 10))
print(apply_n_times(str.strip, "  текст  ", 1))
print(retry_until(lambda n: n * n, lambda r: r > 20, attempts=10))
```

```text
1024
текст
(5, 25)
```

`retry_until` не знает, что делает `func` и что проверяет `condition`, — ей передают поведение снаружи. Это паттерн «Стратегия» из блока 2.2, только стратегия — функция, а не объект.

## lambda: короткая анонимная функция

`lambda параметры: выражение` создаёт функцию без имени — удобно для коротких одноразовых функций, которые передаются аргументом (вы встречали их в блоке 1.6):

```python
students = [("Ада", 92), ("Алан", 85), ("Грейс", 97)]
print(sorted(students, key=lambda pair: pair[1], reverse=True)[0])

double = lambda x: x * 2
print(double(21), double.__name__)
```

```text
('Грейс', 97)
42 <lambda>
```

Ограничения lambda: тело — **одно выражение**, без `if`-блоков, циклов, `return` и присваиваний; у неё нет нормального имени (`<lambda>` в трассировках ошибок). Присваивать lambda переменной, как `double` выше, PEP 8 не рекомендует — для именованной функции пишите `def`. Lambda хороша только «на месте», как аргумент.

## Функция, возвращающая функцию

Функция может создать внутри себя другую функцию и вернуть её:

```python
def make_multiplier(factor):
    def multiply(x):
        return x * factor
    return multiply


double = make_multiplier(2)
triple = make_multiplier(3)
print(double(10), triple(10))
print(double.__name__)
```

```text
20 30
multiply
```

Вызов `make_multiplier(2)` возвращает новую функцию `multiply`, которая «помнит» значение `factor = 2`, хотя `make_multiplier` уже завершилась. Это **замыкание** — тема следующего урока. А функция, которая принимает функцию и возвращает новую функцию, — это **декоратор** (урок 3). Весь блок строится на этих двух идеях.

## Вызываемые объекты: __call__

Вызвать можно не только функцию. Объект любого класса с методом `__call__` тоже **вызываемый** (callable): `obj(аргументы)` вызывает `obj.__call__(аргументы)`. Встроенная функция `callable(x)` проверяет, можно ли вызвать объект:

```python
class Threshold:
    def __init__(self, limit):
        self.limit = limit
        self.calls = 0

    def __call__(self, value):
        self.calls += 1
        return value >= self.limit


is_good = Threshold(0.8)
print(list(filter(is_good, [0.5, 0.85, 0.9, 0.7])))
print(is_good.calls, callable(is_good), callable(42), callable(len))
```

```text
[0.85, 0.9]
4 True False True
```

Вызываемый объект подходит везде, где ожидается функция, — например, в `filter`. При этом у него есть состояние (`calls`) и методы. Модели PyTorch — вызываемые объекты: `model(x)` вызывает `model.__call__(x)`, который внутри запускает ваш метод `forward`.

## Зачем передавать поведение параметром

Все приёмы этого урока решают одну задачу: отделить **неизменную часть** алгоритма от **изменяемой**. Сортировка всегда одинакова, меняется только правило сравнения — его передают через `key`. Цикл обучения всегда одинаков, меняется только то, что делать после эпохи, — это передают колбэками. Конвейер обработки текста одинаков, меняется только набор шагов — их передают списком функций.

Такое разделение даёт три преимущества. Во-первых, общий код пишется и тестируется один раз. Во-вторых, новое поведение добавляется без правки существующего кода — достаточно написать новую функцию и передать её. В-третьих, поведение можно выбирать во время работы программы: по настройке из конфигурации, по имени из запроса пользователя или модели.

Обратная сторона — косвенность: читая `METRICS[name](values)`, нельзя сразу увидеть, какая функция вызовется. Поэтому реестры и колбэки стоит документировать и давать функциям говорящие имена.

## Разбор задачи: колбэки цикла обучения

Цикл обучения модели повторяется в каждом проекте, а вот что делать во время обучения — логировать, сохранять лучшую модель, останавливаться раньше — меняется. Решение: цикл принимает список **колбэков** (callback) — функций или вызываемых объектов, которые он вызывает после каждой эпохи.

```python
def train(epochs, losses, callbacks):
    history = []
    for epoch in range(1, epochs + 1):
        loss = losses[epoch - 1]
        history.append(loss)
        for callback in callbacks:
            if callback(epoch, loss) == "stop":
                return history, f"остановлено после эпохи {epoch}"
    return history, "все эпохи пройдены"


def print_progress(epoch, loss):
    print(f"эпоха {epoch}: loss={loss}")


class EarlyStopping:
    def __init__(self, patience):
        self.patience = patience
        self.best = float("inf")
        self.bad_epochs = 0

    def __call__(self, epoch, loss):
        if loss < self.best:
            self.best = loss
            self.bad_epochs = 0
        else:
            self.bad_epochs += 1
            if self.bad_epochs >= self.patience:
                return "stop"


losses = [1.0, 0.7, 0.6, 0.65, 0.66, 0.5]
history, status = train(6, losses, [print_progress, EarlyStopping(patience=2)])
print(status, history)
```

```text
эпоха 1: loss=1.0
эпоха 2: loss=0.7
эпоха 3: loss=0.6
эпоха 4: loss=0.65
эпоха 5: loss=0.66
остановлено после эпохи 5 [1.0, 0.7, 0.6, 0.65, 0.66]
```

Цикл `train` ничего не знает о логировании и ранней остановке — это поведение передано снаружи. Колбэк-функция `print_progress` не хранит состояние, а `EarlyStopping` — вызываемый объект, которому нужно помнить лучший результат и число неудачных эпох. Для цикла они неразличимы: оба просто вызываются с `(epoch, loss)`. Ровно так устроены колбэки в Keras, PyTorch Lightning и Hugging Face Trainer.

## Частые ошибки

**1. Вызов вместо передачи.** `sorted(words, key=len())` — `TypeError`, потому что `len()` вызывается сразу. Передавайте функцию без скобок: `key=len`.

**2. Передача без вызова там, где нужен результат.** `if is_valid:` вместо `if is_valid(x):` — функция-объект всегда истинна, условие выполнится всегда.

**3. Сложная логика в lambda.** Lambda с вложенными тернарными операторами нечитаема. Если не помещается в короткое выражение — `def`.

**4. Присваивание lambda переменной.** `square = lambda x: x * x` — пишите `def square(x):`, у функции будет нормальное имя в трассировках.

**5. Изменяемые колбэки, используемые повторно.** Объект `EarlyStopping` хранит состояние; если передать тот же объект во второй запуск обучения, он «помнит» первый. Создавайте новый.

**6. Неверная сигнатура функции-аргумента.** Если цикл вызывает `callback(epoch, loss)`, а колбэк объявлен как `def cb(loss)`, будет `TypeError`. Договоритесь об интерфейсе, как с протоколами в блоке 2.2.

## Где это в AI-инженерии

- **Колбэки обучения** в Keras, PyTorch Lightning и Hugging Face Trainer: логирование, ранняя остановка, сохранение чекпоинтов, изменение learning rate.
- **Реестры** метрик, функций потерь и активаций: `{"relu": relu, "gelu": gelu}` — выбор по имени из конфигурации.
- **Инструменты агентов**: агенту передают функции-инструменты; фреймворки читают их `__name__` и `__doc__`, чтобы описать инструмент модели.
- **Предобработка**: список функций-шагов, применяемых к каждому тексту, — как `steps` в уроке; `dataset.map(func)` в Hugging Face принимает функцию.
- **Модели PyTorch** — вызываемые объекты: `model(x)` вызывает `__call__`, а тот — `forward`.

## Итоги урока

- Функции — объекты: их присваивают, хранят в коллекциях, передают и возвращают; `f` — объект, `f()` — вызов.
- Словарь функций заменяет цепочки `if/elif` (таблица диспетчеризации, реестр).
- Функции высшего порядка принимают или возвращают функции: `sorted(key=...)`, `map`, `filter`, свои.
- `lambda` — для коротких функций-аргументов; для всего остального — `def`.
- Функция может вернуть функцию — основа замыканий и декораторов.
- Объект с `__call__` вызываемый и может хранить состояние; `callable(x)` проверяет возможность вызова.
