# Декораторы: как работают, functools.wraps

## Задача: добавить поведение, не меняя функцию

Представьте, что в проекте сотня функций, обращающихся к API, и нужно логировать каждый вызов: имя функции, аргументы и результат. Можно дописать `print` в каждую функцию — сотня одинаковых правок, смешанных с основной логикой. Потом логирование захотят отключить, или добавить замер времени, или повторные попытки при ошибках...

**Декоратор** — способ «обернуть» функцию дополнительным поведением, не изменяя её код. Вы уже знаете всё, что нужно для его понимания: функции — объекты (урок 1), а вложенная функция помнит переменные внешней (урок 2).

## Декоратор вручную

Декоратор — это функция, которая принимает функцию и возвращает новую функцию-**обёртку** (wrapper):

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        print(f"→ вызов {func.__name__}{args}")
        result = func(*args, **kwargs)
        print(f"← {func.__name__} вернула {result!r}")
        return result
    return wrapper


def add(a, b):
    return a + b


add = log_calls(add)
print(add(2, 3))
```

```text
→ вызов add(2, 3)
← add вернула 5
5
```

Разберём строку `add = log_calls(add)`:

1. `log_calls` получает исходную функцию `add` как `func`;
2. создаёт `wrapper`, который замыкает `func`, и возвращает его;
3. имя `add` теперь указывает на `wrapper`.

При вызове `add(2, 3)` на самом деле выполняется `wrapper(2, 3)`: он печатает сообщение, вызывает **исходную** функцию через `func(*args, **kwargs)`, печатает результат и возвращает его.

Три обязательных элемента обёртки:

- `*args, **kwargs` — принять **любые** аргументы, чтобы декоратор подходил к любой функции;
- `func(*args, **kwargs)` — передать их исходной функции без изменений;
- `return result` — вернуть результат, иначе декорированная функция будет возвращать `None`.

## Синтаксис @

Запись `add = log_calls(add)` после определения функции неудобна: её легко забыть, и при чтении определения не видно, что функция будет обёрнута. Поэтому в Python есть специальный синтаксис — строка `@декоратор` над `def`:

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        print(f"{func.__name__}{args} = {result}")
        return result
    return wrapper


@log_calls
def multiply(a, b):
    return a * b


@log_calls
def greet(name, punctuation="!"):
    return f"Привет, {name}{punctuation}"


multiply(6, 7)
greet("Ада", punctuation="?")
```

```text
multiply(6, 7) = 42
greet('Ада',) = Привет, Ада?
```

`@log_calls` над `def multiply` — в точности то же самое, что `multiply = log_calls(multiply)` сразу после определения. Это лишь синтаксический сахар. Обратите внимание: именованный аргумент `punctuation` попал в `kwargs`, поэтому в `args` только `('Ада',)`.

## Когда выполняется декоратор

Важный момент: декоратор выполняется **один раз, в момент определения функции**, а не при каждом вызове. При каждом вызове выполняется обёртка.

```python
def announce(func):
    print(f"декорирую {func.__name__}")

    def wrapper(*args, **kwargs):
        print(f"вызываю {func.__name__}")
        return func(*args, **kwargs)

    return wrapper


@announce
def task():
    return "готово"


print("--- функция определена ---")
print(task())
print(task())
```

```text
декорирую task
--- функция определена ---
вызываю task
готово
вызываю task
готово
```

Код в теле декоратора (вне `wrapper`) срабатывает при импорте модуля. Это используют для **регистрации** функций — об этом ниже.

## Проблема: потерянное имя и docstring

У обёртки есть неприятный побочный эффект — декорированная функция «теряет» своё имя и документацию:

```python
def log_calls(func):
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper


@log_calls
def search(query):
    """Найти документы по запросу."""
    return []


print(search.__name__)
print(search.__doc__)
```

```text
wrapper
None
```

Теперь `search` — это `wrapper`: в трассировках ошибок, логах и документации будет «wrapper», а `help(search)` не покажет описание. Для LLM-агентов это критично: фреймворки описывают инструмент модели по `__name__` и `__doc__` функции.

## functools.wraps

Решение — декоратор `functools.wraps`, который копирует метаданные исходной функции (`__name__`, `__doc__`, `__module__` и другие) на обёртку:

```python
from functools import wraps


def log_calls(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return func(*args, **kwargs)
    return wrapper


@log_calls
def search(query):
    """Найти документы по запросу."""
    return []


print(search.__name__)
print(search.__doc__)
print(search.__wrapped__.__name__)
```

```text
search
Найти документы по запросу.
search
```

`@wraps(func)` — декоратор с аргументом (как такие устроены, разберём в следующем уроке), применённый к `wrapper`. Он также добавляет атрибут `__wrapped__` — ссылку на исходную функцию, через которую можно добраться до неё в обход обёртки (полезно в тестах).

**Правило: каждая обёртка в декораторе помечается `@wraps(func)`.** Это стандарт, и линтеры напоминают о нём.

## Несколько декораторов

Декораторы можно накладывать друг на друга. Применяются они **снизу вверх** (ближайший к `def` — первым), а при вызове обёртки выполняются **сверху вниз**:

```python
from functools import wraps


def bold(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<b>{func(*args, **kwargs)}</b>"
    return wrapper


def italic(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        return f"<i>{func(*args, **kwargs)}</i>"
    return wrapper


@bold
@italic
def title(text):
    return text.upper()


print(title("отчёт"))
```

```text
<b><i>ОТЧЁТ</i></b>
```

`@bold @italic def title` эквивалентно `title = bold(italic(title))`: сначала `italic` оборачивает исходную функцию, затем `bold` оборачивает результат. Внешний декоратор — верхний. Порядок важен: например, декоратор кэширования снаружи декоратора логирования не даст логировать повторные вызовы, а внутри — даст.

## Декоратор без обёртки: регистрация

Декоратор не обязан создавать обёртку. Он может «отметить» функцию — например, записать её в реестр — и вернуть **ту же самую** функцию:

```python
TOOLS = {}


def tool(func):
    TOOLS[func.__name__] = func
    return func


@tool
def get_weather(city):
    """Узнать погоду в городе."""
    return f"В городе {city} солнечно"


@tool
def add_numbers(a, b):
    """Сложить два числа."""
    return a + b


for name, func in TOOLS.items():
    print(f"{name}: {func.__doc__}")
print(TOOLS["add_numbers"](2, 3))
```

```text
get_weather: Узнать погоду в городе.
add_numbers: Сложить два числа.
5
```

Функции регистрируются в момент определения — достаточно поставить `@tool`. Так устроены маршруты в веб-фреймворках (`@app.get("/users")` в FastAPI) и инструменты агентов во многих LLM-фреймворках: модель получает список инструментов с описаниями из docstring.

## Состояние в декораторе

Обёртка — замыкание, поэтому может хранить состояние. Удобный приём — хранить его в атрибуте самой обёртки (функция — объект, ей можно задать атрибуты):

```python
from functools import wraps


def count_calls(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        wrapper.calls += 1
        return func(*args, **kwargs)

    wrapper.calls = 0
    return wrapper


@count_calls
def embed(text):
    return [len(text)]


embed("a")
embed("bb")
print(embed.calls, embed.__name__)
```

```text
2 embed
```

Счётчик доступен снаружи как `embed.calls` — без глобальных переменных. У каждой декорированной функции свой счётчик, потому что каждый вызов `count_calls` создаёт новую обёртку.

## Когда стоит писать декоратор

Декоратор хорош для **сквозной функциональности** (cross-cutting concerns) — поведения, которое нужно многим функциям и не относится к их основной задаче: логирование, замер времени, проверка прав доступа, кэширование, повторные попытки, валидация аргументов, трассировка. Если такую логику вписать в каждую функцию, она перемешается с основным кодом и будет многократно продублирована.

Признаки, что декоратор уместен: одно и то же «до вызова» или «после вызова» повторяется в нескольких функциях; поведение нужно включать и выключать, не трогая функции; это поведение можно описать одной фразой («логировать вызовы», «повторять при ошибке»).

Признаки, что не стоит: логика нужна в одной функции; декоратор должен знать устройство конкретной функции и лезть в её аргументы по именам; поведение настолько важно для понимания функции, что его не должно быть «спрятано» над `def`. Помните: декоратор делает код короче, но добавляет косвенность — читателю придётся заглянуть в определение декоратора, чтобы понять, что на самом деле происходит при вызове.

## Разбор задачи: валидация и логирование инструментов агента

Агент вызывает функции-инструменты с аргументами, которые сгенерировала модель, — а модель может ошибиться. Напишем два декоратора: первый проверяет, что все аргументы — непустые строки, второй ведёт журнал вызовов. Сложим их вместе и посмотрим на порядок.

```python
from functools import wraps

CALL_LOG = []


def require_strings(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        for value in (*args, *kwargs.values()):
            if not isinstance(value, str) or not value.strip():
                return f"ошибка: {func.__name__} ожидает непустые строки, получено {value!r}"
        return func(*args, **kwargs)
    return wrapper


def logged(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        result = func(*args, **kwargs)
        CALL_LOG.append((func.__name__, args, result))
        return result
    return wrapper


@logged
@require_strings
def translate(text, target):
    """Перевести текст на целевой язык."""
    return f"[{target}] {text}"


print(translate("привет", "en"))
print(translate("привет", ""))
print(translate.__name__, "|", translate.__doc__)
print(len(CALL_LOG), CALL_LOG[-1][2])
```

```text
[en] привет
ошибка: translate ожидает непустые строки, получено ''
translate | Перевести текст на целевой язык.
2 ошибка: translate ожидает непустые строки, получено ''
```

Что здесь важно:

- `(*args, *kwargs.values())` объединяет позиционные и именованные аргументы в один кортеж для проверки;
- при ошибке инструмент **не падает**, а возвращает понятное сообщение — модель агента прочитает его и попробует исправить вызов;
- `logged` снаружи, поэтому журналирует и неудачные вызовы: он видит результат обёртки `require_strings`. Поменяйте декораторы местами — и в журнал попадут только прошедшие проверку вызовы;
- благодаря `@wraps` у `translate` сохранились имя и docstring — по ним агент узнает, что делает инструмент.

## Частые ошибки

**1. Вызов вместо передачи.** `return wrapper()` вместо `return wrapper` — декоратор вернёт результат вызова (часто `None`), и декорированное имя перестанет быть функцией.

**2. Забытый `return` в обёртке.** `func(*args, **kwargs)` без `return` → декорированная функция всегда возвращает `None`.

**3. Обёртка без `*args, **kwargs`.** `def wrapper(x):` сломается на функциях с другим числом аргументов или с именованными аргументами.

**4. Нет `@wraps(func)`.** Функция теряет `__name__` и `__doc__`: путаница в логах, трассировках и описаниях инструментов.

**5. Неверный порядок декораторов.** Внешний (верхний) декоратор видит результат внутренних. Проверка аргументов, кэш, логирование и повторные попытки дают разный эффект в разном порядке.

**6. Тяжёлая работа в теле декоратора вне обёртки.** Этот код выполняется при импорте модуля, даже если функцию никогда не вызовут.

## Где это в AI-инженерии

- **Инструменты агентов**: декораторы вроде `@tool` регистрируют функцию и строят её описание для модели из имени, docstring и аргументов — без `@wraps` у обёрнутых инструментов описание терялось бы.
- **FastAPI** (часть 8): `@app.post("/chat")` регистрирует функцию как обработчик HTTP-запроса — декоратор-регистратор.
- **PyTorch**: `@torch.no_grad()` отключает вычисление градиентов на время вызова функции инференса.
- **Наблюдаемость LLM-приложений**: декораторы трассировки (`@traceable` в LangSmith, `@observe` в Langfuse) записывают входы, выходы и время каждого шага.
- **Тесты**: `@pytest.fixture` и `@pytest.mark.parametrize` (блок 2.8) — декораторы.

## Итоги урока

- Декоратор — функция, которая принимает функцию и возвращает новую (обычно обёртку).
- `@deco` над `def f` — то же, что `f = deco(f)`; выполняется один раз при определении.
- Обёртка: `*args, **kwargs` → вызов `func(*args, **kwargs)` → `return result`.
- `@functools.wraps(func)` над обёрткой сохраняет `__name__`, `__doc__` и добавляет `__wrapped__`.
- Несколько декораторов применяются снизу вверх; внешний видит результат внутренних.
- Декоратор может не оборачивать, а регистрировать функцию; состояние удобно хранить в атрибутах обёртки.
