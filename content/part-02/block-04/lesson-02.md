# Замыкания и nonlocal

## Вспомним области видимости

Когда Python встречает имя переменной, он ищет его по правилу **LEGB** (блок 1.6):

1. **L**ocal — локальные переменные текущей функции;
2. **E**nclosing — переменные объемлющих функций (если функция вложена в другую);
3. **G**lobal — переменные модуля;
4. **B**uiltins — встроенные имена (`len`, `print`).

В этом уроке нас интересует буква **E**: вложенная функция видит переменные функции, внутри которой объявлена.

```python
def outer():
    message = "из внешней функции"

    def inner():
        return f"inner видит: {message}"

    return inner()


print(outer())
```

```text
inner видит: из внешней функции
```

Ничего удивительного: `inner` вызывается, пока `outer` ещё работает, и переменная `message` существует. Интересное начинается, когда внутренняя функция **переживает** внешнюю.

## Замыкание: функция с памятью

Вернём внутреннюю функцию наружу, не вызывая её:

```python
def make_greeter(greeting):
    def greet(name):
        return f"{greeting}, {name}!"
    return greet


hello = make_greeter("Привет")
good_morning = make_greeter("Доброе утро")
print(hello("Ада"))
print(good_morning("Алан"))
```

```text
Привет, Ада!
Доброе утро, Алан!
```

Когда мы вызываем `hello("Ада")`, функция `make_greeter` давно завершилась. По обычной логике её локальная переменная `greeting` должна была исчезнуть. Но `greet` её помнит — и у `hello` и `good_morning` значения разные.

**Замыкание** (closure) — это функция вместе с захваченными переменными из объемлющей области. Python сохраняет такие переменные в специальных «ячейках», пока на функцию есть ссылка. Их можно даже увидеть:

```python
def make_greeter(greeting):
    def greet(name):
        return f"{greeting}, {name}!"
    return greet


hello = make_greeter("Привет")
print(hello.__closure__[0].cell_contents)
print(hello.__code__.co_freevars)
```

```text
Привет
('greeting',)
```

`co_freevars` — имена «свободных» переменных, которые функция использует, но не объявляет сама; `__closure__` — ячейки с их значениями. В обычном коде эти атрибуты не нужны, но они показывают: замыкание — не магия, а функция плюс сохранённые переменные.

## Фабрики функций

Функция, которая создаёт и возвращает настроенные функции, называется **фабрикой**. Это главное практическое применение замыканий:

```python
def make_validator(min_len, max_len, forbidden=()):
    def validate(text):
        if not min_len <= len(text) <= max_len:
            return f"длина должна быть от {min_len} до {max_len}"
        for word in forbidden:
            if word in text.lower():
                return f"запрещённое слово: {word}"
        return "ok"
    return validate


check_username = make_validator(3, 16, forbidden=("admin",))
check_prompt = make_validator(1, 2000)
print(check_username("ад"))
print(check_username("SuperAdmin"))
print(check_username("ada_dev"))
print(check_prompt("Расскажи про замыкания"))
```

```text
длина должна быть от 3 до 16
запрещённое слово: admin
ok
ok
```

Каждый валидатор — отдельная функция со своими настройками. Код, который их использует, вызывает `check(text)` и ничего не знает о параметрах. Сравните с альтернативой — передавать `min_len`, `max_len`, `forbidden` при каждом вызове.

## nonlocal: изменить захваченную переменную

Читать захваченную переменную можно свободно. А вот **присвоить** ей новое значение — нельзя без специального объявления:

```python
def make_counter():
    count = 0

    def increment():
        count += 1
        return count

    return increment


counter = make_counter()
try:
    counter()
except UnboundLocalError as error:
    print(type(error).__name__)
```

```text
UnboundLocalError
```

Присваивание `count += 1` внутри `increment` делает `count` **локальной** переменной `increment` (так Python решает на этапе компиляции функции). А у локальной переменной ещё нет значения, когда её пытаются увеличить. Ключевое слово `nonlocal` сообщает Python, что имя относится к переменной объемлющей функции:

```python
def make_counter(start=0):
    count = start

    def increment(step=1):
        nonlocal count
        count += step
        return count

    return increment


clicks = make_counter()
views = make_counter(100)
clicks()
clicks()
print(clicks(), views(5))
```

```text
3 105
```

Каждый вызов `make_counter` создаёт **свою** переменную `count`, поэтому счётчики независимы — как объекты одного класса.

`nonlocal` похож на `global`, но указывает на ближайшую объемлющую функцию, а не на модуль. Обратите внимание: `nonlocal` нужен только для **присваивания**. Если захвачен изменяемый объект (список, словарь) и вы меняете его методами (`append`, `d[key] = ...`), `nonlocal` не нужен — переменная не переприсваивается:

```python
def make_logger():
    lines = []

    def log(message):
        lines.append(message)
        return len(lines)

    def history():
        return list(lines)

    return log, history


log, history = make_logger()
log("старт")
log("эпоха 1")
print(history())
```

```text
['старт', 'эпоха 1']
```

Здесь две функции — `log` и `history` — замыкают **одну и ту же** переменную `lines` и разделяют состояние.

## Ловушка: позднее связывание в цикле

Самая известная ловушка с замыканиями. Создадим в цикле список функций:

```python
multipliers = []
for factor in range(1, 4):
    multipliers.append(lambda x: x * factor)

print([m(10) for m in multipliers])
```

```text
[30, 30, 30]
```

Ожидали `[10, 20, 30]`, а получили три одинаковых результата. Замыкание захватывает **переменную**, а не её значение в момент создания функции. Все три lambda ссылаются на одну переменную `factor`, а к моменту вызова цикл закончился и `factor` равен 3. Это называется **поздним связыванием** (late binding) — то же явление вы видели с генераторными выражениями в блоке 2.3.

Два способа исправить:

```python
by_default = [lambda x, f=factor: x * f for factor in range(1, 4)]
print([m(10) for m in by_default])


def make_multiplier(factor):
    return lambda x: x * factor


by_factory = [make_multiplier(factor) for factor in range(1, 4)]
print([m(10) for m in by_factory])
```

```text
[10, 20, 30]
[10, 20, 30]
```

- **Параметр по умолчанию** `f=factor` вычисляется в момент создания lambda — значение «фиксируется».
- **Фабрика** создаёт новую область видимости при каждом вызове, и у каждой функции своя переменная `factor`. Этот вариант читается лучше.

## Как Python решает, где искать переменную

Почему одно и то же имя `count` в одном случае читается из внешней функции, а в другом вызывает `UnboundLocalError`? Python определяет область видимости каждого имени **заранее**, когда компилирует функцию, а не во время выполнения строки.

Правило такое: если внутри функции есть **любое присваивание** имени (`x = ...`, `x += ...`, `for x in ...`, `import x`, параметр `x`), то это имя считается локальным во всей функции — даже в строках, которые стоят до присваивания. Если присваиваний нет, имя ищется снаружи по правилу LEGB.

Поэтому строка `count += 1` «ломает» чтение: из-за неё `count` объявлен локальным, а локального значения ещё нет. Объявления `nonlocal` и `global` меняют это решение компилятора: они говорят, что присваивание относится к внешней переменной.

Это же правило объясняет, почему `lines.append(...)` работает без `nonlocal`: здесь нет присваивания имени `lines`, есть только вызов метода у объекта, на который это имя указывает.

## Замыкание или класс?

Счётчик можно написать и замыканием, и классом с `__call__` (урок 1). Что выбрать?

- **Замыкание** короче, когда состояние маленькое и операция одна: «функция с настройками» или «функция со счётчиком».
- **Класс** лучше, когда операций несколько, состояние нужно читать снаружи (`counter.value`), сбрасывать, сохранять или когда логика разрастается.

Пример с `make_logger`, возвращающим две функции, — уже на границе: если понадобится третья операция, класс будет понятнее.

## Разбор задачи: учёт расходов на API

При работе с платным LLM API нужно следить за бюджетом: считать потраченные токены и стоимость, отказывать в запросах при превышении лимита. Напишем фабрику, которая создаёт «учётчика» с собственным бюджетом:

```python
def make_budget_tracker(limit_usd, price_per_1k):
    spent = 0.0
    requests = 0

    def record(tokens):
        nonlocal spent, requests
        cost = tokens / 1000 * price_per_1k
        if spent + cost > limit_usd:
            raise RuntimeError(f"бюджет исчерпан: потрачено ${spent:.4f} из ${limit_usd}")
        spent += cost
        requests += 1
        return round(limit_usd - spent, 4)

    def report():
        return {"requests": requests, "spent": round(spent, 4), "left": round(limit_usd - spent, 4)}

    return record, report


record, report = make_budget_tracker(limit_usd=0.05, price_per_1k=0.01)
print(record(2000))
print(record(1500))
try:
    record(2000)
except RuntimeError as error:
    print(error)
print(report())
```

```text
0.03
0.015
бюджет исчерпан: потрачено $0.0350 из $0.05
{'requests': 2, 'spent': 0.035, 'left': 0.015}
```

Разбор:

- `nonlocal spent, requests` — две переменные в одном объявлении; без него присваивания создали бы локальные переменные;
- `limit_usd` и `price_per_1k` только читаются — для них `nonlocal` не нужен;
- проверка бюджета стоит **до** изменения состояния: отклонённый запрос не портит учёт;
- `record` и `report` разделяют одно состояние, а снаружи до `spent` не добраться никак, кроме как через эти функции, — это инкапсуляция без класса.

## Частые ошибки

**1. Присваивание без `nonlocal`.** `count += 1` во вложенной функции → `UnboundLocalError`. Объявите `nonlocal count`.

**2. `nonlocal` для глобальной переменной.** `nonlocal` ищет имя только в объемлющих функциях; для переменной модуля — `SyntaxError: no binding for nonlocal`. Глобальные переменные лучше не менять вовсе.

**3. Позднее связывание в цикле.** Функции, созданные в цикле, видят последнее значение переменной цикла. Используйте фабрику или параметр по умолчанию.

**4. Ожидание, что замыкание копирует значение.** Захватывается переменная: если внешняя функция изменит её после создания вложенной, вложенная увидит новое значение.

**5. Скрытое состояние там, где нужна прозрачность.** Замыкание с пятью переменными и тремя функциями трудно отлаживать: состояние не видно в отладчике так же удобно, как атрибуты объекта. Переходите на класс.

**6. Вызов фабрики вместо передачи результата.** `check = make_validator` (без скобок и аргументов) — это фабрика, а не валидатор. Нужно `check = make_validator(3, 16)`.

## Где это в AI-инженерии

- **Декораторы** (уроки 3–4) — замыкания: обёртка помнит исходную функцию и параметры декоратора.
- **Фабрики функций потерь и метрик**: `make_focal_loss(gamma=2)` возвращает функцию потерь с зафиксированным параметром.
- **Планировщики learning rate**: функция `lr_lambda(epoch)`, созданная фабрикой с базовым значением и скоростью затухания, передаётся в `LambdaLR` PyTorch.
- **Учёт ресурсов**: счётчики токенов, бюджеты, ограничители частоты запросов к API.
- **Обработчики событий и колбэки** с настройками: `make_logger(prefix="train")`.

## Итоги урока

- Вложенная функция видит переменные объемлющей функции (буква E в LEGB).
- Замыкание — функция плюс захваченные переменные; они живут, пока жива функция.
- Фабрики функций создают настроенные функции: `make_validator(3, 16)`.
- `nonlocal` нужен для присваивания захваченной переменной; для изменения списка или словаря методами — не нужен.
- Замыкания захватывают переменные, а не значения: в циклах используйте фабрику или параметр по умолчанию.
- Маленькое состояние и одна операция — замыкание; несколько операций и прозрачное состояние — класс.
